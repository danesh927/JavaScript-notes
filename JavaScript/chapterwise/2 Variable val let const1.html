1. ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ವೇರಿಯೇಬಲ್ (Variables) ಎಂದರೇನು?

ಚಿಕ್ಕಮಕ್ಕಳಿಗೆ ಅರ್ಥವಾಗುವ ಉದಾಹರಣೆ:

ವೇರಿಯೇಬಲ್ ಎಂದರೆ ನಿಮ್ಮ ಮನೆಯಲ್ಲಿರುವ ಒಂದು 'ಪ್ಲಾಸ್ಟಿಕ್ ಡಬ್ಬಿ' (Box) ಇದ್ದಂತೆ. ಆ ಡಬ್ಬಿಗೆ ನೀವು ಒಂದು ಹೆಸರು ಬರೆಯುತ್ತೀರಿ (ಉದಾಹರಣೆಗೆ: "ಸಕ್ಕರೆ ಡಬ್ಬಿ", "ಖಾರದ ಪುಡಿ ಡಬ್ಬಿ"). ನಂತರ ಆ ಡಬ್ಬಿಯೊಳಗೆ ಆ ವಸ್ತುಗಳನ್ನು ಹಾಕಿಡುತ್ತೀರಿ. ನಿಮಗೆ ಯಾವಾಗ ಬೇಕಾದರೂ ಆ ಡಬ್ಬಿಯನ್ನು ತೆರೆದು ಅದರೊಳಗಿರುವ ವಸ್ತುವನ್ನು ಬಳಸಬಹುದು ಅಥವಾ ಆ ವಸ್ತುವನ್ನು ತೆಗೆದು ಬೇರೆ ವಸ್ತುವನ್ನು ಹಾಕಬಹುದು.

ಕಂಪ್ಯೂಟರ್ ಪ್ರೋಗ್ರಾಮಿಂಗ್‌ನಲ್ಲೂ ಅಷ್ಟೇ! ವೇರಿಯೇಬಲ್ ಎಂದರೆ ಡೇಟಾ ಅಥವಾ ಮಾಹಿತಿಯನ್ನು ಶೇಖರಿಸಿಡಲು ಕಂಪ್ಯೂಟರ್ ಮೆಮೊರಿಯಲ್ಲಿ (Memory) ರಚಿಸುವ ಒಂದು ಜಾಗ (Container).

(ವೇರಿಯೇಬಲ್ ಎಂಬುದು ಒಂದು ಕಂಟೇನರ್)

ಉದಾಹರಣೆ:

let age = 25;

ಇಲ್ಲಿ:

  • let ಎಂದರೆ ಡಬ್ಬಿ ತಯಾರು ಮಾಡಲು ಕೊಡುವ ಸೂಚನೆ.
  • age ಎಂದರೆ ಆ ಡಬ್ಬಿಯ ಹೆಸರು.
  • 25 ಎಂದರೆ ಆ ಡಬ್ಬಿಯ ಒಳಗೆ ನಾವು ಇಟ್ಟಿರುವ ಮಾಹಿತಿ (ಬೆಲೆ/Value).

ಹೆಚ್ಚುವರಿ ಮಾಹಿತಿ: ವೇರಿಯೇಬಲ್ ಜೀವನಚಕ್ರ (Memory Lifecycle)

ಒಂದು ವೇರಿಯೇಬಲ್ 3 ಹಂತಗಳನ್ನು ಹೊಂದಿರುತ್ತದೆ:

  1. Declaration (ಘೋಷಣೆ): ಡಬ್ಬಿಯನ್ನು ರೆಡಿ ಮಾಡುವುದು (ಉದಾ: let age;)
  2. Initialization (ಪ್ರಾರಂಭಿಸುವಿಕೆ): ಮೆಮೊರಿಯಲ್ಲಿ ಜಾಗ ಕಾಯ್ದಿರಿಸುವುದು.
  3. Assignment (ಮೌಲ್ಯ ನಿಯೋಜನೆ): ಡಬ್ಬಿಯೊಳಗೆ ವಸ್ತುವನ್ನು ಹಾಕುವುದು (ಉದಾ: age = 25;)

2. ವೇರಿಯೇಬಲ್ ಹೆಸರು ಬರೆಯಲು ಇರುವ ನಿಯಮಗಳು (Naming Rules)

1. ಬಳಸಬಹುದಾದ ಅಕ್ಷರಗಳು ಮತ್ತು ಚಿಹ್ನೆಗಳು

ವೇರಿಯೇಬಲ್ ಹೆಸರಿನಲ್ಲಿ ಇವುಗಳನ್ನು ಮಾತ್ರ ಬಳಸಲು ಅನುಮತಿಯಿದೆ:

  • ಇಂಗ್ಲಿಷ್ ಅಕ್ಷರಗಳು (A-Z ಮತ್ತು a-z)
  • ಅಂಕಿಗಳು (0-9)
  • ಅಂಡರ್‌ಸ್ಕೋರ್ (_)
  • ಡಾಲರ್ ಚಿಹ್ನೆ ($)

ಗಮನಿಸಿ: ಇವುಗಳನ್ನು ಬಿಟ್ಟು ಬೇರೆ ಯಾವುದೇ ವಿಶೇಷ ಚಿಹ್ನೆಗಳನ್ನು (@, #, %, !, -, &) ಬಳಸುವಂತಿಲ್ಲ.

  • ಸರಿ: myAge, price_100, $totalAmount
  • ತಪ್ಪು: my@email, total-price

2. ಅಂಕಿಯಿಂದ (Number) ಶುರುವಾಗುವಂತಿಲ್ಲ

ಹೆಸರು ಯಾವಾಗಲೂ ಅಕ್ಷರ, _ ಅಥವಾ $ ನಿಂದಲೇ ಶುರುವಾಗಬೇಕು. ಯಾವುದೇ ಕಾರಣಕ್ಕೂ ಅಂಕಿಯಿಂದ ಶುರುವಾಗುವಂತಿಲ್ಲ. ಅಂಕಿಗಳನ್ನು ಹೆಸರಿನ ಮಧ್ಯದಲ್ಲಿ ಅಥವಾ ಕೊನೆಯಲ್ಲಿ ಬಳಸಬಹುದು.

  • ಸರಿ: player1, _score, $discount
  • ತಪ್ಪು: 1player, 3rdPlace (ಇದು ಎರ್‍ರರ್/Error ಕೊಡುತ್ತದೆ)

3. ಖಾಲಿ ಜಾಗ (Space) ಬಿಡುವಂತಿಲ್ಲ

ವೇರಿಯೇಬಲ್ ಹೆಸರಿನ ಮಧ್ಯೆ ಜಾಗ (Space) ಬಿಡುವಂತಿಲ್ಲ. ಜಾಗ ಬಿಟ್ಟರೆ ಕಂಪ್ಯೂಟರ್ ಅದನ್ನು ಎರಡು ಬೇರೆ ಬೇರೆ ಪದಗಳು ಎಂದು ಗೊಂದಲಕ್ಕೀಡಾಗುತ್ತದೆ. ಪದಗಳನ್ನು ಸೇರಿಸಲು ಕ್ಯಾಮೆಲ್ ಕೇಸ್ (Camel Case) ಅಥವಾ ಅಂಡರ್‌‌ಸ್ಕೋರ್ ಬಳಸಬೇಕು.

  • ಸರಿ: myFirstName, my_first_name
  • ತಪ್ಪು: my first name

4. ಕಾಯ್ದಿರಿಸಿದ ಪದಗಳನ್ನು (Reserved Keywords) ಬಳಸುವಂತಿಲ್ಲ

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ತನ್ನ ಸ್ವಂತ ಕೆಲಸಗಳಿಗೆ ಕೆಲವು ಪದಗಳನ್ನು ಮೀಸಲಿಟ್ಟಿದೆ. ಉದಾಹರಣೆಗೆ: let, var, const, function, if, else, return, class. ಈ ಪದಗಳನ್ನು ನೀವು ನಿಮ್ಮ ವೇರಿಯೇಬಲ್ ಹೆಸರಾಗಿ ಬಳಸುವಂತಿಲ್ಲ.

  • ಸರಿ: myFunction, isConditionTrue
  • ತಪ್ಪು: let let = 10;, const function = "Hello";

5. ದೊಡ್ಡ ಮತ್ತು ಸಣ್ಣ ಅಕ್ಷರಗಳ ವ್ಯತ್ಯಾಸ (Case Sensitive)

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ದೊಡ್ಡ ಅಕ್ಷರ (Uppercase) ಮತ್ತು ಸಣ್ಣ ಅಕ್ಷರಗಳನ್ನು (Lowercase) ಬೇರೆ ಬೇರೆಯಾಗಿ ನೋಡುತ್ತದೆ.

  • ಉದಾಹರಣೆಗೆ: score, Score, ಮತ್ತು SCORE - ಈ ಮೂರೂ ಪದಗಳು ನಮಗೆ ಒಂದೇ ಎನಿಸಿದರೂ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಪ್ರಕಾರ ಇವು ಮೂರು ಬೇರೆ ಬೇರೆ ವೇರಿಯೇಬಲ್‌ಗಳು! ಆದ್ದರಿಂದ ಅಕ್ಷರಗಳ ಬಗ್ಗೆ ಗಮನವಿರಲಿ.

6. ಹೆಸರಿಸುವ ಶೈಲಿಗಳು (Naming Conventions):

  • ಕ್ಯಾಮೆಲ್ ಕೇಸ್ (Camel Case): myBankBalance
    • ಮೊದಲ ಪದದ ಅಕ್ಷರ ಸಣ್ಣದು, ನಂತರದ ಪದಗಳ ಮೊದಲ ಅಕ್ಷರ ದೊಡ್ಡದು.
    • ಬಳಕೆ: ವೇರಿಯೇಬಲ್ಸ್ ಮತ್ತು ಫಂಕ್ಷನ್‌ಗಳಿಗೆ (ಅತಿ ಹೆಚ್ಚು ಬಳಸುವ ಶೈಲಿ).
  • ಪಾಸ್ಕಲ್ ಕೇಸ್ (Pascal Case): MyBankBalance
    • ಪ್ರತಿಯೊಂದು ಪದದ ಮೊದಲನೇ ಅಕ್ಷರವೂ ದೊಡ್ಡದು.
    • ಬಳಕೆ: ಕ್ಲಾಸ್‌ಗಳು (Classes) ಮತ್ತು ಕಾಂಪೊನೆಂಟ್‌ಗಳಿಗೆ ಮಾತ್ರ.
  • ಸ್ನೇಕ್ ಕೇಸ್ (Snake / Underscore): MAX_SPEED_LIMIT
    • ಎಲ್ಲಾ ಅಕ್ಷರಗಳು ದೊಡ್ಡದು, ಪದಗಳ ಮಧ್ಯೆ ಅಂಡರ್‌ಸ್ಕೋರ್ (_) ಇರುತ್ತದೆ.
    • ಬಳಕೆ: ಎಂದಿಗೂ ಬದಲಾಗದ ಜಾಗತಿಕ ಸ್ಥಿರ ಮೌಲ್ಯಗಳಿಗೆ (Global Constants).

💡 ವೃತ್ತಿಪರ ಡೆವಲಪರ್‌ಗಳ ಉತ್ತಮ ಅಭ್ಯಾಸಗಳು (Best Practices)

ನಿಯಮಗಳಲ್ಲದಿದ್ದರೂ, ಐಟಿ ಕಂಪನಿಗಳಲ್ಲಿ ಕೆಲಸ ಮಾಡುವಾಗ ಎಲ್ಲರೂ ಪಾಲಿಸುವ ಪದ್ಧತಿಗಳಿವು:

  • ಅರ್ಥಗರ್ಭಿತ ಹೆಸರು (Meaningful Names): ವೇರಿಯೇಬಲ್ ಹೆಸರನ್ನು ನೋಡಿದ ತಕ್ಷಣ ಅದರೊಳಗೆ ಏನಿದೆ ಎಂದು ತಿಳಿಯುವಂತಿರಬೇಕು. a, b, x, y ಎಂದು ಚಿಕ್ಕದಾಗಿ ಹೆಸರು ಇಡುವ ಬದಲು totalPrice, studentName ಎಂದು ಅರ್ಥ ಬರುವಂತೆ ಇಡಬೇಕು.
  • ಕ್ಯಾಮೆಲ್ ಕೇಸ್ (Camel Case): ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ವೇರಿಯೇಬಲ್ ಹೆಸರಿಸಲು ಯಾವಾಗಲೂ ಕ್ಯಾಮೆಲ್ ಕೇಸ್ ಬಳಸುವುದು ಅಂತರರಾಷ್ಟ್ರೀಯ ಪದ್ಧತಿ. (ಉದಾ: userBankAccoutNumber).

3. var, let, ಮತ್ತು const ಬಗ್ಗೆ ಸಂಪೂರ್ಣ ಮಾಹಿತಿ

🟢 ಹಂತ 1: ಮೂಲಭೂತ ಪರಿಕಲ್ಪನೆಗಳು (Beginner Level)

ವೇರಿಯೇಬಲ್ ಎಂದರೆ ಡೇಟಾವನ್ನು ಸೇವ್ ಮಾಡಿಡಲು ಬಳಸುವ ಡಬ್ಬಿ (Container). ಇದರಲ್ಲಿ 3 ವಿಧ:

1. var (ಹಳೆಯ ಪದ್ಧತಿ)

  • ನಿಯಮ: ಮೌಲ್ಯವನ್ನು ಬದಲಾಯಿಸಬಹುದು (Reassign) ಮತ್ತು ಒಂದೇ ಹೆಸರಿನಲ್ಲಿ ಮತ್ತೆ ಹೊಸ ಡಬ್ಬಿ ಮಾಡಬಹುದು (Redeclare).
var playerName = "ರಾಹುಲ್";
playerName = "ವಿರಾಟ್"; // 1. ಮೌಲ್ಯ ಬದಲಾಯಿಸಿದೆವು (ಸರಿ)
var playerName = "ಧೋನಿ"; // 2. ಮತ್ತೆ ಅದೇ ಹೆಸರಿನಲ್ಲಿ ಘೋಷಿಸಿದೆವು (ಸರಿ)

console.log(playerName); // ಔಟ್‌ಪುಟ್: ಧೋನಿ

2. let (ಆಧುನಿಕ ಪದ್ಧತಿ)

  • ನಿಯಮ: ಮೌಲ್ಯವನ್ನು ಬದಲಾಯಿಸಬಹುದು, ಆದರೆ ಮತ್ತೆ ಅದೇ ಹೆಸರಿನಲ್ಲಿ ಹೊಸ ವೇರಿಯೇಬಲ್ ಘೋಷಿಸುವಂತಿಲ್ಲ.
let score = 50;
score = 100; // 1. ಮೌಲ್ಯ ಬದಲಾಯಿಸಿದೆವು (ಸರಿ)

// let score = 150; // ❌ ERROR: Identifier 'score' has already been declared
console.log(score); // ಔಟ್‌ಪುಟ್: 100

3. const (ಸ್ಥಿರ ಪದ್ಧತಿ)

  • ನಿಯಮ: ಮೌಲ್ಯವನ್ನು ಬದಲಾಯಿಸುವಂತೆಯೂ ಇಲ್ಲ, ಮತ್ತೆ ಘೋಷಿಸುವಂತೆಯೂ ಇಲ್ಲ.
const birthYear = 2000;

// birthYear = 2001; // ❌ TypeError: Assignment to constant variable.
// const birthYear = 2005; // ❌ ERROR: Cannot redeclare block-scoped variable

console.log(birthYear); // ಔಟ್‌ಪುಟ್: 2000
🟡 ಹಂತ 2: ಸ್ಕೋಪ್ ಅಥವಾ ಮಿತಿ (Intermediate Level)

ಸ್ಕೋಪ್ ಎಂದರೆ ಒಂದು ವೇರಿಯೇಬಲ್ ಅನ್ನು ಎಲ್ಲೆಲ್ಲಿ ಬಳಸಬಹುದು ಎಂಬ ಮಿತಿ.

1. Function Scope (var ನ ಸಮಸ್ಯೆ)

var ಕೇವಲ ಫಂಕ್ಷನ್ ಒಳಗೆ ಮಾತ್ರ ಕಂಟ್ರೋಲ್‌ನಲ್ಲಿರುತ್ತದೆ. if ಅಥವಾ for ಬ್ಲಾಕ್ { } ಒಳಗೆ ಬರೆದರೆ ಅದು ಹೊರಗಡೆ ಸೋರಿಕೆಯಾಗುತ್ತದೆ (Leak).

if (true) {
    var myCity = "ಬೆಂಗಳೂರು"; // ಬ್ಲಾಕ್ ಒಳಗೆ ಬರೆದಿದ್ದೇವೆ
}

// ಹೊರಗಡೆಯಿಂದ ಪ್ರಿಂಟ್ ಮಾಡಿದರೂ ಸಿಗುತ್ತದೆ (ಇದು ಬಗ್ಸ್ / ತಪ್ಪುಗಳಿಗೆ ಕಾರಣವಾಗುತ್ತದೆ)
console.log(myCity); // ಔಟ್‌ಪುಟ್: ಬೆಂಗಳೂರು

2. Block Scope (let ಮತ್ತು const ನ ಶಕ್ತಿ)

ಇವು ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಬ್ರಾಕೆಟ್ { } ನಿಯಮವನ್ನು ಪಾಲಿಸುತ್ತವೆ. ಬ್ಲಾಕ್‌ನಿಂದ ಹೊರಗೆ ಇವು ಸಿಗುವುದಿಲ್ಲ.

if (true) {
    let myAge = 25;
    const myCountry = "India";
}

// console.log(myAge); // ❌ ReferenceError: myAge is not defined
// console.log(myCountry); // ❌ ReferenceError: myCountry is not defined
🔴 ಹಂತ 3: ಪ್ರೊ ಹಂತದ ಪರಿಕಲ್ಪನೆಗಳು (Advanced / Interview Level)

1. Hoisting (ಮೇಲೇರುವಿಕೆ) ಮತ್ತು TDZ

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಕೋಡ್ ರನ್ ಆಗುವ ಮುನ್ನ ಎಲ್ಲಾ ವೇರಿಯೇಬಲ್ ಹೆಸರುಗಳನ್ನು ಮೆಮೊರಿಯ ಮೇಲ್ಭಾಗಕ್ಕೆ ಕೊಂಡೊಯ್ಯುತ್ತದೆ.

A. var ನ Hoisting: (Error ಬರುವುದಿಲ್ಲ, undefined ಬರುತ್ತದೆ)

console.log(company); // ಔಟ್‌ಪುಟ್: undefined
var company = "Google";

B. let/const ನ Hoisting ಮತ್ತು TDZ (Temporal Dead Zone):

ಇವು ಕೂಡ Hoist ಆಗುತ್ತವೆ, ಆದರೆ ಮೌಲ್ಯ ಕೊಡುವವರೆಗೆ ಅವುಗಳನ್ನು ಬಳಸಲು ಹೋದರೆ Error ಬರುತ್ತದೆ. ಆ ಸಮಯವನ್ನು TDZ ಎನ್ನುತ್ತಾರೆ.

// console.log(salary); // ❌ ReferenceError: Cannot access 'salary' before initialization
let salary = 50000;
console.log(salary); // ಔಟ್‌ಪುಟ್: 50000

2. const ನ ಒಳಗಿನ ಗುಟ್ಟು (Mutation vs Reassignment)

const ಬಳಸಿ Array ಅಥವಾ Object ಮಾಡಿದಾಗ, ಇಡೀ ಡಬ್ಬಿಯನ್ನು ಬೇರೆಯದಕ್ಕೆ ಬದಲಿಸುವಂತಿಲ್ಲ. ಆದರೆ ಒಳಗಿರುವ ವಸ್ತುಗಳನ್ನು (Elements/Properties) ಬದಲಾಯಿಸಬಹುದು.

Array ಉದಾಹರಣೆ:

const colors = ["Red", "Green"];

colors.push("Blue"); // ಡಬ್ಬಿಯೊಳಗೆ ಹೊಸ ವಸ್ತು ಹಾಕಿದೆವು (ಸರಿ)
console.log(colors); // ಔಟ್‌ಪುಟ್: ["Red", "Green", "Blue"]

// colors = ["Yellow"]; // ❌ TypeError (ಇಡೀ ಡಬ್ಬಿಯನ್ನು ಬದಲಿಸುವಂತಿಲ್ಲ)

Object ಉದಾಹರಣೆ:

const car = { brand: "Tata", model: "Nexon" };

car.model = "Harrier"; // ಒಳಗಿನ ಪ್ರಾಪರ್ಟಿ ಬದಲಾಯಿಸಿದೆವು (ಸರಿ)
console.log(car.model); // ಔಟ್‌ಪುಟ್: Harrier

3. Global Object (Window) ನಡವಳಿಕೆ

ಬ್ರೌಸರ್‌ನಲ್ಲಿ ರನ್ ಮಾಡುವಾಗ:

  • var ನಿಂದ ಮಾಡಿದ ವೇರಿಯೇಬಲ್ ನೇರವಾಗಿ window ಆಬ್ಜೆಕ್ಟ್‌ಗೆ ಸೇರಿಕೊಳ್ಳುತ್ತದೆ.
  • let ಮತ್ತು const ಸೇರಿಕೊಳ್ಳುವುದಿಲ್ಲ (ಇದು ಹೆಚ್ಚು ಸುರಕ್ಷಿತ).
var a = 10;
let b = 20;

console.log(window.a); // ಔಟ್‌ಪುಟ್: 10 (window ಗೆ ಅಂಟಿಕೊಂಡಿದೆ)
console.log(window.b); // ಔಟ್‌ಪುಟ್: undefined (ಸುರಕ್ಷಿತವಾಗಿದೆ)

4. Variable Shadowing (ಮರೆಮಾಡುವುದು)

ಹೊರಗೆ ಮತ್ತು ಒಳಗೆ ಒಂದೇ ಹೆಸರಿನ ವೇರಿಯೇಬಲ್ ಇದ್ದಾಗ, ಒಳಗಿನ ವೇರಿಯೇಬಲ್ ಹೊರಗಿನದನ್ನು ತನ್ನ ಬ್ಲಾಕ್ ಒಳಗೆ ಮರೆಮಾಡುತ್ತದೆ.

Legal Shadowing (ಸರಿಯಾದ ವಿಧಾನ):

let testScore = 100; // ಹೊರಗಿನ ವೇರಿಯೇಬಲ್

if (true) {
    let testScore = 50; // ಒಳಗಿನ ವೇರಿಯೇಬಲ್
    console.log("ಬ್ಲಾಕ್ ಒಳಗೆ: ", testScore); // ಔಟ್‌ಪುಟ್: 50
}

console.log("ಬ್ಲಾಕ್ ಹೊರಗೆ: ", testScore); // ಔಟ್‌ಪುಟ್: 100

Illegal Shadowing (ತಪ್ಪು ವಿಧಾನ):

ಹೊರಗೆ let ಬಳಸಿ, ಒಳಗೆ ಅದೇ ಹೆಸರಿಗೆ var ಬಳಸುವಂತಿಲ್ಲ.

let name = "Ravi";
if (true) {
    // var name = "Kumar"; // ❌ SyntaxError: Identifier 'name' has already been declared
}

🏆 ಹಂತ 4: ವೃತ್ತಿಪರರ ಸುವರ್ಣ ನಿಯಮಗಳು (Golden Rules Checklist)

ಯಾವಾಗ ಯಾವುದನ್ನು ಬಳಸಬೇಕು?

  • 🥇 ಯಾವಾಗಲೂ const ಬಳಸಿ: ನಿಮ್ಮ ಕೋಡ್ ಬರೆಯುವಾಗ ಮೊದಲ ಆಯ್ಕೆ const ಆಗಿರಲಿ. (ಉದಾ: Arrays, Objects, Functions, ಕಾನ್ಸ್ಟಂಟ್ ಮೌಲ್ಯಗಳು).
  • 🥈 ಅನಿವಾರ್ಯವಿದ್ದರೆ ಮಾತ್ರ let ಬಳಸಿ: ಒಂದು ಮೌಲ್ಯ ಮುಂದೆ ಬದಲಾಗುತ್ತದೆ ಎಂದು ಖಚಿತವಿದ್ದರೆ ಮಾತ್ರ (ಉದಾ: For Loop ಲೆಕ್ಕಾಚಾರಗಳು, ಸ್ಕೋರ್ ಬೋರ್ಡ್, ಟೈಮರ್) let ಬಳಸಿ.
  • 🚫 var ಬಳಸುವುದನ್ನು ನಿಲ್ಲಿಸಿ: ಆಧುನಿಕ ಡೆವಲಪ್ಮೆಂಟ್‌ನಲ್ಲಿ var ಗೆ ಜಾಗವಿಲ್ಲ. ಹಳೆಯ ಪ್ರಾಜೆಕ್ಟ್ ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಮಾತ್ರ ಇದರ ಬಗ್ಗೆ ತಿಳಿದಿರಲಿ.

🚀 ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ Variables - ಕ್ವಿಕ್ ರಿವಿಷನ್ ನೋಟ್ಸ್

📌 1. ವೇರಿಯೇಬಲ್ ಎಂದರೇನು?

  • ಡೇಟಾವನ್ನು ಶೇಖರಿಸಿಡುವ 'ಮೆಮೊರಿ ಡಬ್ಬಿ' (Container).

📌 2. ಹೆಸರಿಸುವ ನಿಯಮಗಳು (Naming Rules)

  • ಬಳಸಬಹುದಾದವು: A-Z, a-z, 0-9, _, $.
  • ಬಳಸಬಾರದವು: ಅಂಕಿಯಿಂದ ಶುರುವಾಗುವಂತಿಲ್ಲ (ಉದಾ: 1name), ಜಾಗ (Space) ಬಿಡುವಂತಿಲ್ಲ, ವಿಶೇಷ ಚಿಹ್ನೆಗಳಿಲ್ಲ (@, #, -).
  • Reserved Words: let, const, if ಬಳಸುವಂತಿಲ್ಲ.
  • Case Sensitive: score ಮತ್ತು Score ಎರಡು ಬೇರೆ ಬೇರೆ!
  • Best Practice: ಯಾವಾಗಲೂ camelCase ಬಳಸಿ (ಉದಾ: myBankBalance).

📌 3. var, let, const - ತ್ವರಿತ ಹೋಲಿಕೆ

ಗುಣಲಕ್ಷಣ var (ಹಳೆಯದು 👴) let (ಹೊಸದು 🧑) const (ಸ್ಥಿರ 🗿)
ಮೌಲ್ಯ ಬದಲಾವಣೆ (Reassign) ✅ ಹೌದು ✅ ಹೌದು ❌ ಇಲ್ಲ (Error)
ಮತ್ತೆ ಘೋಷಣೆ (Redeclare) ✅ ಹೌದು ❌ ಇಲ್ಲ (Error) ❌ ಇಲ್ಲ (Error)
ಮಿತಿ (Scope) Function Scope Block Scope { } Block Scope { }
Window ಆಬ್ಜೆಕ್ಟ್‌ಗೆ ಸೇರುತ್ತಾ? ✅ ಹೌದು (ಅಸುರಕ್ಷಿತ) ❌ ಇಲ್ಲ (ಸುರಕ್ಷಿತ) ❌ ಇಲ್ಲ (ಸುರಕ್ಷಿತ)

📌 4. ಪ್ರೊ ಲೆವೆಲ್ ಕಾನ್ಸೆಪ್ಟ್‌ಗಳು (Pro Concepts)

  • 🔍 Scope (ಮಿತಿ):
    • var ಬ್ಲಾಕ್ { } ನಿಂದ ಹೊರಗೆ ಲೀಕ್ ಆಗುತ್ತದೆ.
    • let/const ಬ್ಲಾಕ್‌ನಿಂದ ಹೊರಬರುವುದಿಲ್ಲ (ಸುರಕ್ಷಿತ).
  • ⬆️ Hoisting (ಮೇಲೇರುವಿಕೆ):
    • var ಮೇಲೇರಿ undefined ಆಗುತ್ತದೆ.
    • let/const ಮೇಲೇರಿದರೂ ಮೌಲ್ಯ ಕೊಡುವವರೆಗೆ TDZ (Temporal Dead Zone) ನಲ್ಲಿರುತ್ತವೆ (ಮುಟ್ಟಿದರೆ Error ಬರುತ್ತದೆ).
  • 🔓 const Mutation (ಒಳಗಿನ ಗುಟ್ಟು):
    • const ನಲ್ಲಿ ಇಡೀ Array/Object ಬದಲಾಯಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ. ಆದರೆ ಒಳಗಿರುವ ವಸ್ತುಗಳನ್ನು (Properties) ಬದಲಾಯಿಸಬಹುದು!
    • (ಉದಾ: car.brand = "New" ✅)
  • 👥 Shadowing (ಮರೆಮಾಡುವುದು):
    • ಬ್ಲಾಕ್ ಒಳಗಿನ ವೇರಿಯೇಬಲ್, ಹೊರಗಿನ ಅದೇ ಹೆಸರಿನ ವೇರಿಯೇಬಲ್ ಅನ್ನು ಮರೆಮಾಡುತ್ತದೆ. (ಆದರೆ ಹೊರಗೆ let, ಒಳಗೆ var ಬಳಸಿದರೆ Illegal Shadowing / Error ಬರುತ್ತದೆ).

🏆 5. ವೃತ್ತಿಪರರ 3 ಸುವರ್ಣ ನಿಯಮಗಳು

  1. 🥇 ಡಿಫಾಲ್ಟ್ ಆಗಿ ಯಾವಾಗಲೂ const ಬಳಸಿ.
  2. 🥈 ಮೌಲ್ಯ ಮುಂದೇ ಬದಲಾಗುತ್ತದೆ ಎಂದು ಖಚಿತವಿದ್ದರೆ ಮಾತ್ರ (ಉದಾ: ಲೂಪ್, ಸ್ಕೋರ್) let ಬಳಸಿ.
  3. 🚫 ಹೊಸ ಕೋಡ್‌ನಲ್ಲಿ var ಬಳಸಲೇಬೇಡಿ!
