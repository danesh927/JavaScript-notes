JS Objects Guide

ಪರಿವಿಡಿ (TOC)

ಪೀಠಿಕೆ 1. Object Literals 2. Factory Function 3. Constructor Function 4. Class ಸಂಕ್ಷಿಪ್ತ ಹೋಲಿಕೆ (Summary)

ಆಬ್ಜೆಕ್ಟ್ ಸೃಷ್ಟಿಸುವ ವಿಧಾನಗಳು

ಹೌದು, Object Literals, Factory Functions, Constructor Functions, ಮತ್ತು Classes — ಈ ನಾಲ್ಕೂ ವಿಧಾನಗಳ ಮೂಲ ಉದ್ದೇಶ ಒಂದೇ: ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಆಬ್ಜೆಕ್ಟ್ (Object) ಗಳನ್ನು ಸೃಷ್ಟಿಸುವುದು.

ಆದರೆ, ನಿಮಗೆ ಕೇವಲ ಒಂದೇ ಒಂದು ಆಬ್ಜೆಕ್ಟ್ ಬೇಕೇ ಅಥವಾ ಸಾವಿರಾರು ಆಬ್ಜೆಕ್ಟ್‌ಗಳು ಬೇಕೇ? ನಿಮ್ಮ ಕೋಡ್‌ನ ಗಾತ್ರವೆಷ್ಟು? ಎಂಬ ಆಧಾರದ ಮೇಲೆ ಇವುಗಳ ಬಳಕೆ ಬದಲಾಗುತ್ತದೆ. ಇದನ್ನು ಒಬ್ಬ ಸಾಮಾನ್ಯ ವ್ಯಕ್ತಿಯಿಂದ (Non-IT) ಹಿಡಿದು ಒಬ್ಬ ಪ್ರೊಫೆಷನಲ್ ಡೆವಲಪರ್ (Pro) ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವ ರೀತಿಯಲ್ಲಿ ಹಂತ-ಹಂತವಾಗಿ ನೋಡೋಣ.

1 Object Literals (ಆಬ್ಜೆಕ್ಟ್ ಲಿಟರಲ್ಸ್)

ಸಾಮಾನ್ಯ ವಿವರಣೆ (Non-IT):

ನಿಮಗೆ ಕೂರಲು ಕೇವಲ ಒಂದೇ ಒಂದು ಮರದ ಕುರ್ಚಿ ಬೇಕಾಗಿದೆ. ನೀವೇ ಮರ ತಂದು, ನಿಮ್ಮ ಕೈಯಾರೆ ಒಂದು ಕುರ್ಚಿ ಮಾಡಿಟ್ಟುಕೊಳ್ಳುತ್ತೀರಿ. ನಾಳೆ ಇನ್ನೊಂದು ಕುರ್ಚಿ ಬೇಕಾದರೆ, ಮತ್ತೆ ಮೊದಲಿನಿಂದ ಮರ ತಂದು ಕೆತ್ತಬೇಕು.

ಪ್ರೊ ಲೆವೆಲ್ ವಿವರಣೆ (Technical):

ಇದು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಆಬ್ಜೆಕ್ಟ್ ಸೃಷ್ಟಿಸುವ ಅತ್ಯಂತ ಸರಳ ಮತ್ತು ನೇರ ವಿಧಾನ. ಗುಂಗುರು ಆವರಣ {} (Curly braces) ಬಳಸಿ ನೇರವಾಗಿ ಡೇಟಾ ಮತ್ತು ಫಂಕ್ಷನ್‌ಗಳನ್ನು ಬರೆಯುವುದು.

  • ಎಲ್ಲಿ ಬಳಸಬೇಕು? ಕೇವಲ ಒಮ್ಮೆ ಮಾತ್ರ ಬಳಸುವ ಡೇಟಾ, ಕಾನ್ಫಿಗರೇಶನ್ ಫೈಲ್‌ಗಳು (Configurations), ಅಥವಾ ಪ್ರಾಜೆಕ್ಟ್‌ನ ಸೆಟ್ಟಿಂಗ್ಸ್ ಬರೆಯಲು.
  • ಅನನುಕೂಲ: ನೀವು 100 ಕಾರುಗಳ ಮಾಹಿತಿಯನ್ನು ಬರೆಯಬೇಕಾದರೆ, 100 ಬಾರಿ ಕೋಡ್ ಅನ್ನು ಕಾಪಿ-ಪೇಸ್ಟ್ ಮಾಡಬೇಕಾಗುತ್ತದೆ. ಇದು Reusable (ಮರುಬಳಕೆ) ಅಲ್ಲ. 

const myCar = {
  brand: "Tata",
  color: "Red",
  start: function() {
    console.log("ಕಾರು ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!");
  }
};

myCar.start();
ಔಟ್‌ಪುಟ್:
> ಕಾರು ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!

2 Factory Function (ಫ್ಯಾಕ್ಟರಿ ಫಂಕ್ಷನ್)

ಸಾಮಾನ್ಯ ವಿವರಣೆ (Non-IT):

ನೀವು ಕೈಯಾರೆ ಕುರ್ಚಿ ಮಾಡುವ ಬದಲು, ಒಂದು ಸಣ್ಣ 'ಕುರ್ಚಿ ಮಾಡುವ ಮಷಿನ್' (Factory) ತರುತ್ತೀರಿ. ಆ ಮಷಿನ್‌ಗೆ ಬಣ್ಣ ಮತ್ತು ಮರವನ್ನು ಹಾಕಿದರೆ ಸಾಕು, ಅದು ತಾನಾಗಿಯೇ ಒಂದು ಹೊಸ ಕುರ್ಚಿಯನ್ನು ಹೊರಹಾಕುತ್ತದೆ.

ಪ್ರೊ ಲೆವೆಲ್ ವಿವರಣೆ (Technical):

ಇದು ಕೇವಲ ಒಂದು ಸಾಧಾರಣ ಫಂಕ್ಷನ್. ಆದರೆ, ಈ ಫಂಕ್ಷನ್ ತನ್ನ ಒಳಗಡೆ ಒಂದು ಹೊಸ ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ಸೃಷ್ಟಿಸಿ, ಕೊನೆಯಲ್ಲಿ ಆ ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು return ಮಾಡುತ್ತದೆ. ಇಲ್ಲಿ this ಅಥವಾ new ಕೀವರ್ಡ್‌ನ ಗೊಂದಲ ಇರುವುದಿಲ್ಲ.

  • ಎಲ್ಲಿ ಬಳಸಬೇಕು? ಆಬ್ಜೆಕ್ಟ್‌ಗಳನ್ನು ಪದೇ ಪದೇ ಸೃಷ್ಟಿಸಬೇಕಾದಾಗ ಮತ್ತು ಖಾಸಗಿ ಡೇಟಾವನ್ನು (Private variables - Closures ಮೂಲಕ) ಕಾಪಾಡಿಕೊಳ್ಳಬೇಕಾದಾಗ.
  • ಅನನುಕೂಲ: ಈ ವಿಧಾನದಲ್ಲಿ ಸೃಷ್ಟಿಯಾಗುವ ಪ್ರತಿಯೊಂದು ಆಬ್ಜೆಕ್ಟ್ ಕೂಡ ತನ್ನದೇ ಆದ ಪ್ರತ್ಯೇಕ ಮೆಮೊರಿಯನ್ನು (Functions ಗಳಿಗೆ) ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ. ಇದು ಮೆಮೊರಿ ದೃಷ್ಟಿಯಿಂದ ದೊಡ್ಡ ಪ್ರಾಜೆಕ್ಟ್‌ಗಳಿಗೆ ಒಳ್ಳೆಯದಲ್ಲ. 

function createCar(brandName, carColor) {
  return {
    brand: brandName,
    color: carColor,
    start: function() {
      console.log(`${brandName} ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!`);
    }
  };
}

const car1 = createCar("Tata", "Red");
const car2 = createCar("Maruti", "White");

3 Constructor Function (ಕನ್ಸ್ಟ್ರಕ್ಟರ್ ಫಂಕ್ಷನ್)

ಸಾಮಾನ್ಯ ವಿವರಣೆ (Non-IT):

ನೀವು ಒಬ್ಬ ಪ್ರೊಫೆಷನಲ್ ಕಾಂಟ್ರಾಕ್ಟರ್ ಅನ್ನು (Constructor) ನೇಮಿಸುತ್ತೀರಿ. ಆ ಕಾಂಟ್ರಾಕ್ಟರ್ ಬಳಿ ಒಂದು ಮಾಸ್ಟರ್ ಪ್ಲಾನ್ ಇರುತ್ತದೆ. ನೀವು ಹೊಸ ಮನೆ ಕಟ್ಟಬೇಕಾದರೆ ಕಡ್ಡಾಯವಾಗಿ ಅವನಿಗೆ ಆಫೀಶಿಯಲ್ ಆಗಿ ಆರ್ಡರ್ (new ಕೀವರ್ಡ್) ಕೊಡಲೇಬೇಕು. ಅವನು ಕಡಿಮೆ ಸಂಪನ್ಮೂಲ (Memory) ಬಳಸಿ ಮನೆ ಕಟ್ಟಿಕೊಡುತ್ತಾನೆ.

ಪ್ರೊ ಲೆವೆಲ್ ವಿವರಣೆ (Technical):

ES6 (Classes) ಬರುವ ಮುನ್ನ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಆಬ್ಜೆಕ್ಟ್-ಓರಿಯೆಂಟೆಡ್ ಪ್ರೋಗ್ರಾಮಿಂಗ್ (OOP) ಮಾಡಲು ಇದನ್ನೇ ಬಳಸಲಾಗುತ್ತಿತ್ತು. ಇಲ್ಲಿ ಫಂಕ್ಷನ್‌ನ ಮೊದಲ ಅಕ್ಷರವನ್ನು ಕ್ಯಾಪಿಟಲ್ (Capital) ನಲ್ಲಿ ಬರೆಯಲಾಗುತ್ತದೆ. ಆಬ್ಜೆಕ್ಟ್ ಸೃಷ್ಟಿಸುವಾಗ ಕಡ್ಡಾಯವಾಗಿ new ಕೀವರ್ಡ್ ಬಳಸಬೇಕು.

ಇದು Prototype (ಪ್ರೋಟೋಟೈಪ್) ಎಂಬ ಕಾನ್ಸೆಪ್ಟ್ ಅನ್ನು ಬಳಸುತ್ತದೆ. ಅಂದರೆ ಫಂಕ್ಷನ್‌ಗಳನ್ನು ಪ್ರತಿಯೊಂದು ಆಬ್ಜೆಕ್ಟ್‌ಗೂ ಪ್ರತ್ಯೇಕವಾಗಿ ಸೇರಿಸುವ ಬದಲು, ಒಂದೇ ಕಡೆ ಸ್ಟೋರ್ ಮಾಡಿ ಮೆಮೊರಿ ಉಳಿಸುತ್ತದೆ.

  • ಎಲ್ಲಿ ಬಳಸಬೇಕು? ಹಳೆಯ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಕೋಡ್‌ಬೇಸ್‌ಗಳಲ್ಲಿ (Legacy Code) ಮೆಮೊರಿ ನಿರ್ವಹಣೆಗಾಗಿ. (ಆದರೆ ಪ್ರಸ್ತುತ ಇದರ ಬದಲಿಗೆ Classes ಬಳಸಲಾಗುತ್ತದೆ). 

function Car(brandName, carColor) {
  // 'this' ಎಂದರೆ ಹೊಸದಾಗಿ ಸೃಷ್ಟಿಯಾಗುತ್ತಿರುವ ಆಬ್ಜೆಕ್ಟ್
  this.brand = brandName;
  this.color = carColor;
}

// ಮೆಮೊರಿ ಉಳಿಸಲು Prototype ಬಳಕೆ
Car.prototype.start = function() {
  console.log(`${this.brand} ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!`);
};

// 'new' ಕೀವರ್ಡ್ ಕಡ್ಡಾಯ
const myCar1 = new Car("Tata", "Red");
myCar1.start();
ಔಟ್‌ಪುಟ್:
> Tata ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!

4 Class (ಕ್ಲಾಸ್)

ಸಾಮಾನ್ಯ ವಿವರಣೆ (Non-IT):

ಇದು ಕಾಂಟ್ರಾಕ್ಟರ್‌ನ ಅತ್ಯಾಧುನಿಕ ರೂಪ. ಒಂದು ಸ್ಮಾರ್ಟ್ ಕಾರ್ಖಾನೆ ಇದ್ದಂತೆ. ಇಲ್ಲಿ ಎಲ್ಲವೂ ಅತ್ಯಂತ ವ್ಯವಸ್ಥಿತವಾಗಿ ಬರೆಯಲ್ಪಟ್ಟಿರುತ್ತದೆ. ನೋಡಲು ಮತ್ತು ಓದಲು ಬಹಳ ಸುಲಭ.

ಪ್ರೊ ಲೆವೆಲ್ ವಿವರಣೆ (Technical):

ಇದು 2015 ರಲ್ಲಿ (ES6) ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ಗೆ ಪರಿಚಯಿಸಲಾದ ಹೊಸ ವಿಧಾನ. ತಾಂತ್ರಿಕವಾಗಿ ಹೇಳಬೇಕೆಂದರೆ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ Class ಎಂಬುದು ವಾಸ್ತವದಲ್ಲಿ 'Constructor Function' ನ ಇನ್ನೊಂದು ಸುಂದರವಾದ ಮುಖವಾಡ (Syntactic Sugar). ಒಳಗಡೆ ಕೆಲಸ ಮಾಡುವುದು ಹಳೆಯ Prototype ವಿಧಾನವೇ, ಆದರೆ ಡೆವಲಪರ್‌ಗಳಿಗೆ ಕೋಡ್ ಬರೆಯಲು (OOPs ಕಾನ್ಸೆಪ್ಟ್ - Inheritance, Encapsulation) ಇದು ಅತ್ಯಂತ ಸುಲಭ ಮತ್ತು ಕ್ಲೀನ್ ಆಗಿದೆ.

  • ಎಲ್ಲಿ ಬಳಸಬೇಕು? ಆಧುನಿಕ ಪ್ರಾಜೆಕ್ಟ್‌ಗಳಲ್ಲಿ (React, Node.js, Angular). ದೊಡ್ಡ ಅಪ್ಲಿಕೇಶನ್‌ಗಳನ್ನು ನಿರ್ಮಿಸುವಾಗ ಆಬ್ಜೆಕ್ಟ್-ಓರಿಯೆಂಟೆಡ್ ಶೈಲಿಯನ್ನು ಅಚ್ಚುಕಟ್ಟಾಗಿ ಅಳವಡಿಸಲು. 

class Car {
  constructor(brandName, carColor) {
    this.brand = brandName;
    this.color = carColor;
  }

  // ಮೆಥಡ್‌ಗಳು ತಾನಾಗಿಯೇ Prototype ಗೆ ಸೇರಿಕೊಳ್ಳುತ್ತವೆ (ಮೆಮೊರಿ ಉಳಿತಾಯ)
  start() {
    console.log(`${this.brand} ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!`);
  }
}

const modernCar = new Car("Tata", "Red");
modernCar.start();
ಔಟ್‌ಪುಟ್:
> Tata ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!

ಸಂಕ್ಷಿಪ್ತ ಹೋಲಿಕೆ (Summary Table)

ವಿಧಾನ (Method) ಮರುಬಳಕೆ (Reusability) ಮೆಮೊರಿ ಉಳಿತಾಯ (Memory Efficiency) ಯಾವಾಗ ಬಳಸಬೇಕು? (Use Case)
Object Literal ಇಲ್ಲ (No) ಕಡಿಮೆ (ಪ್ರತಿ ಬಾರಿ ಹೊಸ ಡೇಟಾ) ಒಂದೇ ಆಬ್ಜೆಕ್ಟ್ ಬೇಕಿದ್ದಾಗ, ಸೆಟ್ಟಿಂಗ್ಸ್/ಕಾನ್ಫಿಗರೇಶನ್.
Factory Function ಹೌದು (Yes) ಕಡಿಮೆ (ಮೆಥಡ್‌ಗಳು ರಿಪೀಟ್ ಆಗುತ್ತವೆ) new ಕೀವರ್ಡ್ ಬೇಡವಾದಾಗ, ಚಿಕ್ಕ ಪ್ರಾಜೆಕ್ಟ್‌ಗಳಿಗೆ.
Constructor Fn ಹೌದು (Yes) ಹೆಚ್ಚು (Prototype ಬಳಸುವುದರಿಂದ) ಹಳೆಯ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಕೋಡ್ (ES5) ಬರೆಯುವಾಗ.
ES6 Class ಹೌದು (Yes) ಹೆಚ್ಚು (Prototype ಆಧರಿತ) ಆಧುನಿಕ ಪ್ರಾಜೆಕ್ಟ್‌ಗಳಲ್ಲಿ, ದೊಡ್ಡ ಲೆವೆಲ್ ಕೋಡಿಂಗ್ (Pro level) ಮಾಡುವಾಗ.
