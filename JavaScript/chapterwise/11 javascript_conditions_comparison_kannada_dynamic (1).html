ಭಾಗ 1: Conditions ಎಂದರೇನು?

1.1 ನೈಜ ಜೀವನದಲ್ಲಿ Condition

ನೀವು ಒಂದು ಪರೀಕ್ಷೆ ಬರೆದಿದ್ದೀರಿ ಎಂದುಕೊಳ್ಳಿ. ಪರೀಕ್ಷೆಯಲ್ಲಿ ಪಾಸ್ ಆಗಲು ಕನಿಷ್ಠ 35 ಅಂಕಗಳು ಬೇಕು.

  • ಅಂಕಗಳು 35 ಅಥವಾ ಅದಕ್ಕಿಂತ ಹೆಚ್ಚು ಇದ್ದರೆ — Pass.
  • ಅಂಕಗಳು 35 ಕ್ಕಿಂತ ಕಡಿಮೆ ಇದ್ದರೆ — Fail.

ನೀವು ತೆಗೆದುಕೊಳ್ಳುವ ನಿರ್ಧಾರವು ಒಂದು ಷರತ್ತಿನ ಮೇಲೆ ಅವಲಂಬಿತವಾಗಿದೆ. ಆ ಷರತ್ತೇ Condition.

ಕಂಪ್ಯೂಟರ್‌ನಲ್ಲಿ ಕೂಡ ಇದೇ ತರ್ಕವನ್ನು ಬಳಸಬಹುದು.

let marks = 80;

if (marks >= 35) {
  console.log("Pass");
}

Output:

Pass

ಈ ಉದಾಹರಣೆಯನ್ನು ಹಂತ ಹಂತವಾಗಿ ಅರ್ಥಮಾಡಿಕೊಳ್ಳಿ.

  1. let marks = 80; — marks ಎಂಬ Variable ನಲ್ಲಿ 80 ಅನ್ನು ಸಂಗ್ರಹಿಸಲಾಗಿದೆ.
  2. if — ಮುಂದಿನ ಷರತ್ತನ್ನು ಪರಿಶೀಲಿಸಲು JavaScript ಗೆ ಸೂಚಿಸುತ್ತದೆ.
  3. marks >= 35 — ಅಂಕಗಳು 35 ಕ್ಕಿಂತ ಹೆಚ್ಚು ಅಥವಾ ಅದಕ್ಕೆ ಸಮಾನವೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ.
  4. 80 >= 35 ಫಲಿತಾಂಶ true.
  5. ಆದ್ದರಿಂದ { } ಒಳಗಿನ ಕೋಡ್ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.
  6. console.log("Pass") ಎಂಬುದು Pass ಅನ್ನು Output ನಲ್ಲಿ ತೋರಿಸುತ್ತದೆ.

1.2 Condition ಎಂದರೇನು?

Condition ಎಂದರೆ ಒಂದು ನಿರ್ದಿಷ್ಟ ಷರತ್ತು ಸತ್ಯವೇ ಅಥವಾ ಅಸತ್ಯವೇ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಿ, ಅದರ ಆಧಾರದ ಮೇಲೆ ಪ್ರೋಗ್ರಾಂನ ಮುಂದಿನ ಕಾರ್ಯವನ್ನು ನಿರ್ಧರಿಸಲು ಬಳಸುವ Expression.

ಸಾಮಾನ್ಯವಾಗಿ Condition ನಿಂದ true ಅಥವಾ false ಎಂಬ Boolean ಫಲಿತಾಂಶ ಸಿಗುತ್ತದೆ. ಆದರೆ JavaScript ನ if Statement ನಲ್ಲಿ Number, String, Object ಮುಂತಾದ ಮೌಲ್ಯಗಳನ್ನೂ ನೇರವಾಗಿ ಬಳಸಬಹುದು. ಇವುಗಳನ್ನು ನಂತರ Truthy ಮತ್ತು Falsy ಭಾಗದಲ್ಲಿ ಕಲಿಯೋಣ.

Condition ಎಲ್ಲಿ ಉಪಯೋಗವಾಗುತ್ತದೆ?

ಬಳಕೆ                ಷರತ್ತಿನ ಉದಾಹರಣೆ       
ಪಾಸ್ ಅಥವಾ ಫೇಲ್      marks >= 35         
ವಯಸ್ಸು ಪರಿಶೀಲನೆ      age >= 18           
Login ಪರಿಶೀಲನೆ      isLoggedIn === true 
Password ಪರಿಶೀಲನೆ    password.length >= 8
Stock ಲಭ್ಯತೆ        quantity > 0         
Internet connection isOnline === true   
ಪ್ರವೇಶ ಅನುಮತಿ        isAdmin === true     

ನೈಜ ವೆಬ್‌ಸೈಟ್‌ಗಳಲ್ಲಿ Form Validation, Login Flow, Shopping Cart, Payment Status, User Permissions ಮುಂತಾದ ಅನೇಕ ಕಾರ್ಯಗಳಲ್ಲಿ Conditions ಬಳಸಲಾಗುತ್ತದೆ.

1.3 Boolean ಎಂದರೇನು?

JavaScript ನಲ್ಲಿ Boolean ಎಂಬುದು ಕೇವಲ ಎರಡು ಮೌಲ್ಯಗಳನ್ನು ಹೊಂದಿರುವ Data Type.

let isAvailable = true;
let isCompleted = false;

console.log(isAvailable); // true
console.log(isCompleted); // false
  • true ಎಂದರೆ ಷರತ್ತು ಸತ್ಯ.
  • false ಎಂದರೆ ಷರತ್ತು ಅಸತ್ಯ.

JavaScript ನಲ್ಲಿ ಇವುಗಳನ್ನು ಸಣ್ಣ ಅಕ್ಷರಗಳಲ್ಲಿ ಬರೆಯಬೇಕು. True ಮತ್ತು False JavaScript ನ Boolean Literals ಅಲ್ಲ.

console.log(typeof true);  // "boolean"
console.log(typeof false); // "boolean"

ಭಾಗ 2: Comparison Operators ಸಂಪೂರ್ಣ ವಿವರಣೆ

2.1 Comparison Operator ಎಂದರೇನು?

ಎರಡು ಮೌಲ್ಯಗಳನ್ನು ಹೋಲಿಸಲು ಬಳಸುವ Operator ಅನ್ನು Comparison Operator ಎನ್ನುತ್ತಾರೆ.

ಉದಾಹರಣೆಗೆ:

console.log(10 > 5);

Output:

true

ಇಲ್ಲಿ 10 ಮತ್ತು 5 ಎಂಬ ಮೌಲ್ಯಗಳನ್ನು > Operator ಮೂಲಕ ಹೋಲಿಸಲಾಗಿದೆ. ಫಲಿತಾಂಶ true.

2.2 ಎಲ್ಲಾ ಎಂಟು ಮುಖ್ಯ Comparison Operators

Operator English ಹೆಸರು            ಕನ್ನಡದ ಅರ್ಥ                          ಉದಾಹರಣೆ      Result 
>      Greater than              ಗಿಂತ ದೊಡ್ಡದು                          10 > 5    true 
<      Less than                ಗಿಂತ ಚಿಕ್ಕದು                          3 < 8      true 
>=      Greater than or equal to ದೊಡ್ಡದು ಅಥವಾ ಸಮಾನ                    5 >= 5    true 
<=      Less than or equal to    ಚಿಕ್ಕದು ಅಥವಾ ಸಮಾನ                    4 <= 5    true 
==      Loose equality            Type Conversion ನಿಯಮಗಳೊಂದಿಗೆ ಸಮಾನತೆ  5 == "5"  true 
===    Strict equality          Type ಮತ್ತು Value ಎರಡರ ಸಮಾನತೆ          5 === "5" false
!=      Loose inequality          Type Conversion ನಿಯಮಗಳೊಂದಿಗೆ ಅಸಮಾನತೆ 5 != "6"  true 
!==    Strict inequality        Strict ನಿಯಮಗಳ ಪ್ರಕಾರ ಅಸಮಾನತೆ          5 !== "5" true 

ಈಗ ಪ್ರತಿಯೊಂದನ್ನು ವಿವರವಾಗಿ ಕಲಿಯೋಣ.

2.3 Greater Than (>)

ಎಡಭಾಗದ ಮೌಲ್ಯವು ಬಲಭಾಗದ ಮೌಲ್ಯಕ್ಕಿಂತ ದೊಡ್ಡದಾಗಿದ್ದರೆ true ಬರುತ್ತದೆ.

console.log(20 > 10); // true
console.log(5 > 10);  // false
console.log(10 > 10); // false

ವಿವರಣೆ:

  • 20 > 10 — 20 ದೊಡ್ಡದು; true.
  • 5 > 10 — 5 ದೊಡ್ಡದಲ್ಲ; false.
  • 10 > 10 — ಎರಡೂ ಸಮಾನ; false.

ಮುಖ್ಯ ನಿಯಮ: > ಎಂದರೆ ದೊಡ್ಡದು ಮಾತ್ರ. ಸಮಾನವಾಗಿದ್ದರೆ ಸಾಕಾಗುವುದಿಲ್ಲ.

2.4 Less Than (<)

ಎಡಭಾಗದ ಮೌಲ್ಯವು ಬಲಭಾಗದ ಮೌಲ್ಯಕ್ಕಿಂತ ಚಿಕ್ಕದಾಗಿದ್ದರೆ true ಬರುತ್ತದೆ.

console.log(5 < 10);  // true
console.log(15 < 10); // false
console.log(10 < 10); // false

< Operator ಸಮಾನತೆಯನ್ನು ಸ್ವೀಕರಿಸುವುದಿಲ್ಲ.

2.5 Greater Than or Equal To (>=)

ಎಡಭಾಗದ ಮೌಲ್ಯವು ದೊಡ್ಡದಾಗಿದ್ದರೂ ಅಥವಾ ಎರಡೂ ಮೌಲ್ಯಗಳು ಸಮಾನವಾಗಿದ್ದರೂ true ಬರುತ್ತದೆ.

console.log(40 >= 35); // true
console.log(35 >= 35); // true
console.log(20 >= 35); // false

ಪರೀಕ್ಷೆಯ ಪಾಸ್ ಮಾರ್ಕ್ ಅಥವಾ ಕನಿಷ್ಠ ವಯಸ್ಸನ್ನು ಪರೀಕ್ಷಿಸಲು ಇದು ಉಪಯುಕ್ತ.

2.6 Less Than or Equal To (<=)

ಎಡಭಾಗದ ಮೌಲ್ಯವು ಚಿಕ್ಕದಾಗಿದ್ದರೂ ಅಥವಾ ಸಮಾನವಾಗಿದ್ದರೂ true ಬರುತ್ತದೆ.

console.log(10 <= 20); // true
console.log(20 <= 20); // true
console.log(25 <= 20); // false

ಉದಾಹರಣೆಗೆ, ಒಂದು ಉತ್ಪನ್ನದ ಬೆಲೆ ನಿಮ್ಮ ಬಜೆಟ್ ಒಳಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಲು ಇದನ್ನು ಬಳಸಬಹುದು.

let price = 800;
let budget = 1000;

console.log(price <= budget); // true

2.7 ಈ ನಾಲ್ಕು Operators ನಡುವಿನ ವ್ಯತ್ಯಾಸ

let a = 10;
let b = 10;

console.log(a > b);  // false
console.log(a < b);  // false
console.log(a >= b); // true
console.log(a <= b); // true

ಎರಡೂ ಮೌಲ್ಯಗಳು ಸಮಾನವಾದಾಗ > ಮತ್ತು < ಎರಡೂ false ನೀಡುತ್ತವೆ. ಆದರೆ >= ಮತ್ತು <= ಎರಡೂ true ನೀಡುತ್ತವೆ.

ಭಾಗ 3: Equality Operators — == ಮತ್ತು ===

ಇದು JavaScript ನಲ್ಲಿ ಅತ್ಯಂತ ಮುಖ್ಯವಾದ ವಿಷಯ. Beginner ಗಳು ಮಾತ್ರವಲ್ಲದೆ ಅನುಭವಿಗಳೂ ಇದನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಅರ್ಥಮಾಡಿಕೊಂಡಿರಬೇಕು.

3.1 == ಎಂದರೇನು?

== ಅನ್ನು Loose Equality Operator ಎನ್ನುತ್ತಾರೆ.

ಎರಡು ಮೌಲ್ಯಗಳನ್ನು ಹೋಲಿಸುವಾಗ JavaScript ನ ನಿಯಮಗಳ ಪ್ರಕಾರ ಅಗತ್ಯವಿದ್ದರೆ Type Conversion ಮಾಡುತ್ತದೆ.

console.log(5 == 5);   // true
console.log(5 == "5"); // true

ಎರಡನೆಯ ಉದಾಹರಣೆಯಲ್ಲಿ:

  • 5 — Number Type.
  • "5" — String Type.
  • == ಬಳಸಿದಾಗ JavaScript Type Conversion ನಿಯಮಗಳನ್ನು ಅನ್ವಯಿಸಿ ಅವುಗಳನ್ನು ಹೋಲಿಸುತ್ತದೆ.
  • ಈ ನಿರ್ದಿಷ್ಟ ಉದಾಹರಣೆಯಲ್ಲಿ ಫಲಿತಾಂಶ true.

3.2 === ಎಂದರೇನು?

=== ಅನ್ನು Strict Equality Operator ಎನ್ನುತ್ತಾರೆ.

ಇದು Type Conversion ಮೂಲಕ ವಿಭಿನ್ನ Types ಗಳನ್ನು ಸಮಾನಗೊಳಿಸುವುದಿಲ್ಲ. Primitive ಮೌಲ್ಯಗಳಿಗೆ Type ಮತ್ತು Value ಎರಡೂ ಹೊಂದಾಣಿಕೆಯಾಗಬೇಕು.

console.log(5 === 5);   // true
console.log(5 === "5"); // false

ಇಲ್ಲಿ ಎರಡನೆಯ ಉದಾಹರಣೆ false, ಏಕೆಂದರೆ 5 Number; "5" String.

3.3 == ಮತ್ತು === ಹೋಲಿಕೆ

Loose Equality — ==

console.log(10 == "10"); // true
console.log(0 == false); // true

ಕೆಲವು ವಿಭಿನ್ನ Types ಗಳ ಮೌಲ್ಯಗಳು Type Conversion ನಂತರ ಸಮಾನವೆಂದು ಪರಿಗಣಿಸಲ್ಪಡಬಹುದು.

Strict Equality — ===

console.log(10 === "10"); // false
console.log(0 === false); // false

Type ಮತ್ತು Value ಹೊಂದಾಣಿಕೆಯಿರಬೇಕು. ವಿಭಿನ್ನ Types ಗಳ ಮೌಲ್ಯಗಳನ್ನು ಕೇವಲ ಪರಿವರ್ತಿಸಿ ಸಮಾನಗೊಳಿಸುವುದಿಲ್ಲ.

ಇನ್ನೂ ಕೆಲವು ಮುಖ್ಯ ಉದಾಹರಣೆಗಳು

console.log(1 == true);      // true
console.log(1 === true);     // false

console.log("" == false);    // true
console.log("" === false);   // false

console.log(null == undefined);  // true
console.log(null === undefined); // false

ಈ ಫಲಿತಾಂಶಗಳು JavaScript ನ ನಿರ್ದಿಷ್ಟ Equality Algorithm ಗಳಿಂದ ಬರುತ್ತವೆ. ಆದ್ದರಿಂದ == ಬಳಸಿದಾಗ ಫಲಿತಾಂಶ ಊಹಿಸುವ ಬದಲು ಅದರ Conversion ನಿಯಮಗಳನ್ನು ತಿಳಿದುಕೊಳ್ಳಬೇಕು.

Professional Coding ನಲ್ಲಿ ಯಾವುದನ್ನು ಬಳಸಬೇಕು?

ಸಾಮಾನ್ಯವಾಗಿ === ಮತ್ತು !== ಬಳಸುವುದು ಉತ್ತಮ.

let enteredAge = "18";

if (enteredAge === 18) {
  console.log("Eligible");
} else {
  console.log("Types do not match");
}

Output:

Types do not match

ಕಾರಣ: enteredAge ಒಂದು String. ಬಳಕೆದಾರರು Text Input ಮೂಲಕ ಸಂಖ್ಯೆಯನ್ನು ನೀಡಿದಾಗ ಅದನ್ನು ಅಗತ್ಯಕ್ಕೆ ತಕ್ಕಂತೆ Validate ಮಾಡಿ, Number ಆಗಿ ಪರಿವರ್ತಿಸಿ ನಂತರ ಹೋಲಿಸಬೇಕು.

let enteredAge = "18";
let age = Number(enteredAge);

if (Number.isFinite(age) && age >= 18) {
  console.log("Eligible");
}

Output:

Eligible

ಗಮನಿಸಿ: ನೈಜ Form ಗಳಲ್ಲಿ ಖಾಲಿ String ಅನ್ನು ನೇರವಾಗಿ Number() ಮಾಡಿದರೆ 0 ಸಿಗುತ್ತದೆ. ಆದ್ದರಿಂದ Input ಖಾಲಿಯಿದೆಯೇ ಮತ್ತು ಅದರ Format ಸರಿಯಿದೆಯೇ ಎಂಬುದನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ ಪರಿಶೀಲಿಸುವುದು ಅಗತ್ಯ.

3.4 != ಮತ್ತು !==

ಇವು Equality Operators ಗಳ ವಿರುದ್ಧದ ಅರ್ಥವನ್ನು ನೀಡುತ್ತವೆ.

  • != — Loose Inequality.
  • !== — Strict Inequality.
console.log(5 != "5");   // false
console.log(5 !== "5");  // true

console.log(5 != 8);     // true
console.log(5 !== 8);    // true

5 != "5" ನಲ್ಲಿ Loose Equality ಪ್ರಕಾರ ಎರಡೂ ಸಮಾನವೆಂದು ಪರಿಗಣಿಸಲ್ಪಡುತ್ತವೆ. ಆದ್ದರಿಂದ != ಫಲಿತಾಂಶ false.

5 !== "5" ನಲ್ಲಿ Type ಬೇರೆ ಇರುವುದರಿಂದ ಅವು Strict Equality ಪ್ರಕಾರ ಸಮಾನವಲ್ಲ. ಆದ್ದರಿಂದ !== ಫಲಿತಾಂಶ true.

ಈ ನಿಯಮವನ್ನು ನೆನಪಿಡಿ:

  • == / === — ಸಮಾನತೆ ಪರಿಶೀಲಿಸುತ್ತವೆ.
  • != / !== — ಅಸಮಾನತೆ ಪರಿಶೀಲಿಸುತ್ತವೆ.

ಇವುಗಳಲ್ಲಿ == ಮತ್ತು != Type Conversion ಮಾಡಬಹುದಾದರೆ, === ಮತ್ತು !== Strict ನಿಯಮಗಳನ್ನು ಅನುಸರಿಸುತ್ತವೆ.

ಭಾಗ 4: JavaScript ನಲ್ಲಿ if ಮತ್ತು Conditional Statements

Comparison Operators ಷರತ್ತನ್ನು ಪರಿಶೀಲಿಸುತ್ತವೆ. Conditional Statements ಆ ಷರತ್ತಿನ ಫಲಿತಾಂಶಕ್ಕೆ ಅನುಗುಣವಾಗಿ ಯಾವ ಕೋಡ್ ಕಾರ್ಯನಿರ್ವಹಿಸಬೇಕು ಎಂಬುದನ್ನು ನಿರ್ಧರಿಸುತ್ತವೆ.

4.1 if Statement

ಒಂದು Condition ಸತ್ಯವಾದಾಗ ಮಾತ್ರ ನಿರ್ದಿಷ್ಟ ಕೋಡ್ ಕಾರ್ಯನಿರ್ವಹಿಸಬೇಕಾದರೆ if ಬಳಸುತ್ತೇವೆ.

Syntax:

if (condition) {
  // condition ಸತ್ಯವಾದಾಗ ನಡೆಯುವ ಕೋಡ್
}

ಉದಾಹರಣೆ:

let temperature = 35;

if (temperature > 30) {
  console.log("It is hot");
}

Output:

It is hot

temperature > 30 ಸತ್ಯವಾದ್ದರಿಂದ if Block ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

Condition false ಆಗಿದ್ದರೆ ಒಳಗಿನ ಕೋಡ್ ನಡೆಯುವುದಿಲ್ಲ.

let temperature = 20;

if (temperature > 30) {
  console.log("It is hot");
}

console.log("Program finished");

Output:

Program finished

Curly Braces {} ಏಕೆ ಬಳಸಬೇಕು?

{} ಒಂದು Block ಅನ್ನು ಸೂಚಿಸುತ್ತದೆ.

if (true) {
  console.log("First line");
  console.log("Second line");
}

ಎರಡೂ Statements if Block ನ ಭಾಗವಾಗಿವೆ.

ಕೆಲವು ಸಂದರ್ಭಗಳಲ್ಲಿ JavaScript ಒಂದೇ Statement ಗೆ {} ಇಲ್ಲದೆಯೂ ಅವಕಾಶ ನೀಡುತ್ತದೆ. ಆದರೆ Professional Coding ನಲ್ಲಿ ಷರತ್ತುಗಳಿಗೆ {} ಬಳಸುವ ಅಭ್ಯಾಸ ಉತ್ತಮ. ಇದು ತಪ್ಪುಗಳನ್ನು ಕಡಿಮೆ ಮಾಡಿ ಕೋಡ್ ಓದಲು ಸುಲಭಗೊಳಿಸುತ್ತದೆ.

4.2 if...else

Condition ಸತ್ಯವಾದಾಗ ಒಂದು ಕಾರ್ಯ, ಅಸತ್ಯವಾದಾಗ ಬೇರೆ ಕಾರ್ಯ ಮಾಡಬೇಕಾದರೆ if...else ಬಳಸುತ್ತೇವೆ.

Syntax:

if (condition) {
  // true ಆಗಿದ್ದರೆ
} else {
  // false ಆಗಿದ್ದರೆ
}

ಉದಾಹರಣೆ:

let marks = 28;

if (marks >= 35) {
  console.log("Pass");
} else {
  console.log("Fail");
}

Output:

Fail

if ಮತ್ತು else ಗಳಲ್ಲಿ ಒಂದು ಮಾರ್ಗ ಮಾತ್ರ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

4.3 if...else if...else

ಹಲವು ಷರತ್ತುಗಳಲ್ಲಿ ಯಾವುದು ಮೊದಲು ಸತ್ಯವಾಗುತ್ತದೆಯೋ ಆ ಮಾರ್ಗವನ್ನು ಆಯ್ಕೆ ಮಾಡಲು ಬಳಸುತ್ತೇವೆ.

let marks = 76;

if (marks >= 90) {
  console.log("Grade A+");
} else if (marks >= 80) {
  console.log("Grade A");
} else if (marks >= 70) {
  console.log("Grade B");
} else if (marks >= 35) {
  console.log("Pass");
} else {
  console.log("Fail");
}

Output:

Grade B

ಇದು ಹೀಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ:

  1. 76 >= 90 → false.
  2. 76 >= 80 → false.
  3. 76 >= 70 → true.
  4. Grade B ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ.
  5. ನಂತರದ else if ಷರತ್ತುಗಳನ್ನು ಈ ಸರಣಿಯಲ್ಲಿ ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ.

Professional ನಿಯಮ: ಷರತ್ತುಗಳ ಕ್ರಮವನ್ನು ಸರಿಯಾಗಿ ಯೋಜಿಸಬೇಕು. ಅತಿ ವ್ಯಾಪಕವಾದ ಷರತ್ತನ್ನು ಮೊದಲಿಗೆ ಬರೆಯುವುದರಿಂದ ನಿರ್ದಿಷ್ಟ ಫಲಿತಾಂಶಗಳ Block ಗಳು ಕಾರ್ಯನಿರ್ವಹಿಸದೇ ಹೋಗಬಹುದು.

4.4 Nested if

ಒಂದು if Block ಒಳಗೆ ಮತ್ತೊಂದು if ಬರೆಯುವುದನ್ನು Nested if ಎನ್ನುತ್ತಾರೆ.

ಉದಾಹರಣೆ: ವಯಸ್ಸು ಮತ್ತು ಪರೀಕ್ಷಾ ಅಂಕಗಳನ್ನು ಎರಡನ್ನೂ ಪರಿಶೀಲಿಸೋಣ.

let age = 20;
let marks = 80;

if (age >= 18) {
  if (marks >= 35) {
    console.log("Eligible and Pass");
  } else {
    console.log("Eligible but Fail");
  }
} else {
  console.log("Not eligible by age");
}

Output:

Eligible and Pass

ಮೊದಲು ವಯಸ್ಸು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ. ವಯಸ್ಸಿನ ಷರತ್ತು ಸತ್ಯವಾದರೆ ಮಾತ್ರ ಅಂಕಗಳ ಷರತ್ತನ್ನು ಪರಿಶೀಲಿಸಲಾಗುತ್ತದೆ.

ಇದೇ ತರ್ಕವನ್ನು ಕೆಲವು ಸಂದರ್ಭಗಳಲ್ಲಿ && ಮೂಲಕವೂ ಬರೆಯಬಹುದು:

if (age >= 18 && marks >= 35) {
  console.log("Eligible and Pass");
}

ಆದರೆ ಎರಡೂ ರೂಪಗಳು ಪ್ರತಿಯೊಂದು ಸನ್ನಿವೇಶದಲ್ಲಿಯೂ ಸಮಾನವಾಗಿರುವುದಿಲ್ಲ. ಎರಡನೇ ಷರತ್ತನ್ನು ಮೊದಲ ಷರತ್ತು ಸತ್ಯವಾದಾಗ ಮಾತ್ರ ಪರಿಶೀಲಿಸಬೇಕಾದರೆ Nested if ಉಪಯುಕ್ತವಾಗುತ್ತದೆ.

ಭಾಗ 5: Logical Operators — &&, ||, !

Comparison Operators ಸಾಮಾನ್ಯವಾಗಿ ಎರಡು ಮೌಲ್ಯಗಳನ್ನು ಹೋಲಿಸುತ್ತವೆ. Logical Operators ಅನೇಕ ಷರತ್ತುಗಳನ್ನು ಜೋಡಿಸಲು ಅಥವಾ Boolean ಮೌಲ್ಯವನ್ನು ಬದಲಾಯಿಸಲು ಸಹಾಯ ಮಾಡುತ್ತವೆ.

5.1 Logical AND (&&)

&& ಅನ್ನು AND ಎಂದು ಓದಬೇಕು.

ಎರಡೂ ಷರತ್ತುಗಳು ಸತ್ಯವಾಗಿದ್ದರೆ ಮಾತ್ರ Boolean Context ನಲ್ಲಿ ಒಟ್ಟಾರೆ ಫಲಿತಾಂಶ ಸತ್ಯವಾಗುತ್ತದೆ.

ಉದಾಹರಣೆ:

let age = 20;
let hasID = true;

if (age >= 18 && hasID === true) {
  console.log("Access granted");
} else {
  console.log("Access denied");
}

Output:

Access granted

ಇಲ್ಲಿ:

  • age >= 18 → true.
  • hasID === true → true.
  • true && true → true.

AND Truth Table

Condition 1 Condition 2 ಫಲಿತಾಂಶ
true      true      true 
true      false      false
false      true      false
false      false      false

ಎಲ್ಲಿ ಬಳಸುತ್ತೇವೆ? ಕನಿಷ್ಠ ವಯಸ್ಸು ಪೂರೈಸಬೇಕು ಮತ್ತು ಗುರುತಿನ ಚೀಟಿ ಇರಬೇಕು; Password ಸರಿಯಾಗಿರಬೇಕು ಮತ್ತು Account ಸಕ್ರಿಯವಾಗಿರಬೇಕು — ಇಂತಹ ಸಂದರ್ಭಗಳಲ್ಲಿ.

5.2 Logical OR (||)

|| ಅನ್ನು OR ಎಂದು ಓದಬೇಕು.

ಎರಡು ಷರತ್ತುಗಳಲ್ಲಿ ಕನಿಷ್ಠ ಒಂದು ಸತ್ಯವಾಗಿದ್ದರೂ Boolean Context ನಲ್ಲಿ ಒಟ್ಟಾರೆ ಫಲಿತಾಂಶ ಸತ್ಯವಾಗುತ್ತದೆ.

let hasEmail = false;
let hasPhone = true;

if (hasEmail || hasPhone) {
  console.log("Contact detail available");
} else {
  console.log("No contact detail");
}

Output:

Contact detail available

ಇಲ್ಲಿ hasEmail false ಆಗಿದೆ. ಆದರೆ hasPhone true. ಆದ್ದರಿಂದ OR ಫಲಿತಾಂಶ true.

OR Truth Table

Condition 1 Condition 2 ಫಲಿತಾಂಶ
true      true      true 
true      false      true 
false      true      true 
false      false      false

AND ಮತ್ತು OR ವ್ಯತ್ಯಾಸ ನೆನಪಿಡಿ:

  • && — ಎರಡೂ ಸತ್ಯವಾಗಿರಬೇಕು.
  • || — ಕನಿಷ್ಠ ಒಂದು ಸತ್ಯವಾಗಿರಬೇಕು.

5.3 Logical NOT (!)

! ಒಂದು Boolean Context ನಲ್ಲಿ ಸತ್ಯವನ್ನು ಅಸತ್ಯವಾಗಿಯೂ, ಅಸತ್ಯವನ್ನು ಸತ್ಯವಾಗಿಯೂ ಪರಿವರ್ತಿಸುತ್ತದೆ.

console.log(!true);  // false
console.log(!false); // true

ಉದಾಹರಣೆ:

let isLoggedIn = false;

if (!isLoggedIn) {
  console.log("Please log in");
}

Output:

Please log in

isLoggedIn false. ಅದರ ಮುಂದೆ ! ಇರುವುದರಿಂದ !isLoggedIn ಸತ್ಯವಾಗುತ್ತದೆ. ಆದ್ದರಿಂದ ಸಂದೇಶ ಪ್ರದರ್ಶಿಸಲಾಗುತ್ತದೆ.

! ಮತ್ತು !== ಒಂದೇ ಅಲ್ಲ

console.log(!true);      // false
console.log(5 !== "5");  // true

! Boolean Context ನಲ್ಲಿ ಮೌಲ್ಯವನ್ನು ವಿರುದ್ಧಗೊಳಿಸುತ್ತದೆ. !== ಎರಡು ಮೌಲ್ಯಗಳನ್ನು Strict Inequality ನಿಯಮದಂತೆ ಹೋಲಿಸುತ್ತದೆ.

5.4 ಮೂರು Logical Operators ಒಟ್ಟಿಗೆ

let age = 22;
let isStudent = true;
let hasPermission = false;

if (age >= 18 && (isStudent || hasPermission)) {
  console.log("Condition satisfied");
}

Output:

Condition satisfied

ತರ್ಕ:

  • age >= 18 → true.
  • isStudent || hasPermission → true || false → true.
  • true && true → true.

ಇಂತಹ Expression ಗಳಲ್ಲಿ Parentheses () ಬಳಸುವುದರಿಂದ ಷರತ್ತಿನ ಅರ್ಥ ಸ್ಪಷ್ಟವಾಗುತ್ತದೆ.

ಭಾಗ 6: Truthy ಮತ್ತು Falsy Values

JavaScript ನಲ್ಲಿ if Statement ಗೆ Boolean ಮೌಲ್ಯಗಳನ್ನಷ್ಟೇ ನೀಡಬೇಕೆಂಬ ನಿಯಮವಿಲ್ಲ.

if (100) {
  console.log("Runs");
}

Output:

Runs

ಇಲ್ಲಿ 100 Boolean true ಅಲ್ಲ. ಆದರೂ if ಒಳಗೆ ಅದು Truthy ಎಂದು ಪರಿಗಣಿಸಲ್ಪಡುತ್ತದೆ.

ಇದಕ್ಕೆ ಕಾರಣ JavaScript ನ ToBoolean ನಿಯಮ.

6.1 Falsy Values — ಸಂಪೂರ್ಣ ಪಟ್ಟಿ

ಸಾಮಾನ್ಯ JavaScript ಪರಿಸರದಲ್ಲಿ Falsy ಆಗಿರುವ ಮುಖ್ಯ ಮೌಲ್ಯಗಳು ಹೀಗಿವೆ:

ಮೌಲ್ಯ        ಅರ್ಥ                       
false      Boolean false               
0          Number zero                 
-0        Negative zero               
0n        BigInt zero                 
""        Empty String               
null      ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಮೌಲ್ಯ ಇಲ್ಲ
undefined ಮೌಲ್ಯ ನಿಗದಿಪಡಿಸಿಲ್ಲ         
NaN        Not-a-Number               

ಹಳೆಯ Browser ಗಳಲ್ಲಿನ ವಿಶೇಷ document.all ವರ್ತನೆ ಒಂದು ಅಪವಾದವಾಗಿದೆ; ಅದು ಸಾಮಾನ್ಯ JavaScript Coding ನಲ್ಲಿ ಅಪರೂಪಕ್ಕೆ ಮಾತ್ರ ಸಂಬಂಧಿಸಿದೆ.

ಉದಾಹರಣೆ:

if (0) {
  console.log("A");
} else {
  console.log("B");
}

Output:

B

0 Falsy ಆಗಿರುವುದರಿಂದ else ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

6.2 Truthy Values

ಮೇಲಿನ Falsy Values ಗಳನ್ನು ಹೊರತುಪಡಿಸಿ ಹೆಚ್ಚಿನ ಮೌಲ್ಯಗಳು Truthy ಆಗಿರುತ್ತವೆ.

console.log(Boolean("Hello")); // true
console.log(Boolean("0"));     // true
console.log(Boolean("false")); // true
console.log(Boolean(-1));      // true
console.log(Boolean([]));      // true
console.log(Boolean({}));      // true
console.log(Boolean(" "));     // true

ಇಲ್ಲಿ ಸಾಮಾನ್ಯವಾಗಿ ಹೆಚ್ಚು ತಪ್ಪಾಗುವ ಅಂಶಗಳನ್ನು ಗಮನಿಸಿ:

Value      Truthy / Falsy ಕಾರಣ             
0        Falsy          Number zero     
"0"      Truthy          ಖಾಲಿಯಲ್ಲದ String
false    Falsy          Boolean false   
"false" Truthy          String           
""      Falsy          ಖಾಲಿ String     
" "      Truthy          ಒಂದು Space ಇದೆ   
[]      Truthy          Array Object     
{}      Truthy          Object           

ಮುಖ್ಯ ನಿಯಮ: ಖಾಲಿ Array [] ಮತ್ತು ಖಾಲಿ Object {} ಗಳು false ಆಗಿರುವುದಿಲ್ಲ. ಅವು Truthy.

6.3 Boolean() Function

ಒಂದು Value Boolean Context ನಲ್ಲಿ ಯಾವ ಮೌಲ್ಯವಾಗಿ ಪರಿಗಣಿಸಲ್ಪಡುತ್ತದೆ ಎಂಬುದನ್ನು ಪರೀಕ್ಷಿಸಲು Boolean() ಬಳಸಬಹುದು.

console.log(Boolean(0));        // false
console.log(Boolean(1));        // true
console.log(Boolean(""));       // false
console.log(Boolean("Hello"));  // true

ಇದು ಕೋಡ್ ಕಲಿಯಲು ಮತ್ತು Debugging ಮಾಡಲು ಉಪಯುಕ್ತ. ಆದರೆ ಪ್ರತಿಯೊಂದು Condition ಗೂ Boolean() ಬರೆಯುವ ಅಗತ್ಯವಿಲ್ಲ.

6.4 Falsy Values ಅನ್ನು ! ಮೂಲಕ ಪರಿಶೀಲಿಸುವುದು

let username = "";

if (!username) {
  console.log("Username is empty or missing");
}

Output:

Username is empty or missing

ಆದರೆ !username ಖಾಲಿ String ಮಾತ್ರವಲ್ಲದೆ ಇತರ Falsy ಮೌಲ್ಯಗಳನ್ನೂ ಒಪ್ಪಿಕೊಳ್ಳುತ್ತದೆ. ನಿಮಗೆ ಖಾಲಿ String ಮಾತ್ರವೇ ಪರಿಶೀಲಿಸಬೇಕಿದ್ದರೆ ಹೀಗೆ ಬರೆಯಿರಿ:

if (username === "") {
  console.log("Username is empty");
}

ಯಾವ ರೀತಿಯ Condition ಬರೆಯಬೇಕು ಎಂಬುದು ನಿಮ್ಮ ಉದ್ದೇಶದ ಮೇಲೆ ಅವಲಂಬಿತವಾಗಿರುತ್ತದೆ.

ಭಾಗ 7: Type Coercion ಮತ್ತು Type Conversion

7.1 ಈ ಎರಡರ ಅರ್ಥವೇನು?

JavaScript ನಲ್ಲಿ ಒಂದು Type ನ ಮೌಲ್ಯವನ್ನು ಮತ್ತೊಂದು Type ಆಗಿ ಬದಲಿಸುವ ಪ್ರಕ್ರಿಯೆ ಇದೆ.

Type Conversion ಎಂದರೆ Type ಅನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಪರಿವರ್ತಿಸುವುದು.

let age = Number("25");

console.log(age);        // 25
console.log(typeof age); // "number"

Type Coercion ಎಂದರೆ ಒಂದು Operation ನಡೆಯುವಾಗ JavaScript ಸ್ವಯಂಚಾಲಿತವಾಗಿ Type ಪರಿವರ್ತಿಸುವುದು.

console.log("5" - 2); // 3

ಇಲ್ಲಿ String "5" ಅನ್ನು ಸಂಖ್ಯೆಗೆ ಪರಿವರ್ತಿಸಿ ಗಣಿತ ಕಾರ್ಯಾಚರಣೆ ಮಾಡಲಾಗಿದೆ.

ಆದರೆ + Operator ಹಲವು ಸಂದರ್ಭಗಳಲ್ಲಿ Concatenation ಮಾಡುತ್ತದೆ:

console.log("5" + 2); // "52"

ಇದು 7 ಆಗುವುದಿಲ್ಲ. String ಮತ್ತು Number ನಡುವಿನ ಈ ವರ್ತನೆಗೆ ಸಂಬಂಧಿಸಿದಂತೆ Conversion ನಿಯಮಗಳನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವುದು ಮುಖ್ಯ.

7.2 == ನಲ್ಲಿ Type Coercion

console.log("5" == 5); // true
console.log(false == 0); // true
console.log("" == 0); // true

ಈ ಫಲಿತಾಂಶಗಳು Loose Equality ನಿಯಮಗಳಿಗೆ ಅನುಗುಣವಾಗಿವೆ.

ಆದರೆ ಎಲ್ಲ Falsy Values ಗಳೂ == ನಲ್ಲಿ ಪರಸ್ಪರ ಸಮಾನವಲ್ಲ.

console.log(null == 0);         // false
console.log(null == undefined); // true
console.log(undefined == 0);    // false

ಇವುಗಳ ವ್ಯತ್ಯಾಸವನ್ನು ನೆನಪಿಡಿ. null ಮತ್ತು undefined ಗಳು == ನಲ್ಲಿ ಪರಸ್ಪರ ಸಮಾನವೆಂದು ಪರಿಗಣಿಸಲ್ಪಡುತ್ತವೆ. ಆದರೆ ಅವು 0 ಗೆ ಸಮಾನವಲ್ಲ.

7.3 Relational Comparison ನಲ್ಲಿ Conversion

>, <, >= ಮತ್ತು <= ಬಳಸಿದಾಗ ಎರಡೂ Operands Strings ಆಗಿದ್ದರೆ String ಕ್ರಮದ ಪ್ರಕಾರ ಹೋಲಿಸಬಹುದು.

console.log("10" < "2"); // true

ಏಕೆ? ಎರಡೂ Strings ಆಗಿವೆ. ಅವು ಸಂಖ್ಯೆಗಳಂತೆ ಅಲ್ಲ, String ಕ್ರಮದ ಪ್ರಕಾರ ಹೋಲಿಸಲ್ಪಡುತ್ತವೆ. "1" ಅಕ್ಷರದ ಸ್ಥಾನ "2" ಗಿಂತ ಮೊದಲು ಬರುತ್ತದೆ.

ಸಂಖ್ಯೆಗಳಂತೆ ಹೋಲಿಸಬೇಕಾದರೆ:

console.log(Number("10") < Number("2")); // false
console.log(Number("10") > Number("2")); // true

ಇಲ್ಲಿ ಎರಡೂ ಮೌಲ್ಯಗಳನ್ನು Numbers ಆಗಿ ಪರಿವರ್ತಿಸಲಾಗಿದೆ.

null ಮತ್ತು undefined ಜೊತೆಗಿನ ವ್ಯತ್ಯಾಸ

console.log(null >= 0);     // true
console.log(null == 0);     // false
console.log(undefined < 1); // false

ಮೊದಲ ಉದಾಹರಣೆಯಲ್ಲಿ Relational Comparison ವೇಳೆ null ಸಂಖ್ಯಾತ್ಮಕ ಮೌಲ್ಯವಾಗಿ 0 ಆಗಿ ಪರಿಗಣಿಸಲ್ಪಡುತ್ತದೆ. ಆದರೆ null == 0 Loose Equality ನಿಯಮವು ಅದೇ ಫಲಿತಾಂಶ ನೀಡುವುದಿಲ್ಲ. undefined ಅನ್ನು ಸಂಖ್ಯಾತ್ಮಕವಾಗಿ ಪರಿವರ್ತಿಸಿದಾಗ NaN ದೊರೆಯುವುದರಿಂದ ಅದರ Relational Comparison ಗಳು ಸಾಮಾನ್ಯವಾಗಿ false ಆಗುತ್ತವೆ.

Professional ನಿಯಮ: ವಿಭಿನ್ನ Types ಗಳ ಮೌಲ್ಯಗಳನ್ನು ಹೋಲಿಸುವಾಗ ಸ್ವಯಂಚಾಲಿತ Conversion ಮೇಲೆ ಅವಲಂಬಿಸುವುದಕ್ಕಿಂತ Input ಅನ್ನು Validate ಮಾಡಿ, ಅಗತ್ಯವಿದ್ದರೆ ಸ್ಪಷ್ಟವಾಗಿ Convert ಮಾಡುವುದು ಉತ್ತಮ.

ಭಾಗ 8: NaN, null, undefined ಮತ್ತು Edge Cases

ಇವುಗಳನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವುದು Professional JavaScript ಗೆ ಬಹಳ ಮುಖ್ಯ.

8.1 NaN ಎಂದರೇನು?

NaN ಎಂದರೆ Not-a-Number. ಕೆಲವು ಗಣಿತೀಯ ಅಥವಾ ಸಂಖ್ಯಾತ್ಮಕ ಕಾರ್ಯಾಚರಣೆಗಳು ಮಾನ್ಯ ಸಂಖ್ಯೆಯನ್ನು ನೀಡದಾಗ NaN ದೊರೆಯಬಹುದು.

let result = Number("hello");

console.log(result); // NaN

"hello" ಅನ್ನು Number ಆಗಿ ಪರಿವರ್ತಿಸಲಾಗುವುದಿಲ್ಲ. ಆದ್ದರಿಂದ ಫಲಿತಾಂಶ NaN.

NaN ಅನ್ನು ಹೇಗೆ ಪರಿಶೀಲಿಸಬೇಕು?

let result = Number("hello");

console.log(result === NaN);       // false
console.log(Number.isNaN(result)); // true

ಏಕೆಂದರೆ NaN ಅನ್ನು ಅದರಂತೆಯೇ === ಮೂಲಕ ಹೋಲಿಸಿದಾಗಲೂ ಫಲಿತಾಂಶ false.

ಆದ್ದರಿಂದ:

Number.isNaN(value)

ಎಂಬುದು ಮೌಲ್ಯವು ನಿಜವಾಗಿಯೂ NaN ಆಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುವ ಉತ್ತಮ ವಿಧಾನ.

isNaN(value) ಎಂಬ Global Function ಕೂಡ ಇದೆ. ಆದರೆ ಅದು ಮೌಲ್ಯವನ್ನು ಮೊದಲು ಸಂಖ್ಯೆಯಾಗಿ ಪರಿವರ್ತಿಸಲು ಪ್ರಯತ್ನಿಸುವುದರಿಂದ ಕೆಲವು ವಿಭಿನ್ನ ಫಲಿತಾಂಶಗಳನ್ನು ನೀಡಬಹುದು.

console.log(isNaN("hello"));        // true
console.log(Number.isNaN("hello")); // false

ಮೊದಲ Function "hello" ಅನ್ನು Number ಆಗಿ ಪರಿವರ್ತಿಸಲು ಪ್ರಯತ್ನಿಸಿ NaN ಪಡೆಯುತ್ತದೆ. ಎರಡನೆಯ Function ಮೂಲ ಮೌಲ್ಯವೇ NaN ಆಗಿದೆಯೇ ಎಂದು ಪರೀಕ್ಷಿಸುತ್ತದೆ; String "hello" ಸ್ವತಃ NaN ಅಲ್ಲ.

8.2 null ಮತ್ತು undefined

null ಮತ್ತು undefined ಎರಡೂ ಮೌಲ್ಯ ಇಲ್ಲದಿರುವುದಕ್ಕೆ ಸಂಬಂಧಿಸಿದರೂ ಅವು ಒಂದೇ ಅಲ್ಲ.

let a = null;
let b;

console.log(a); // null
console.log(b); // undefined
  • null — ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಮೌಲ್ಯ ಇಲ್ಲ ಎಂದು ಸೂಚಿಸುವುದು.
  • undefined — ಮೌಲ್ಯ ನಿಯೋಜಿಸದಿರುವುದು ಅಥವಾ ಮೌಲ್ಯ ಲಭ್ಯವಿಲ್ಲದಿರುವ ಕೆಲವು ಸಂದರ್ಭಗಳಲ್ಲಿ ದೊರೆಯುವುದು.

ಹೋಲಿಕೆ:

console.log(null == undefined);  // true
console.log(null === undefined); // false

typeof ಬಳಸಿದಾಗಲೂ ಒಂದು ವಿಶೇಷತೆ ಇದೆ:

console.log(typeof null);      // "object"
console.log(typeof undefined); // "undefined"

typeof null ಫಲಿತಾಂಶ "object" ಎನ್ನುವುದು JavaScript ನ ಐತಿಹಾಸಿಕ ವರ್ತನೆ. ಅದನ್ನು null ನ ನಿಖರ Type ಪರೀಕ್ಷೆಯೆಂದು ತಪ್ಪಾಗಿ ಅರ್ಥಮಾಡಿಕೊಳ್ಳಬಾರದು.

8.3 NaN ಜೊತೆ Comparison

console.log(NaN === NaN); // false
console.log(NaN > 10);    // false
console.log(NaN < 10);    // false
console.log(NaN >= 10);   // false
console.log(NaN <= 10);   // false
console.log(NaN !== NaN); // true

NaN ಇದ್ದಾಗ ಸಾಮಾನ್ಯ ಸಂಖ್ಯಾತ್ಮಕ Comparison ಗಳಿಂದ ನೀವು ನಿರೀಕ್ಷಿಸುವ ಫಲಿತಾಂಶ ಸಿಗದೆ ಇರಬಹುದು. ಆದ್ದರಿಂದ User Input, API Response ಅಥವಾ Calculation ನ ಫಲಿತಾಂಶವನ್ನು ಬಳಸುವ ಮೊದಲು ಅದರ ಮಾನ್ಯತೆಯನ್ನು ಪರಿಶೀಲಿಸುವುದು ಉತ್ತಮ.

8.4 Object ಮತ್ತು Array ಗಳ Comparison

Primitive Values ಗಳನ್ನು ಹೋಲಿಸುವುದು ಮತ್ತು Objects ಗಳನ್ನು ಹೋಲಿಸುವುದು ವಿಭಿನ್ನ.

console.log(10 === 10); // true
console.log([1, 2] === [1, 2]); // false

ಎರಡು Arrays ಗಳಲ್ಲೂ ಒಂದೇ Elements ಇದ್ದರೂ ಅವು ಎರಡು ಪ್ರತ್ಯೇಕ Array Objects ಆಗಿವೆ. === ಅವುಗಳ ಒಳಗಿನ Elements ಗಳನ್ನು ಸ್ವಯಂಚಾಲಿತವಾಗಿ ಹೋಲಿಸುವುದಿಲ್ಲ.

let a = [1, 2];
let b = a;

console.log(a === b); // true

ಈಗ a ಮತ್ತು b ಒಂದೇ Array Object ಅನ್ನು ಸೂಚಿಸುತ್ತವೆ.

Objects ಗಳ ಒಳಗಿನ ವಿಷಯಗಳನ್ನು ಹೋಲಿಸುವುದು ಬೇಕಾದರೆ ನಿಮ್ಮ Data ಪ್ರಕಾರ Deep Comparison ಮಾಡಬೇಕು. ಸರಳವಾಗಿ === ಬಳಸುವುದರಿಂದ ಎರಡು ವಿಭಿನ್ನ Objects ಒಂದೇ ವಿಷಯ ಹೊಂದಿವೆಯೇ ಎಂದು ತಿಳಿಯಲು ಸಾಧ್ಯವಿಲ್ಲ.

8.5 Object.is() — ಇನ್ನಷ್ಟು ನಿಖರವಾದ ಹೋಲಿಕೆ

JavaScript ನಲ್ಲಿ Object.is() ಎಂಬ ವಿಧಾನವೂ ಇದೆ.

console.log(Object.is(NaN, NaN)); // true
console.log(Object.is(0, -0));    // false
console.log(0 === -0);            // true

ಮುಖ್ಯ ವ್ಯತ್ಯಾಸಗಳು:

Comparison    NaN ಮತ್ತು NaN 0 ಮತ್ತು -0
===          false            true         
Object.is() true            false       

ಸಾಮಾನ್ಯ Conditions ಗಳಲ್ಲಿ === ಬಳಸುವುದು ಸರಿಯಾದ ಆಯ್ಕೆ. ವಿಶೇಷ ಸಂಖ್ಯಾತ್ಮಕ Edge Cases ಪರಿಶೀಲಿಸುವ ಅಗತ್ಯವಿದ್ದಾಗ Object.is() ಉಪಯುಕ್ತವಾಗಬಹುದು.

ಭಾಗ 9: switch Statement ಸಂಪೂರ್ಣ ವಿವರಣೆ

9.1 switch ಎಂದರೇನು?

ಒಂದು Expression ನ ಮೌಲ್ಯವನ್ನು ಹಲವು ನಿಗದಿತ ಮೌಲ್ಯಗಳೊಂದಿಗೆ ಹೋಲಿಸಿ, ಹೊಂದಾಣಿಕೆಯ Block ಅನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸಲು switch ಬಳಸಬಹುದು.

ಉದಾಹರಣೆಗೆ ದಿನದ ಸಂಖ್ಯೆಗೆ ತಕ್ಕಂತೆ ದಿನದ ಹೆಸರನ್ನು ತೋರಿಸೋಣ.

let day = 2;

switch (day) {
  case 1:
    console.log("Monday");
    break;

  case 2:
    console.log("Tuesday");
    break;

  case 3:
    console.log("Wednesday");
    break;

  default:
    console.log("Invalid day");
}

Output:

Tuesday

ಮುಖ್ಯ Keywords

Keyword    ಕೆಲಸ                                         
switch  ಪರಿಶೀಲಿಸಬೇಕಾದ Expression ಅನ್ನು ಒದಗಿಸುತ್ತದೆ   
case    ಹೊಂದಾಣಿಕೆಗಾಗಿ ಮೌಲ್ಯ ನೀಡುತ್ತದೆ               
break    switch ನಿಂದ ಹೊರಬರುತ್ತದೆ                   
default ಯಾವುದೇ case ಹೊಂದಾಣಿಕೆಯಾಗದಿದ್ದಾಗ ನಡೆಯುತ್ತದೆ

9.2 break ಏಕೆ ಮುಖ್ಯ?

let day = 2;

switch (day) {
  case 1:
    console.log("Monday");

  case 2:
    console.log("Tuesday");

  case 3:
    console.log("Wednesday");

  default:
    console.log("Other");
}

Output:

Tuesday
Wednesday
Other

ಇಲ್ಲಿ case 2 ಹೊಂದಿಕೆಯಾದ ನಂತರ break ಇಲ್ಲದ ಕಾರಣ JavaScript ಮುಂದಿನ Statements ಗಳನ್ನೂ ಕಾರ್ಯಗತಗೊಳಿಸುತ್ತದೆ. ಇದನ್ನು Fall-through ಎನ್ನುತ್ತಾರೆ.

Fall-through ಅನ್ನು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಬಳಸುವ ಸಂದರ್ಭಗಳಿವೆ. ಆದರೆ ಸಾಮಾನ್ಯವಾಗಿ ಅನಗತ್ಯ Fall-through ತಪ್ಪಿಸಲು break ಸೇರಿಸುವುದು ಉತ್ತಮ.

9.3 switch Strict Equality ಬಳಸುತ್ತದೆ

let value = "2";

switch (value) {
  case 2:
    console.log("Number");
    break;

  case "2":
    console.log("String");
    break;
}

Output:

String

switch ನ case ಹೊಂದಾಣಿಕೆ === ನಿಯಮಕ್ಕೆ ಅನುಗುಣವಾಗಿರುತ್ತದೆ. ಆದ್ದರಿಂದ Number 2 ಮತ್ತು String "2" ಬೇರೆ.

9.4 switch ಯಾವಾಗ ಮತ್ತು if...else ಯಾವಾಗ?

switch ಅನ್ನು ಕೆಲವು ನಿಗದಿತ ಮೌಲ್ಯಗಳ ಆಧಾರದ ಮೇಲೆ ಆಯ್ಕೆ ಮಾಡಲು ಬಳಸುವುದು ಅನುಕೂಲಕರ.

switch (status) {
  case "success":
    console.log("Completed");
    break;

  case "pending":
    console.log("Waiting");
    break;

  case "failed":
    console.log("Failed");
    break;

  default:
    console.log("Unknown status");
}

ಆದರೆ ಮೌಲ್ಯಗಳ ವ್ಯಾಪ್ತಿ ಪರಿಶೀಲಿಸಬೇಕಾದರೆ if...else if ಹೆಚ್ಚು ಸಹಜ.

if (marks >= 90) {
  console.log("A+");
} else if (marks >= 80) {
  console.log("A");
} else {
  console.log("Other grade");
}

ಇವುಗಳಲ್ಲಿ ಯಾವುದೂ ಪ್ರತಿಯೊಂದು ಸಂದರ್ಭದಲ್ಲೂ ಉತ್ತಮ ಎಂದು ಹೇಳಲಾಗುವುದಿಲ್ಲ. ಸಮಸ್ಯೆಯ ಸ್ವರೂಪಕ್ಕೆ ಅನುಗುಣವಾಗಿ ಆಯ್ಕೆ ಮಾಡಬೇಕು.

ಭಾಗ 10: Ternary Operator (? :)

10.1 Ternary ಎಂದರೇನು?

ಒಂದು Condition ನ ಆಧಾರದ ಮೇಲೆ ಎರಡು Expressions ಗಳಲ್ಲಿ ಒಂದನ್ನು ಆಯ್ಕೆ ಮಾಡುವ Conditional Operator ಅನ್ನು Ternary Operator ಎನ್ನುತ್ತಾರೆ.

Syntax:

condition ? valueIfTrue : valueIfFalse

ಉದಾಹರಣೆ:

let age = 20;

let result = age >= 18 ? "Adult" : "Minor";

console.log(result);

Output:

Adult

ಇದು ಹೀಗೆ ಅರ್ಥ:

  • age >= 18 ಸತ್ಯವಾದರೆ "Adult" ಆಯ್ಕೆ.
  • ಇಲ್ಲದಿದ್ದರೆ "Minor" ಆಯ್ಕೆ.

10.2 ಇದೇ ಕೆಲಸವನ್ನು if...else ಮೂಲಕ

let age = 20;
let result;

if (age >= 18) {
  result = "Adult";
} else {
  result = "Minor";
}

console.log(result);

ಎರಡೂ ವಿಧಾನಗಳು ಒಂದೇ ಫಲಿತಾಂಶ ನೀಡುತ್ತವೆ.

ಯಾವಾಗ Ternary ಬಳಸಬೇಕು?

ಸರಳವಾದ Conditional Value ಆಯ್ಕೆಮಾಡುವಾಗ:

let isLoggedIn = true;

let message = isLoggedIn ? "Welcome" : "Please log in";

ಆದರೆ ಅನೇಕ ಹಂತದ Condition ಗಳನ್ನು ಒಂದೇ ಸಾಲಿನಲ್ಲಿ Nested Ternary ಆಗಿ ಬರೆಯುವುದರಿಂದ ಕೋಡ್ ಓದಲು ಕಷ್ಟವಾಗಬಹುದು. ಅಂತಹ ಸಂದರ್ಭಗಳಲ್ಲಿ if...else if...else ಬಳಸುವುದು ಉತ್ತಮ.

ಭಾಗ 11: Short-Circuit Evaluation — Professional Concept

ಇದು JavaScript ಕಲಿಯುವಾಗ ಅತ್ಯಂತ ಉಪಯುಕ್ತವಾದ ವಿಷಯ.

&& ಮತ್ತು || ಕೇವಲ true ಅಥವಾ false ಮಾತ್ರ ಹಿಂತಿರುಗಿಸುವುದಿಲ್ಲ. ಅವುಗಳ ಫಲಿತಾಂಶವನ್ನು ನಿರ್ಧರಿಸಲು ಬಳಸುವ ನಿಜವಾದ Operand Value ಯನ್ನೂ ಹಿಂತಿರುಗಿಸಬಹುದು.

11.1 AND (&&) Short-Circuit

console.log(false && "Hello"); // false
console.log(true && "Hello");  // "Hello"

&& ಎಡಭಾಗವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಎಡಭಾಗ Falsy ಆಗಿದ್ದರೆ, ಅದೇ ಮೌಲ್ಯವನ್ನು ಹಿಂತಿರುಗಿಸಿ ಬಲಭಾಗವನ್ನು ಪರಿಶೀಲಿಸುವುದಿಲ್ಲ. ಎಡಭಾಗ Truthy ಆಗಿದ್ದರೆ ಬಲಭಾಗಕ್ಕೆ ಮುಂದುವರಿಯುತ್ತದೆ.

ಉದಾಹರಣೆ:

let username = "";

let result = username && username.toUpperCase();

console.log(result); // ""

username ಖಾಲಿ String ಆಗಿದೆ. ಆದ್ದರಿಂದ username.toUpperCase() ಕಾರ್ಯಗತಗೊಳ್ಳುವುದಿಲ್ಲ.

ಇದರಿಂದ ಕೆಲವು ಷರತ್ತುಗಳ ಆಧಾರದ ಮೇಲೆ ಮುಂದಿನ Expression ಅನ್ನು ಕಾರ್ಯಗತಗೊಳಿಸುವುದು ಸಾಧ್ಯ.

11.2 OR (||) Short-Circuit

console.log("Hello" || "Guest"); // "Hello"
console.log("" || "Guest");      // "Guest"

|| ಎಡಭಾಗ Truthy ಆಗಿದ್ದರೆ ಅದನ್ನೇ ಹಿಂತಿರುಗಿಸುತ್ತದೆ. ಇಲ್ಲದಿದ್ದರೆ ಬಲಭಾಗವನ್ನು ಪರಿಶೀಲಿಸುತ್ತದೆ.

ಇದನ್ನು Default Value ಆಯ್ಕೆ ಮಾಡಲು ಬಳಸಬಹುದು.

let username = "";

let displayName = username || "Guest";

console.log(displayName); // "Guest"

ಆದರೆ || ಶೂನ್ಯ, false ಮತ್ತು ಖಾಲಿ String ಮುಂತಾದ ಎಲ್ಲಾ Falsy Values ಗಳನ್ನೂ ಬದಲಾಯಿಸುತ್ತದೆ. ನಿಮಗೆ ಕೇವಲ null ಅಥವಾ undefined ಇದ್ದಾಗ ಮಾತ್ರ Default Value ಬೇಕಾಗಿದ್ದರೆ ?? ಉತ್ತಮ ಆಯ್ಕೆಯಾಗಬಹುದು.

ಭಾಗ 12: Modern JavaScript — Nullish Coalescing (??)

?? ಅನ್ನು Nullish Coalescing Operator ಎನ್ನುತ್ತಾರೆ.

ಎಡಭಾಗದ ಮೌಲ್ಯ null ಅಥವಾ undefined ಆಗಿದ್ದರೆ ಬಲಭಾಗದ Default Value ಅನ್ನು ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ. ಇಲ್ಲದಿದ್ದರೆ ಎಡಭಾಗದ ಮೌಲ್ಯವನ್ನೇ ಉಳಿಸುತ್ತದೆ.

let username = null;

let result = username ?? "Guest";

console.log(result); // "Guest"

ಆದರೆ:

let count = 0;

console.log(count || 10); // 10
console.log(count ?? 10); // 0

ಏಕೆ?

  • 0 Falsy ಆಗಿದೆ; ಆದ್ದರಿಂದ || ಬಲಭಾಗದ 10 ಅನ್ನು ಆಯ್ಕೆಮಾಡುತ್ತದೆ.
  • 0 null ಅಥವಾ undefined ಅಲ್ಲ; ಆದ್ದರಿಂದ ?? 0 ಅನ್ನು ಉಳಿಸುತ್ತದೆ.

ಇನ್ನೊಂದು ಉದಾಹರಣೆ:

let isAvailable = false;

console.log(isAvailable || true); // true
console.log(isAvailable ?? true); // false

ಇಲ್ಲಿ false ಒಂದು ನೈಜ Boolean ಮೌಲ್ಯ. ಅದನ್ನು ಉಳಿಸಬೇಕಾದರೆ ?? ಸಹಾಯ ಮಾಡುತ್ತದೆ.

Professional ನಿಯಮ: || ಮತ್ತು ?? ಎರಡೂ Default Value ಗಳನ್ನು ಆಯ್ಕೆ ಮಾಡಲು ಉಪಯುಕ್ತ. ಆದರೆ ಅವುಗಳ ಅರ್ಥ ಬೇರೆ. ನಿಮ್ಮ Data ಯಲ್ಲಿ 0, false, "" ಇವು ಮಾನ್ಯ ಮೌಲ್ಯಗಳಾಗಿದ್ದರೆ ?? ಅನಗತ್ಯವಾಗಿ ಅವುಗಳನ್ನು ಬದಲಿಸುವುದಿಲ್ಲ.

ಭಾಗ 13: Optional Chaining (?.) ಮತ್ತು Conditions

Optional Chaining ಆಧುನಿಕ JavaScript ನಲ್ಲಿ Nested Object ಗಳಲ್ಲಿ Property ಲಭ್ಯವಿದೆಯೇ ಎಂಬುದನ್ನು ಸುರಕ್ಷಿತವಾಗಿ ಪ್ರವೇಶಿಸಲು ಉಪಯುಕ್ತ.

ಉದಾಹರಣೆ:

let user = {
  profile: {
    name: "Ravi"
  }
};

console.log(user.profile?.name); // "Ravi"
console.log(user.address?.city); // undefined

user.address ಇಲ್ಲದಿದ್ದರೂ user.address?.city Expression ದೋಷವಿಲ್ಲದೆ undefined ನೀಡುತ್ತದೆ.

Optional Chaining ಅನ್ನು Condition ಗಳೊಂದಿಗೆ ಬಳಸಬಹುದು:

let user = null;

if (user?.profile) {
  console.log("Profile available");
} else {
  console.log("Profile not available");
}

Output:

Profile not available

ಮುಖ್ಯ ವ್ಯತ್ಯಾಸ: ?. ಯಾವುದನ್ನೂ ಸ್ವತಃ true ಎಂದು ಸಾಬೀತುಪಡಿಸುವುದಿಲ್ಲ. ಅದು null ಅಥವಾ undefined ಬಂದಾಗ Property ಪ್ರವೇಶಿಸುವುದರಿಂದ ಉಂಟಾಗುವ ದೋಷವನ್ನು ತಪ್ಪಿಸುತ್ತದೆ. ಅದರ Expression ಫಲಿತಾಂಶವನ್ನು if ಪರಿಶೀಲಿಸುತ್ತದೆ.

ಉದಾಹರಣೆಗೆ, user.profile ಇದ್ದರೆ ಮಾತ್ರ ಕೋಡ್ ಕಾರ್ಯನಿರ್ವಹಿಸಬೇಕು ಎಂದಾದರೆ if (user?.profile) ಉಪಯುಕ್ತ. ಆದರೆ profile ಇದ್ದರೂ ಅದರ ಮೌಲ್ಯ 0 ಅಥವಾ "" ಆಗಿರಬಹುದಾದ ಸಂದರ್ಭಗಳಲ್ಲಿ Truthiness ಪರಿಶೀಲಿಸುವುದು ಸಾಕೇ ಎಂಬುದನ್ನು ನಿಮ್ಮ ಅಗತ್ಯಕ್ಕೆ ಅನುಗುಣವಾಗಿ ನಿರ್ಧರಿಸಿ.

ಭಾಗ 14: in ಮತ್ತು instanceof Operators

ಈ ಎರಡು Operators ಗಳನ್ನು Basic Comparison ಪಟ್ಟಿಯಲ್ಲಿ ಹೆಚ್ಚಾಗಿ ಸೇರಿಸದಿದ್ದರೂ, Advanced JavaScript ನಲ್ಲಿ ಬಹಳ ಉಪಯುಕ್ತ.

14.1 in Operator

ಒಂದು Property Object ನಲ್ಲಿ ಲಭ್ಯವಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಇದು Object ನ ಸ್ವಂತ Property ಗಳನ್ನಷ್ಟೇ ಅಲ್ಲದೆ Prototype ನಿಂದ ಬಂದ Property ಗಳನ್ನೂ ಪರಿಶೀಲಿಸುತ್ತದೆ.

let student = {
  name: "Ravi",
  age: 20
};

console.log("name" in student);  // true
console.log("marks" in student); // false

in ನ ಎಡಭಾಗದಲ್ಲಿ ಸಾಮಾನ್ಯವಾಗಿ Property Name String ಅಥವಾ Symbol ಇರಬೇಕು.

ನಿಮಗೆ Object ನ ಸ್ವಂತ Property ಮಾತ್ರ ಪರಿಶೀಲಿಸಬೇಕಿದ್ದರೆ:

console.log(Object.hasOwn(student, "name"));  // true
console.log(Object.hasOwn(student, "marks")); // false

Object.hasOwn() ಮೂಲಕ Prototype Properties ಗಳನ್ನು ಸ್ವಂತ Properties ಎಂದು ತಪ್ಪಾಗಿ ಗುರುತಿಸುವುದನ್ನು ತಪ್ಪಿಸಬಹುದು.

14.2 instanceof Operator

ಒಂದು Object ನಿರ್ದಿಷ್ಟ Constructor ನ Prototype Chain ಗೆ ಸಂಬಂಧಿಸಿದೆಯೇ ಎಂಬುದನ್ನು ಪರಿಶೀಲಿಸಲು ಬಳಸುತ್ತಾರೆ.

let numbers = [10, 20, 30];

console.log(numbers instanceof Array);  // true
console.log(numbers instanceof Object); // true

Array ಕೂಡ Object ಆಗಿರುವುದರಿಂದ ಎರಡೂ ಫಲಿತಾಂಶಗಳು true.

ಇನ್ನೊಂದು ಉದಾಹರಣೆ:

let message = new Date();

console.log(message instanceof Date); // true
console.log(message instanceof Array); // false

instanceof ಎಲ್ಲಾ ಸಂದರ್ಭಗಳಲ್ಲೂ ನಿಖರ Type ಪರೀಕ್ಷೆಯಾಗುವುದಿಲ್ಲ; ವಿಶೇಷವಾಗಿ ವಿಭಿನ್ನ JavaScript Realms ಗಳಿಂದ ಬಂದ Objects ಗಳಲ್ಲಿ ಇದರ ಫಲಿತಾಂಶ ನಿರೀಕ್ಷಿತ ರೀತಿಯಲ್ಲಿ ಇರದೇ ಇರಬಹುದು.

Array ಗುರುತಿಸಲು Array.isArray() ಹೆಚ್ಚು ನೇರವಾದ ವಿಧಾನ:

console.log(Array.isArray([1, 2])); // true
console.log(Array.isArray({}));     // false

ಭಾಗ 15: Operator Precedence ಮತ್ತು Parentheses

ಒಂದು Expression ನಲ್ಲಿ ಅನೇಕ Operators ಇದ್ದರೆ ಅವು ಯಾವ ಕ್ರಮದಲ್ಲಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತವೆ ಎಂಬುದನ್ನು Operator Precedence ಎನ್ನುತ್ತಾರೆ.

ಉದಾಹರಣೆ:

console.log(5 > 3 && 10 < 20);

ಈ Expression ನಲ್ಲಿ ಮೊದಲು Comparison ಗಳು ನಡೆಯುತ್ತವೆ:

  • 5 > 3 → true.
  • 10 < 20 → true.
  • ನಂತರ true && true → true.

15.1 Parentheses ಬಳಸಿ ಸ್ಪಷ್ಟಗೊಳಿಸುವುದು

let age = 20;
let hasID = true;

if ((age >= 18) && (hasID === true)) {
  console.log("Access granted");
}

Parentheses ಗಳಿಂದ Expression ಗಳನ್ನು ಓದಲು ಸುಲಭವಾಗುತ್ತದೆ. ಯಾವ ಭಾಗವನ್ನು ಮೊದಲು ಅರ್ಥಮಾಡಿಕೊಳ್ಳಬೇಕು ಎಂಬುದು ಸ್ಪಷ್ಟವಾಗುತ್ತದೆ.

ಮತ್ತೊಂದು ಉದಾಹರಣೆ:

console.log(true || false && false);

&& ಗೆ || ಗಿಂತ ಹೆಚ್ಚಿನ Precedence ಇದೆ. ಆದ್ದರಿಂದ:

true || (false && false)

ಮೊದಲು false && false → false; ನಂತರ true || false → true.

Parentheses ಬಳಸಿದರೆ:

console.log((true || false) && false); // false

ಈಗ ಫಲಿತಾಂಶ ಬದಲಾಗುತ್ತದೆ.

ಮಿಶ್ರ Logical Operators ಗಾಗಿ ನಿಯಮ

&& ಮತ್ತು || ಅನ್ನು ಒಟ್ಟಿಗೆ ಬಳಸುವಾಗ ನಿಮ್ಮ ಉದ್ದೇಶವನ್ನು ಸ್ಪಷ್ಟಪಡಿಸಲು Parentheses ಬಳಸುವುದು ಉತ್ತಮ ಅಭ್ಯಾಸ.

ಗಮನಿಸಿ: ?? ಅನ್ನು && ಅಥವಾ || ಜೊತೆ ನೇರವಾಗಿ ಮಿಶ್ರಣ ಮಾಡಿದರೆ Parentheses ಅಗತ್ಯವಾಗುವ Syntax ನಿಯಮಗಳಿವೆ.

let result = (null ?? "Guest") || "Default";
console.log(result); // "Guest"

ಇಂತಹ Expression ಗಳಲ್ಲಿ Parentheses ಬಳಸಿ ನಿಮ್ಮ ಉದ್ದೇಶವನ್ನು ಸ್ಪಷ್ಟವಾಗಿ ಸೂಚಿಸಿ.

ಭಾಗ 16: Professional Coding ನಲ್ಲಿ ತಪ್ಪಿಸಬೇಕಾದ ಪ್ರಮುಖ ತಪ್ಪುಗಳು

16.1 = ಮತ್ತು === ನಡುವಿನ ಗೊಂದಲ

ಈ ಎರಡೂ Operators ಒಂದೇ ಕೆಲಸ ಮಾಡುವುದಿಲ್ಲ.

let age = 18;

ಇಲ್ಲಿ = ಮೌಲ್ಯವನ್ನು ನಿಯೋಜಿಸುತ್ತದೆ.

console.log(age === 18);

ಇಲ್ಲಿ === ಹೋಲಿಸುತ್ತದೆ.

ಈ ತಪ್ಪನ್ನು ನೋಡಿ:

let age = 15;

if (age = 18) {
  console.log("Eligible");
}

Output:

Eligible

ಇಲ್ಲಿ age = 18 ಎಂಬುದು Comparison ಅಲ್ಲ; Assignment. ಇದು age ಗೆ 18 ನಿಯೋಜಿಸುತ್ತದೆ. 18 Truthy ಆಗಿರುವುದರಿಂದ if Block ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

ಸರಿಯಾದ ಕೋಡ್:

let age = 15;

if (age === 18) {
  console.log("Age is exactly 18");
}

ಇದರಲ್ಲಿ age ನ ಮೌಲ್ಯ ಬದಲಾಗುವುದಿಲ್ಲ. ಅದು ನಿಖರವಾಗಿ 18 ಆಗಿದೆಯೇ ಎಂದು ಮಾತ್ರ ಪರಿಶೀಲಿಸುತ್ತದೆ.

16.2 JavaScript ನಲ್ಲಿ Chained Comparisons ತಪ್ಪಾಗಿ ಬರೆಯುವುದು

ಗಣಿತದಲ್ಲಿ ಹೀಗೆ ಬರೆಯಬಹುದು:

\[ 1 < x < 18 \]

ಆದರೆ JavaScript ನಲ್ಲಿ ಅದೇ Expression ಅನ್ನು ನೇರವಾಗಿ ಬಳಸಬಾರದು.

let age = 10;

console.log(1 < age < 18); // true

ಇಲ್ಲಿ ಫಲಿತಾಂಶ true ಬಂದಿರುವುದರಿಂದ ಕೋಡ್ ಸರಿಯಾಗಿದೆ ಎಂದು ಕಾಣಬಹುದು. ಆದರೆ ಈ Expression ನ ಕಾರ್ಯನಿರ್ವಹಣಾ ಕ್ರಮ ಬೇರೆ.

JavaScript ಇದನ್ನು ಹೀಗೆ ಮೌಲ್ಯಮಾಪನ ಮಾಡುತ್ತದೆ:

(1 < age) < 18

ಮೊದಲ ಹೋಲಿಕೆ true ನೀಡುತ್ತದೆ. ನಂತರ true ಅನ್ನು Number ಆಗಿ ಪರಿಗಣಿಸಿದರೆ 1 ಸಿಗುತ್ತದೆ. ಹೀಗಾಗಿ 1 < 18 ಸತ್ಯವಾಗುತ್ತದೆ.

ಆದರೆ:

let age = 25;

console.log(1 < age < 18); // true

ಇದು ಕೂಡ true ನೀಡುತ್ತದೆ! 25 ವಯಸ್ಸು 18 ಕ್ಕಿಂತ ಕಡಿಮೆಯಿಲ್ಲದಿದ್ದರೂ ಫಲಿತಾಂಶ ಸತ್ಯವಾಗಿದೆ.

ಸರಿಯಾದ ವಿಧಾನ:

let age = 25;

console.log(age > 1 && age < 18); // false

JavaScript ನಲ್ಲಿ ಒಂದು ಸಂಖ್ಯೆಯು ಎರಡು ಮಿತಿಗಳ ನಡುವೆ ಇದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸಲು ಎರಡು Comparison ಗಳನ್ನು && ಮೂಲಕ ಜೋಡಿಸಬೇಕು.

16.3 Empty String ಮತ್ತು ಖಾಲಿ ಮೌಲ್ಯಗಳನ್ನು ತಪ್ಪಾಗಿ ಪರಿಶೀಲಿಸುವುದು

let username = " ";

if (username) {
  console.log("Username supplied");
}

Output:

Username supplied

String ನಲ್ಲಿ ಒಂದು Space ಇರುವುದರಿಂದ ಅದು Truthy. ಆದರೆ ಬಳಕೆದಾರರು ನಿಜವಾದ ಹೆಸರನ್ನು ನಮೂದಿಸಿದ್ದಾರೆ ಎಂದು ಇದರಿಂದ ಸಾಬೀತಾಗುವುದಿಲ್ಲ.

Form Input ನಲ್ಲಿ ಖಾಲಿ ಜಾಗಗಳನ್ನು ತೆಗೆದುಹಾಕಿ ಪರಿಶೀಲಿಸಬಹುದು:

let username = "   ";

if (username.trim() === "") {
  console.log("Enter a username");
}

Output:

Enter a username

trim() ಆರಂಭ ಮತ್ತು ಅಂತ್ಯದಲ್ಲಿರುವ White Space ಅನ್ನು ತೆಗೆದುಹಾಕುತ್ತದೆ. ನೈಜ Application ನಲ್ಲಿ Input ಅನ್ನು ಯಾವ ಮಟ್ಟಿಗೆ ಪರಿಶೀಲಿಸಬೇಕು ಎಂಬುದು ಅದರ ನಿಯಮಗಳ ಮೇಲೆ ಅವಲಂಬಿತವಾಗಿರುತ್ತದೆ.

16.4 Number Input ಅನ್ನು Validate ಮಾಡದೆ ಬಳಸುವುದು

let age = Number("hello");

console.log(age); // NaN

ಕೇವಲ Number() ಬಳಸುವುದರಿಂದ Input ಮಾನ್ಯ Number ಆಗುತ್ತದೆ ಎಂಬ ಖಾತರಿ ಇಲ್ಲ.

let age = Number("hello");

if (Number.isFinite(age) && age >= 18) {
  console.log("Eligible");
} else {
  console.log("Invalid age or not eligible");
}

ಇಲ್ಲಿ Number.isFinite(age) ಮಾನ್ಯ Finite Number ಆಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ. ಇದರಿಂದ NaN, Infinity ಮತ್ತು -Infinity ಅನ್ನು ತಿರಸ್ಕರಿಸಬಹುದು.

Input ಖಾಲಿಯಾಗಿರಬಹುದಾದ Form ನಲ್ಲಿ ಖಾಲಿ String ಅನ್ನು ಪ್ರತ್ಯೇಕವಾಗಿ Validate ಮಾಡುವುದು ಅಗತ್ಯ.

16.5 ಅತಿಯಾಗಿ Complex Conditions ಬರೆಯುವುದು

if (isLoggedIn && (isAdmin || hasPermission) && !isBlocked) {
  console.log("Access granted");
}

ಇಂತಹ ಕೋಡ್ ಸರಿಯಾಗಿದೆ. ಆದರೆ ತುಂಬಾ ದೀರ್ಘವಾದ Conditions ಇದ್ದಾಗ ಅವುಗಳನ್ನು ಸ್ಪಷ್ಟವಾದ Variable ಗಳಾಗಿ ವಿಭಜಿಸಬಹುದು.

let hasAccessLevel = isAdmin || hasPermission;
let canAccess = isLoggedIn && hasAccessLevel && !isBlocked;

if (canAccess) {
  console.log("Access granted");
}

ಇದರಿಂದ ಕೋಡ್ ಓದಲು, ಪರೀಕ್ಷಿಸಲು ಮತ್ತು Debug ಮಾಡಲು ಸುಲಭವಾಗುತ್ತದೆ.

ಭಾಗ 17: Real-World Project Example — Login Validation

ಈಗ Conditions ಮತ್ತು Comparison Operators ಅನ್ನು ಒಟ್ಟಿಗೆ ಬಳಸಿ ಸರಳ Login Validation Logic ನೋಡೋಣ.

ಇದು ಕಲಿಕೆಯ ಉದಾಹರಣೆ ಮಾತ್ರ; ನೈಜ Authentication ಗೆ ಇದು ಬದಲಿಯಾಗುವುದಿಲ್ಲ.

let username = "ravi";
let password = "abc12345";

let isUsernameValid = username.trim().length >= 3;
let isPasswordValid = password.length >= 8;

if (isUsernameValid && isPasswordValid) {
  console.log("Input validation successful");
} else if (!isUsernameValid && !isPasswordValid) {
  console.log("Username and password are invalid");
} else if (!isUsernameValid) {
  console.log("Username is invalid");
} else {
  console.log("Password is invalid");
}

Output:

Input validation successful

username.trim().length >= 3        Username ನಲ್ಲಿ ಕನಿಷ್ಠ 3 Characters ಇವೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ       
password.length >= 8                Password ನಲ್ಲಿ ಕನಿಷ್ಠ 8 Characters ಇವೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ       
isUsernameValid && isPasswordValid ಎರಡೂ Input Validation ನಿಯಮಗಳು ಪೂರೈಸಲ್ಪಟ್ಟಿವೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ
!isUsernameValid                    Username Validation ವಿಫಲವಾಗಿದೆಯೇ ಎಂದು ಪರಿಶೀಲಿಸುತ್ತದೆ               

ಗಮನಿಸಿ: ಕನಿಷ್ಠ Length ಪರಿಶೀಲಿಸುವುದರಿಂದ Password ಸುರಕ್ಷಿತವಾಗಿದೆ ಎಂದು ಸಾಬೀತಾಗುವುದಿಲ್ಲ. ನೈಜ Website ನಲ್ಲಿ Server-side Validation, ಸುರಕ್ಷಿತ Password Hashing, Authentication ಮತ್ತು Rate Limiting ಮುಂತಾದ ಕ್ರಮಗಳೂ ಅಗತ್ಯ.

ಉದಾಹರಣೆ 1: ವಯಸ್ಸಿನ ಆಧಾರದಲ್ಲಿ ಫಲಿತಾಂಶ

ನಿಯಮ ಶಿಫಾರಸು
Equality ಸಾಮಾನ್ಯವಾಗಿ === ಮತ್ತು !== ಬಳಸಿ
Input Validation Type ಮತ್ತು Input Range ಅನ್ನು ಪರಿಶೀಲಿಸಿ
Multiple Conditions ಅಗತ್ಯವಿದ್ದಲ್ಲಿ && / || ಬಳಸಿ
Complex Logic Parentheses ಮತ್ತು ಅರ್ಥಪೂರ್ಣ Variable Names ಬಳಸಿ
if Blocks ಸ್ಪಷ್ಟತೆಗಾಗಿ {} ಬಳಸಿ
Default Values Falsy Value ಗಳನ್ನೂ ಉಳಿಸಬೇಕಿದ್ದರೆ ?? ಪರಿಗಣಿಸಿ
Number Checking ಅಗತ್ಯಕ್ಕೆ ಅನುಗುಣವಾಗಿ Number.isFinite() ಮತ್ತು Number.isNaN() ಬಳಸಿ
Object Properties Property ಇರುವುದನ್ನು ತಿಳಿಯಲು in ಅಥವಾ Object.hasOwn() ಬಳಸಿ
Nested Conditions ಓದಲು ಕಷ್ಟವಾದರೆ ಸ್ಪಷ್ಟವಾದ Guard Clauses ಅಥವಾ ಬೇರೆ Variables ಬಳಸಿ
Debugging ಪ್ರತಿಯೊಂದು Condition ನ Intermediate Value ಗಳನ್ನು ಪರಿಶೀಲಿಸಿ

Guard Clause ಎಂದರೇನು?

ಒಂದು ಕಾರ್ಯದ ಆರಂಭದಲ್ಲಿಯೇ ತಪ್ಪಾದ ಅಥವಾ ಅನುಮತಿಸದ ಪರಿಸ್ಥಿತಿಗಳನ್ನು ಪರಿಶೀಲಿಸಿ, ಅವು ಪೂರೈಸದಿದ್ದರೆ Function ನಿಂದ ಬೇಗನೆ ಹೊರಬರುವ ವಿಧಾನವನ್ನು Guard Clause ಎನ್ನುತ್ತಾರೆ.

function processPayment(amount) {
  if (!Number.isFinite(amount)) {
    return "Invalid amount";
  }

  if (amount <= 0) {
    return "Amount must be positive";
  }

  return "Payment can be processed";
}

console.log(processPayment(500)); // Payment can be processed
console.log(processPayment(0));   // Amount must be positive

ಇದರಿಂದ ಎಲ್ಲ Conditions ಗಳನ್ನೂ ಒಳಹೊಕ್ಕು Nested Block ಗಳಾಗಿ ಬರೆಯುವ ಅಗತ್ಯ ಕಡಿಮೆಯಾಗುತ್ತದೆ.

ಭಾಗ 20: ಸ್ವಯಂ ಅಭ್ಯಾಸ — ಉತ್ತರಗಳೊಂದಿಗೆ

ಕೆಳಗಿನ ಪ್ರಶ್ನೆಗಳನ್ನು ಸ್ವತಃ ಯೋಚಿಸಿ ಉತ್ತರಿಸಿ. ನಂತರ ಕೊಟ್ಟಿರುವ ಉತ್ತರಗಳೊಂದಿಗೆ ಹೋಲಿಸಿ.

ಪ್ರಶ್ನೆ 1: Comparison

console.log(15 > 20);

ಉತ್ತರ: false

ಕಾರಣ: 15, 20 ಕ್ಕಿಂತ ದೊಡ್ಡದಲ್ಲ.

ಪ್ರಶ್ನೆ 2: Equality

console.log(10 == "10");
console.log(10 === "10");

ಉತ್ತರ:

true
false

ಕಾರಣ: == Type Conversion ನಿಯಮಗಳನ್ನು ಅನುಸರಿಸಬಹುದು. === ನಲ್ಲಿ Type ಮತ್ತು Value ಎರಡೂ ಹೊಂದಾಣಿಕೆಯಾಗಬೇಕು.

ಪ್ರಶ್ನೆ 3: Logical AND

console.log(5 > 2 && 10 < 5);

ಉತ್ತರ: false

ಕಾರಣ: ಮೊದಲ ಷರತ್ತು true, ಎರಡನೆಯದು false. AND ಗೆ ಎರಡೂ ಸತ್ಯವಾಗಿರಬೇಕು.

ಪ್ರಶ್ನೆ 4: Logical OR

console.log(false || true);

ಉತ್ತರ: true

ಕಾರಣ: ಕನಿಷ್ಠ ಒಂದು ಷರತ್ತು ಸತ್ಯವಾಗಿದೆ.

ಪ್ರಶ್ನೆ 5: Truthy ಮತ್ತು Falsy

console.log(Boolean("0"));
console.log(Boolean(0));
console.log(Boolean([]));

ಉತ್ತರ:

true
false
true

ಪ್ರಶ್ನೆ 6: if...else

let number = 12;

if (number % 2 === 0) {
  console.log("Even");
} else {
  console.log("Odd");
}

ಉತ್ತರ: Even

ಕಾರಣ: 12 ಅನ್ನು 2 ರಿಂದ ಭಾಗಿಸಿದಾಗ ಶೇಷ 0.

ಪ್ರಶ್ನೆ 7: NaN

console.log(NaN === NaN);
console.log(Number.isNaN(NaN));

ಉತ್ತರ:

false
true

ಪ್ರಶ್ನೆ 8: ?? ಮತ್ತು ||

console.log(0 || 100);
console.log(0 ?? 100);

ಉತ್ತರ:

100
0

ಕಾರಣ: || Falsy Value ಗಳನ್ನು Default Value ಯಿಂದ ಬದಲಾಯಿಸಬಹುದು. ?? ಕೇವಲ null ಮತ್ತು undefined ಗಳಿಗೆ Default Value ಬಳಸುತ್ತದೆ.

1

Condition

Comparison

AND

OR

NOT

Falsy

`false`, `0`, `-0`, `0n`, `““`, `null`, `undefined`, `NaN`.

Ternary

9

Nullish Coalescing

`??` — `null` ಅಥವಾ `undefined` ಬಂದಾಗ ಮಾತ್ರ Default Value ಆಯ್ಕೆ ಮಾಡುತ್ತದೆ.

Validation
