ಸಂಪೂರ್ಣ ಮಾರ್ಗದರ್ಶಿ (Complete Guide)

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ `async` ಮತ್ತು `await`

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಸರ್ವರ್‌ನಿಂದ ಡೇಟಾ ತರುವುದು ಅಥವಾ ಫೈಲ್ ಸೇವ್ ಮಾಡುವುದು ಮುಂತಾದ ಕೆಲಸಗಳಿಗೆ ಸ್ವಲ್ಪ ಸಮಯ ಬೇಕಾಗುತ್ತದೆ. ಇಂತಹ ಸಮಯದಲ್ಲಿ ಇಡೀ ವೆಬ್‌ಸೈಟ್ ಹ್ಯಾಂಗ್ ಆಗದಂತೆ (ಗಾಬರಿಯಾಗದಂತೆ) ತಡೆಯಲು ಹಾಗೂ ಕೆಲಸ ಪೂರ್ಣಗೊಳ್ಳುವವರೆಗೆ ಕಾಯುವ ಪ್ರಕ್ರಿಯೆಯನ್ನು ಅಚ್ಚುಕಟ್ಟಾಗಿ ನಿರ್ವಹಿಸಲು async ಮತ್ತು await ಅನ್ನು ಬಳಸಲಾಗುತ್ತದೆ.

1 ಹಂತ 1: ದೈನಂದಿನ ಉದಾಹರಣೆ (Synchronous vs Asynchronous)

ಇದನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಹೋಟೆಲ್‌ನಲ್ಲಿ ಮಸಾಲೆ ದೋಸೆ ಆರ್ಡರ್ ಮಾಡುವ ಉದಾಹರಣೆ ನೋಡೋಣ:

ಸಾಮಾನ್ಯ ವಿಧಾನ (Synchronous / Blocking)

ನೀವು ಕೌಂಟರ್‌ನಲ್ಲಿ ಆರ್ಡರ್ ಮಾಡಿ, ದೋಸೆ ಬರುವವರೆಗೂ ಅಲ್ಲಿಯೇ ನಿಂತಿರುತ್ತೀರಿ. ದೋಸೆ ಕೈಗೆ ಸಿಗುವವರೆಗೂ ನೀವು ಬೇರೆ ಯಾವ ಕೆಲಸವೂ ಮಾಡುವಂತಿಲ್ಲ. ಇದು ನಿಮ್ಮ ಸಮಯವನ್ನು ತಡೆಯುತ್ತದೆ.

ಅಸಿಂಕ್ರೋನಸ್ (Asynchronous / Non-blocking)

ನೀವು ಆರ್ಡರ್ ಮಾಡಿದಾಗ ಅವರು ನಿಮಗೆ ಒಂದು ಟೋಕನ್ ಕೊಡುತ್ತಾರೆ. ನೀವು ಹೋಗಿ ಸೀಟಿನಲ್ಲಿ ಕುಳಿತು ಸ್ನೇಹಿತರೊಂದಿಗೆ ಮಾತನಾಡಬಹುದು. ದೋಸೆ ರೆಡಿಯಾದಾಗ ಟೋಕನ್ ಕರೆಯುತ್ತಾರೆ, ಆಗ ಹೋಗಿ ತರುತ್ತೀರಿ. ಇಲ್ಲಿ ನೀವು ಕಾಯುವ ಸಮಯದಲ್ಲಿ ಬೇರೆ ಕೆಲಸ ಮಾಡಬಹುದು. async/await ಕೆಲಸ ಮಾಡುವುದು ಇದೇ ರೀತಿ!

2 ಹಂತ 2: ಪ್ರಮುಖ ಪದಗಳ ಅರ್ಥ ಮತ್ತು ನಿಯಮಗಳು

  • `async` (ಅಸಿಂಕ್): ಯಾವುದೇ ಫಂಕ್ಷನ್‌ನ ಮುಂದೆ async ಎಂದು ಬರೆದರೆ, ಆ ಫಂಕ್ಷನ್ ಒಳಗೆ ಸಮಯ ತೆಗೆದುಕೊಳ್ಳುವ ಕೆಲಸ ಇದೆ ಎಂದು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ಗೆ ತಿಳಿಸಿದಂತೆ.
  • (ಹೊಸ ಮಾಹಿತಿ ಸೇರ್ಪಡೆ)
    ನೆನಪಿಡಿ: ನೀವು ಒಂದು ಫಂಕ್ಷನ್ ಹಿಂದೆ async ಹಾಕಿದರೆ, ಆ ಫಂಕ್ಷನ್ ಯಾವಾಗಲೂ ಒಂದು Promise ಅನ್ನೇ ಹಿಂತಿರುಗಿಸುತ್ತದೆ (Return ಮಾಡುತ್ತದೆ).
  • `await` (ಅವೇಟ್): ಇದರ ಅರ್ಥ "ಈ ನಿರ್ದಿಷ್ಟ ಕೆಲಸ ಮುಗಿಯುವವರೆಗೂ ಇಲ್ಲಿಯೇ ಕಾಯು".
  • ನಿಯಮ: await ಅನ್ನು ಕೇವಲ async ಫಂಕ್ಷನ್‌ನ ಒಳಗೆ ಮಾತ್ರ ಬಳಸಲು ಸಾಧ್ಯ. ಹೊರಗಡೆ ಬಳಸಿದರೆ ಎರರ್ ಬರುತ್ತದೆ. (ಆದರೆ ಆಧುನಿಕ JS ನಲ್ಲಿ Top-level await ಬಂದಿದೆ, ಅದನ್ನು ಕೊನೆಯಲ್ಲಿ ವಿವರಿಸಲಾಗಿದೆ).

3 ಹಂತ 3: ಮೂಲ ಸಿಂಟ್ಯಾಕ್ಸ್ (Basic Syntax)

ಇದನ್ನು ಬರೆಯಲು ಮುಖ್ಯವಾಗಿ ಎರಡು ವಿಧಾನಗಳಿವೆ:

ವಿಧಾನ 1: ಸಾಮಾನ್ಯ ಫಂಕ್ಷನ್ (Regular Function)

async function functionName() {
    let result = await somePromiseFunction();
    console.log(result);
}

📌 ಕೋಡ್‌ನ ಹಂತ-ಹಂತದ ವಿವರಣೆ:

  • async function functionName() { : ಇದು ಒಂದು ಸಾಮಾನ್ಯ ಫಂಕ್ಷನ್, ಆದರೆ `async` ಕೀವರ್ಡ್ ಬಳಸಿರುವುದರಿಂದ ಇದರೊಳಗೆ ನಾವು ಕಾಯುವ (`await`) ಕೆಲಸ ಮಾಡಬಹುದು.
  • let result = await somePromiseFunction(); : `somePromiseFunction()` ಎಂಬುದು ಸಮಯ ತೆಗೆದುಕೊಳ್ಳುವ ಕೆಲಸ. `await` ಇರುವುದರಿಂದ ಆ ಕೆಲಸ ಮುಗಿದು ಡೇಟಾ ಬರುವವರೆಗೂ ಕೋಡ್ ಇಲ್ಲಿಯೇ ಕಾಯುತ್ತದೆ. ಬಂದ ಡೇಟಾ `result` ಎಂಬ ವೇರಿಯೇಬಲ್ ಒಳಗೆ ಸೇವ್ ಆಗುತ್ತದೆ.
  • console.log(result); : ಬಂದ ಡೇಟಾವನ್ನು ಸ್ಕ್ರೀನ್ ಮೇಲೆ (ಕನ್ಸೋಲ್‌ನಲ್ಲಿ) ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ.

ವಿಧಾನ 2: ಆ್ಯರೋ ಫಂಕ್ಷನ್ (Arrow Function - ಆಧುನಿಕ ವಿಧಾನ)

const functionName = async () => {
    let result = await somePromiseFunction();
    console.log(result);
}

📌 ಕೋಡ್‌ನ ಹಂತ-ಹಂತದ ವಿವರಣೆ:

  • const functionName = async () => { : ಇದು ಆಧುನಿಕ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ (ES6) ಬರವಣಿಗೆ. ಫಂಕ್ಷನ್ ಹೆಸರನ್ನು ಒಂದು ವೇರಿಯೇಬಲ್‌ನಂತೆ ಬರೆದು, `()` ಚಿಹ್ನೆಗೂ ಮುನ್ನ `async` ಸೇರಿಸಲಾಗಿದೆ. ಒಳಗಿನ ಕೆಲಸ ವಿಧಾನ 1 ರಂತೆಯೇ ಇರುತ್ತದೆ.

4 ಹಂತ 4: `await` ಬಳಸುವ ಮುನ್ನ ಮಾಡಬೇಕಾದ ಸಿದ್ಧತೆ (Prerequisites)

await ಬಳಸುವ ಮುನ್ನ ಅತಿ ಮುಖ್ಯವಾದ ಅಂಶವೆಂದರೆ: ನೀವು ಯಾವ ಕೆಲಸಕ್ಕಾಗಿ ಕಾಯುತ್ತಿದ್ದೀರೋ, ಆ ಕೆಲಸವು ಕಡ್ಡಾಯವಾಗಿ ಒಂದು "Promise" ಆಗಿರಬೇಕು. ಸಾಮಾನ್ಯ ಡೇಟಾಗೆ (ಉದಾ: ಸ್ಟ್ರಿಂಗ್, ನಂಬರ್) `await` ಹಾಕಿದರೆ ಅದು ಕಾಯುವುದಿಲ್ಲ.

ತಪ್ಪಾದ ವಿಧಾನ: 

async function test() {
    let data = await "ಹಲೋ"; // ಇದು Promise ಅಲ್ಲ, ಹಾಗಾಗಿ ಇಲ್ಲಿ ಸಮಯ ಕಾಯುವುದಿಲ್ಲ!
    console.log(data);
}

📌 ಕೋಡ್‌ನ ಹಂತ-ಹಂತದ ವಿವರಣೆ:

ಇಲ್ಲಿ `await` ನ ಪಕ್ಕದಲ್ಲಿ ಕೇವಲ `"ಹಲೋ"` ಎಂಬ ಸ್ಟ್ರಿಂಗ್ (ಪದ) ಇದೆ. ಇದು Promise ಅಲ್ಲದ ಕಾರಣ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಒಂದು ಮಿಲಿಸೆಕೆಂಡ್ ಕೂಡ ಕಾಯುವುದಿಲ್ಲ, ನೇರವಾಗಿ ಪ್ರಿಂಟ್ ಮಾಡಿಬಿಡುತ್ತದೆ. ಇದು `await` ನ ತಪ್ಪು ಬಳಕೆ.

ಸರಿಯಾದ ವಿಧಾನ (Promise ರಚಿಸುವುದು):

ಸಮಯ ತೆಗೆದುಕೊಳ್ಳುವ ಕೆಲಸವನ್ನು Promise ಆಗಿ ಪರಿವರ್ತಿಸಬೇಕು.

// 1. ಸಮಯ ತೆಗೆದುಕೊಳ್ಳುವ ಕೆಲಸ (Promise)
function getDataFromServer() {
    return new Promise((resolve, reject) => {
        setTimeout(() => resolve("ಡೇಟಾ ಯಶಸ್ವಿಯಾಗಿ ಬಂದಿದೆ!"), 2000);
    });
}

// 2. ಆ Promise ಅನ್ನು async/await ಒಳಗೆ ಕರೆಯುವುದು
async function showData() {
    console.log("ಡೇಟಾ ತರುತ್ತಿದ್ದೇನೆ...");
    let result = await getDataFromServer(); // ಸರಿಯಾಗಿ 2 ಸೆಕೆಂಡ್ ಕಾಯುತ್ತದೆ
    console.log(result);
}

📌 ಕೋಡ್‌ನ ಹಂತ-ಹಂತದ ವಿವರಣೆ:

  • return new Promise(...) : ಇದೊಂದು ಭರವಸೆ (Promise). ಕೆಲಸ ಮುಗಿದಾಗ `resolve` ಮೂಲಕ ಉತ್ತರ ಕೊಡುತ್ತೇನೆ ಎಂದು ಹೇಳುತ್ತದೆ.
  • setTimeout(...) : ಇದು ಕೃತಕವಾಗಿ 2 ಸೆಕೆಂಡ್ (2000ms) ವಿಳಂಬ ಮಾಡುತ್ತದೆ (ಸರ್ವರ್‌ನಿಂದ ಡೇಟಾ ಬರಲು ಸಮಯ ತಗಲುವಂತೆ). 2 ಸೆಕೆಂಡ್ ನಂತರ `"ಡೇಟಾ ಯಶಸ್ವಿಯಾಗಿ ಬಂದಿದೆ!"` ಎಂಬುದನ್ನು ಕಳುಹಿಸುತ್ತದೆ.
  • console.log("ಡೇಟಾ ತರುತ್ತಿದ್ದೇನೆ..."); : ಇದು ಮೊದಲು ಪ್ರಿಂಟ್ ಆಗುತ್ತದೆ.
  • let result = await getDataFromServer(); : ಇಲ್ಲಿಗೆ ಬಂದಾಗ ಪ್ರೋಗ್ರಾಮ್ ನಿಖರವಾಗಿ 2 ಸೆಕೆಂಡ್ ಕಾಯುತ್ತದೆ. ಏಕೆಂದರೆ `getDataFromServer` ಒಂದು Promise ಆಗಿದೆ.
  • console.log(result); : 2 ಸೆಕೆಂಡ್ ನಂತರ ಬಂದ ಡೇಟಾವನ್ನು ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ.

5 ಹಂತ 5: ಹಿನ್ನೆಲೆಯಲ್ಲಿ ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ? (Behind the Scenes)

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ "ಸಿಂಗಲ್ ಥ್ರೆಡ್" (Single-threaded) ಭಾಷೆ. ಅದಕ್ಕೆ ಏಕಕಾಲದಲ್ಲಿ ಒಂದೇ ಕೆಲಸ ಮಾಡಲು ಸಾಧ್ಯ. ಆದರೂ ಇದು ಮಲ್ಟಿ-ಟಾಸ್ಕಿಂಗ್‌ನಂತೆ ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ?

1

ಪ್ರಾರಂಭ:

`async` ಫಂಕ್ಷನ್ ಕರೆದಾಗ, ಸಾಲಿನಿಂದ ಸಾಲಿಗೆ ಕೋಡ್ ಓದಲು ಶುರುವಾಗುತ್ತದೆ.

2

ತಾತ್ಕಾಲಿಕ ತಡೆ (Pause):

ಕೋಡ್‌ನಲ್ಲಿ `await` ಎದುರಾದಾಗ, ಆ ಫಂಕ್ಷನ್ ಅನ್ನು ಅಲ್ಲಿಗೇ ತಾತ್ಕಾಲಿಕವಾಗಿ ತಡೆಹಿಡಿಯಲಾಗುತ್ತದೆ.

3

ಹಿನ್ನೆಲೆಗೆ ವರ್ಗಾವಣೆ:

`await` ಮುಂದಿರುವ ಕೆಲಸವನ್ನು (ಉದಾ: ಇಂಟರ್ನೆಟ್‌ನಿಂದ ಡೇಟಾ ತರುವುದು) ಬ್ರೌಸರ್‌ನ ಹಿನ್ನೆಲೆಗೆ (Web APIs) ಒಪ್ಪಿಸಲಾಗುತ್ತದೆ.

4

ಬೇರೆ ಕೆಲಸ ಮುಂದುವರಿಕೆ (Non-blocking):

ಇಲ್ಲಿ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಖಾಲಿ ಕೂರುವುದಿಲ್ಲ! ಆ ಫಂಕ್ಷನ್‌ನಿಂದ ಹೊರಬಂದು, ಕೆಳಗಿರುವ ಬೇರೆ ಸಾಲಿನ ಕೋಡ್‌ಗಳನ್ನು ರನ್ ಮಾಡಲು ಶುರು ಮಾಡುತ್ತದೆ.

5

ಮರಳಿ ಬರುವುದು (Resume):

ಹಿನ್ನೆಲೆಯಲ್ಲಿ ನಡೆಯುತ್ತಿದ್ದ ಕೆಲಸ ಮುಗಿದ ತಕ್ಷಣ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಮತ್ತೆ ಎಲ್ಲಿ `await` ಬಳಿ ಕೋಡ್ ನಿಲ್ಲಿಸಿತ್ತೋ, ಅಲ್ಲಿಂದಲೇ ಮುಂದಿನ ಸಾಲುಗಳನ್ನು ರನ್ ಮಾಡುತ್ತದೆ.

6 ಹಂತ 6: ಪ್ರಾಯೋಗಿಕ ಉದಾಹರಣೆಗಳು (Beginner to Pro)

Level 1 ಬೇಸಿಕ್ (ಹೋಟೆಲ್ ಆರ್ಡರ್) 

function makeDosa() {
    return new Promise(resolve => setTimeout(() => resolve("ದೋಸೆ ರೆಡಿಯಾಗಿದೆ! 🍽️"), 3000));
}

async function getFood() {
    console.log("1. ಆರ್ಡರ್ ಮಾಡಿದ್ದೀನಿ, ಕಾಯುತ್ತಿದ್ದೇನೆ...");
    let food = await makeDosa(); // 3 ಸೆಕೆಂಡ್ ಕಾಯುತ್ತದೆ
    console.log("2.", food);
}

getFood();
console.log("ಈ ಮಧ್ಯೆ ನಾನು ಸ್ನೇಹಿತರೊಂದಿಗೆ ಮಾತನಾಡುತ್ತಿದ್ದೇನೆ... 🗣️");
// ಔಟ್‌ಪುಟ್: ಮೊದಲು 1 ಮತ್ತು 'ಸ್ನೇಹಿತರೊಂದಿಗೆ...' ಪ್ರಿಂಟ್ ಆಗಿ, 3 ಸೆಕೆಂಡ್ ನಂತರ ದೋಸೆ ಬರುತ್ತದೆ.

📌 ಕೋಡ್‌ನ ಹಂತ-ಹಂತದ ವಿವರಣೆ:

  • `makeDosa()` : ಇದು 3 ಸೆಕೆಂಡ್ ಕಾಯುವ ಒಂದು Promise.
  • `getFood()` ಕರೆಯಲ್ಪಟ್ಟಾಗ, `"1. ಆರ್ಡರ್ ಮಾಡಿದ್ದೀನಿ..."` ಪ್ರಿಂಟ್ ಆಗುತ್ತದೆ.
  • `await makeDosa()` ಎದುರಾದಾಗ `getFood` ಫಂಕ್ಷನ್ 3 ಸೆಕೆಂಡ್‌ಗಳ ಕಾಲ ತಾತ್ಕಾಲಿಕವಾಗಿ ನಿಲ್ಲುತ್ತದೆ (Pause).
  • ಆದರೆ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಕಾಯುವುದಿಲ್ಲ! ಅದು ಫಂಕ್ಷನ್‌ನಿಂದ ಹೊರಬಂದು, ಕೆಳಗಿರುವ `"ಈ ಮಧ್ಯೆ ನಾನು ಸ್ನೇಹಿತರೊಂದಿಗೆ..."` ಅನ್ನು ತಕ್ಷಣ ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ.
  • 3 ಸೆಕೆಂಡ್ ಮುಗಿದ ತಕ್ಷಣ, ಮತ್ತೆ `getFood` ಒಳಗೆ ಹೋಗಿ `"2. ದೋಸೆ ರೆಡಿಯಾಗಿದೆ! 🍽️"` ಎಂದು ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ.

Level 2 ಇಂಟರ್ಮೀಡಿಯೇಟ್ (API ನಿಂದ ಡೇಟಾ ತರುವುದು)

ಇಲ್ಲಿ fetch ಎಂಬುದು ಮೊದಲೇ ಸಿದ್ಧಪಡಿಸಿದ Promise ಆಗಿದೆ.

async function getUserData() {
    console.log("ಡೇಟಾ ತರುತ್ತಿದ್ದೇನೆ... ⏳");
    
    // ಇಂಟರ್ನೆಟ್‌ನಿಂದ ಡೇಟಾ ಬರಲು ಕಾಯುತ್ತಿದೆ
    let response = await fetch('https://jsonplaceholder.typicode.com/users/1');
    
    // ಬಂದ ಡೇಟಾವನ್ನು JSON ಗೆ ಬದಲಾಯಿಸಲು ಕಾಯುತ್ತಿದೆ
    let user = await response.json();
    
    console.log("ಬಳಕೆದಾರನ ಹೆಸರು:", user.name);
}
getUserData();

📌 ಕೋಡ್‌ನ ಹಂತ-ಹಂತದ ವಿವರಣೆ:

  • `await fetch(...)` : ಇದು ಇಂಟರ್ನೆಟ್‌ನಿಂದ (API) ಡೇಟಾ ತರುತ್ತದೆ. ಇದು ತಾನಾಗಿಯೇ ಒಂದು Promise ಆಗಿರುವುದರಿಂದ ಡೇಟಾ ಡೌನ್‌ಲೋಡ್ ಆಗುವರೆಗೆ ಕೋಡ್ ಇಲ್ಲೇ ಕಾಯುತ್ತದೆ.
  • `await response.json()` : ಇಂಟರ್ನೆಟ್‌ನಿಂದ ಬಂದ ಡೇಟಾ ನೇರವಾಗಿ ಓದಲು ಬರುವುದಿಲ್ಲ. ಅದನ್ನು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವ JSON ಫಾರ್ಮ್ಯಾಟ್‌ಗೆ ಬದಲಾಯಿಸಲು ಸ್ವಲ್ಪ ಸಮಯ ಬೇಕು. ಅದಕ್ಕೂ `await` ಹಾಕಲಾಗಿದೆ.
  • `user.name` : JSON ಆಗಿ ಬದಲಾದ ಡೇಟಾದಿಂದ ಕೇವಲ ಹೆಸರನ್ನು (name) ಮಾತ್ರ ತೆಗೆದು ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ.

Level 3 ಪ್ರೊ (Pro) - ದೋಷ ನಿವಾರಣೆ (Error Handling) ಮತ್ತು `Promise.all`

ಇಂಟರ್ನೆಟ್ ಆಫ್ ಆಗಿದ್ದರೆ ಪ್ರೋಗ್ರಾಮ್ ಕ್ರ್ಯಾಶ್ ಆಗದಂತೆ `try...catch` ಮತ್ತು ಏಕಕಾಲದಲ್ಲಿ ಹಲವು ಡೇಟಾ ತರಲು `Promise.all` ಬಳಸಲಾಗುತ್ತದೆ.

async function getMultipleUsersInfo() {
    try {
        console.log("ಮಾಹಿತಿ ಕಲೆಹಾಕಲಾಗುತ್ತಿದೆ...");

        // Promise.all ಬಳಸಿ ಒಟ್ಟಿಗೆ ಎರಡು ಡೇಟಾಗಳನ್ನು ತರುವುದು (ಸಮಯದ ಉಳಿತಾಯ)
        let [res1, res2] = await Promise.all([
            fetch('https://jsonplaceholder.typicode.com/users/1'),
            fetch('https://jsonplaceholder.typicode.com/users/2')
        ]);

        let user1 = await res1.json();
        let user2 = await res2.json();

        console.log("ಮೊದಲ ವ್ಯಕ್ತಿ:", user1.name, "| ಎರಡನೇ ವ್ಯಕ್ತಿ:", user2.name);

    } catch (error) {
        // ಇಂಟರ್ನೆಟ್ ಇಲ್ಲದಿದ್ದರೆ ಈ ಭಾಗ ರನ್ ಆಗುತ್ತದೆ
        console.log("ಕ್ಷಮಿಸಿ, ದೋಷ ಕಂಡುಬಂದಿದೆ! 🚫", error.message);
    } finally {
        // ಕೆಲಸ ಯಶಸ್ವಿಯಾಗಲಿ ಅಥವಾ ವಿಫಲವಾಗಲಿ, ಇದು ರನ್ ಆಗುತ್ತದೆ
        console.log("ಪ್ರಕ್ರಿಯೆ ಮುಕ್ತಾಯಗೊಂಡಿದೆ. ✅");
    }
}
getMultipleUsersInfo();

📌 ಕೋಡ್‌ನ ಹಂತ-ಹಂತದ ವಿವರಣೆ:

  • `try { ... }` : ಯಶಸ್ವಿಯಾಗಿ ನಡೆಯಬೇಕಾದ ಕೋಡ್ ಅನ್ನು ಇದರೊಳಗೆ ಬರೆಯುತ್ತೇವೆ.
  • `await Promise.all([...])` : ಇದು ಬಹಳ ಮುಖ್ಯ! ಎರಡು ಪ್ರತ್ಯೇಕ `await fetch` ಬರೆದರೆ, ಮೊದಲನೆಯದು ಮುಗಿಯುವರೆಗೆ ಎರಡನೆಯದು ಕಾಯಬೇಕು. ಆದರೆ `Promise.all` ಬಳಸಿದರೆ ಎರಡೂ API ಗಳು ಏಕಕಾಲದಲ್ಲಿ (Parallel) ರನ್ ಆಗಿ, ಸಮಯ ಉಳಿತಾಯವಾಗುತ್ತದೆ.
  • `let [res1, res2]` : ಎರಡೂ ಡೇಟಾಗಳನ್ನು ಒಟ್ಟಿಗೆ ತಂದು Array Destructuring ಮೂಲಕ ಎರಡು ಬೇರೆ ಬೇರೆ ವೇರಿಯೇಬಲ್‌ಗೆ ಹಾಕಲಾಗುತ್ತಿದೆ.
  • `catch (error) { ... }` : ಒಂದು ವೇಳೆ ಇಂಟರ್ನೆಟ್ ಇಲ್ಲದಿದ್ದರೆ ಅಥವಾ ಸರ್ವರ್ ಡೌನ್ ಇದ್ದರೆ `try` ಬ್ಲಾಕ್ ಫೇಲ್ ಆಗುತ್ತದೆ. ಆಗ ಪ್ರೋಗ್ರಾಮ್ ನಿಲ್ಲುವ ಬದಲು, ಈ `catch` ಬ್ಲಾಕ್ ಒಳಗೆ ಬಂದು ಯೂಸರ್‌ಗೆ ದೋಷದ ಸಂದೇಶವನ್ನು (error.message) ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ.
  • `finally { ... }` : ಕೆಲಸ ಸಕ್ಸಸ್ ಆಗಲಿ (try) ಅಥವಾ ಫೇಲ್ ಆಗಲಿ (catch), ಕೊನೆಯಲ್ಲಿ ಈ ಬ್ಲಾಕ್ ಕಡ್ಡಾಯವಾಗಿ ರನ್ ಆಗುತ್ತದೆ (ಉದಾಹರಣೆಗೆ ಲೋಡಿಂಗ್ ಸ್ಪಿನ್ನರ್ ಅನ್ನು ಆಫ್ ಮಾಡಲು ಇದನ್ನು ಬಳಸುತ್ತಾರೆ).

7 ಹಂತ 7: ಹಳೆಯ ವಿಧಾನ vs ಹೊಸ ವಿಧಾನ (ಏಕೆ ಬದಲಾಯಿಸಬೇಕು?)

ಹಳೆಯ `Promise.then().catch()` ವಿಧಾನವನ್ನು ಹೊಸ `async/await` ಗೆ ಬದಲಾಯಿಸುವುದು ಬಹಳ ಸುಲಭ.

  • `.then()` ಮಾಡುವ ಕೆಲಸವನ್ನು `await` ಮಾಡುತ್ತದೆ.
  • `.catch()` ಮಾಡುವ ಕೆಲಸವನ್ನು `try...catch` ಮಾಡುತ್ತದೆ.

ಹಳೆಯ ವಿಧಾನ (Callback Hell / Promise Chain): 

fetch('https://jsonplaceholder.typicode.com/users/1')
    .then(response => response.json())
    .then(user => console.log(user.name))
    .catch(error => console.log(error));

ಇಲ್ಲಿ `fetch` ಮಾಡಿದ ಮೇಲೆ ಡೇಟಾ ಬಂದರೆ `.then` ಒಳಗೆ ಹೋಗು, ಆಮೇಲೆ ಅದನ್ನು JSON ಮಾಡು, ಆಮೇಲೆ ಪ್ರಿಂಟ್ ಮಾಡು, ಏನಾದರೂ ತಪ್ಪಾದರೆ `.catch` ಗೆ ಹೋಗು ಎಂದು ಚೈನ್ (Chain) ರೀತಿ ಬರೆಯಲಾಗುತ್ತದೆ.

ಸಮಸ್ಯೆ: ಒಂದರ ಕೆಳಗೆ ಒಂದು `.then()` ಬರೆಯುತ್ತಾ ಹೋದರೆ ಕೋಡ್ ಓದಲು ಕಷ್ಟವಾಗುತ್ತದೆ (ಇದನ್ನು Callback Hell ಎನ್ನುತ್ತಾರೆ).

ಹೊಸ ವಿಧಾನ (Clean & Readable): 

async function getUser() {
    try {
        let response = await fetch('https://jsonplaceholder.typicode.com/users/1');
        let user = await response.json();
        console.log(user.name);
    } catch (error) {
        console.log(error);
    }
}

ಇಲ್ಲಿ ಯಾವುದೇ `.then` ಚೈನಿಂಗ್ ಇಲ್ಲ.

ಸಾಲು 1 ರಲ್ಲಿ ಡೇಟಾ ತರುವುದು, ಸಾಲು 2 ರಲ್ಲಿ JSON ಮಾಡುವುದು, ಸಾಲು 3 ರಲ್ಲಿ ಪ್ರಿಂಟ್ ಮಾಡುವುದು. ಇದು ಸಾಮಾನ್ಯ ಸಿಂಕ್ರೋನಸ್ ಕೋಡ್‌ನಂತೆಯೇ ಕಾಣುತ್ತದೆ.

ಲಾಭ: ಹೊಸ ವಿಧಾನದಲ್ಲಿ ಕೋಡ್ ಸಾಮಾನ್ಯ ಇಂಗ್ಲಿಷ್ ವಾಕ್ಯದಂತೆ ಓದಲು ಮತ್ತು ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಬಹಳ ಸುಲಭ.

8 ಹಂತ 8: ಬೋನಸ್ ಮಾಹಿತಿ (ನೀವು ತಿಳಿದಿರಲೇಬೇಕಾದ ಅಂಶಗಳು)

1. `await` ಹಾಕಲು ಮರೆತರೆ ಏನಾಗುತ್ತದೆ?

ಒಂದು ವೇಳೆ ನೀವು `await` ಹಾಕಲು ಮರೆತರೆ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಡೇಟಾ ಬರುವವರೆಗೆ ಕಾಯುವುದಿಲ್ಲ. ಬದಲಾಗಿ ಅದು ನೇರವಾಗಿ ಒಂದು ಖಾಲಿ Promise { <pending> } ಅನ್ನು ರಿಟರ್ನ್ ಮಾಡಿಬಿಡುತ್ತದೆ. ಇದು ಡೆವಲಪರ್‌ಗಳು ಮಾಡುವ ಅತಿ ಸಾಮಾನ್ಯ ತಪ್ಪು.

2. Top-level `await` (ಹೊಸ ಅಪ್ಡೇಟ್):

ಹಿಂದೆ `await` ಬಳಸಲು `async` ಫಂಕ್ಷನ್ ಕಡ್ಡಾಯವಾಗಿತ್ತು. ಆದರೆ ಆಧುನಿಕ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ (ES2022+) Modules (type="module") ಒಳಗೆ ಫಂಕ್ಷನ್ ಇಲ್ಲದೆಯೂ ನೇರವಾಗಿ await fetch(...) ಎಂದು ಬರೆಯಬಹುದು.

ಹಂತ 9: ವಿಶೇಷ ಬೋನಸ್ - Event Loop ಮತ್ತು Microtask Queue

ನೀವು Event Loop ಆರ್ಕಿಟೆಕ್ಚರ್ ಅನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವಾಗ async/await ನ ಹಿಂದಿನ ರಹಸ್ಯವನ್ನು ತಿಳಿದಿರುವುದು ಅತ್ಯಗತ್ಯ:

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ Promise ಗಳು (ಹಾಗೂ `await` ನ ಮುಂದಿನ ಸಾಲುಗಳು) ನೇರವಾಗಿ ಮೈಕ್ರೋಟಾಸ್ಕ್ ಕ್ಯೂ (Microtask Queue) ಒಳಗೆ ಹೋಗುತ್ತವೆ.

ಸಾಮಾನ್ಯ `setTimeout` ಅಥವಾ Event Listener ಗಳು ಮ್ಯಾಕ್ರೋಟಾಸ್ಕ್ ಕ್ಯೂ (Macrotask Queue) ಒಳಗೆ ಹೋಗುತ್ತವೆ.

💡 ಪ್ರಮುಖ ನಿಯಮ: Event Loop ಯಾವಾಗಲೂ ಮ್ಯಾಕ್ರೋಟಾಸ್ಕ್‌ಗಿಂತ ಮೊದಲು ಮೈಕ್ರೋಟಾಸ್ಕ್ ಕ್ಯೂ ಅನ್ನು ಸಂಪೂರ್ಣವಾಗಿ ಖಾಲಿ ಮಾಡುತ್ತದೆ. ಆದ್ದರಿಂದ `await` ನ ಹಿನ್ನೆಲೆ ಕೆಲಸಗಳು `setTimeout` ಗಿಂತ ಹೆಚ್ಚಿನ ಆದ್ಯತೆ (High Priority) ಪಡೆಯುತ್ತವೆ!
