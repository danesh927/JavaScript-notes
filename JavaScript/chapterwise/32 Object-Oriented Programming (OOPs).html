Object-Oriented Programming (OOPs) in JavaScript - ಸಂಪೂರ್ಣ ನೋಟ್ಸ್

ಪೀಠಿಕೆ (Introduction):

OOPs (Object-Oriented Programming) ಎಂಬುದು ಪ್ರೋಗ್ರಾಮಿಂಗ್ ಬರೆಯುವ ಒಂದು ಶೈಲಿ ಅಥವಾ ವಿಧಾನ. ಇದನ್ನು ಕಲಿಯಲು ನೀವು ಐಟಿ (IT) ಹಿನ್ನೆಲೆಯಿಂದಲೇ ಬರಬೇಕಾಗಿಲ್ಲ. ನಮ್ಮ ದೈನಂದಿನ ಜೀವನದ ಉದಾಹರಣೆಗಳನ್ನು ಬಳಸಿಕೊಂಡು ES6 Classes ಮತ್ತು OOPs ನ ನಾಲ್ಕು ಮುಖ್ಯ ಗುಣಲಕ್ಷಣಗಳನ್ನು (Properties) ನಾವು ಸುಲಭವಾಗಿ ಅರ್ಥಮಾಡಿಕೊಳ್ಳಬಹುದು.

(ಹೆಚ್ಚುವರಿ ಮಾಹಿತಿ: OOPs ಬಳಕೆಯಿಂದ ಸಾಫ್ಟ್‌ವೇರ್ ಡೆವಲಪ್‌ಮೆಂಟ್‌ನಲ್ಲಿ ಕೋಡ್ ಅನ್ನು ಅಚ್ಚುಕಟ್ಟಾಗಿ ನಿರ್ವಹಿಸಬಹುದು, ಒಂದೇ ಕೋಡ್ ಅನ್ನು ಮತ್ತೆ ಮತ್ತೆ ಬಳಸಬಹುದು (Reusability) ಮತ್ತು ದೊಡ್ಡ ಪ್ರಾಜೆಕ್ಟ್‌ಗಳನ್ನು ಸುಲಭವಾಗಿ ವಿಂಗಡಿಸಿ ನಿರ್ಮಿಸಬಹುದು.)

ಜ್ಞಾನ ವಿಸ್ತರಣೆ (DOM & OOPs):

ನೀವು ಫ್ರಂಟ್-ಎಂಡ್ ಡೆವಲಪ್‌ಮೆಂಟ್ ಕಲಿಯುತ್ತಿರುವಾಗ, ಬ್ರೌಸರ್‌ನ DOM (Document Object Model) ಕೂಡ ಇದೇ Object-Oriented ಶೈಲಿಯಲ್ಲಿ ಕೆಲಸ ಮಾಡುತ್ತದೆ. ಪ್ರತಿಯೊಂದು HTML ಎಲಿಮೆಂಟ್ (ಉದಾ: <div>, <button>) ಬ್ರೌಸರ್‌ನಲ್ಲಿ ಒಂದು 'Object' ಆಗಿರುತ್ತದೆ ಮತ್ತು ಅವೆಲ್ಲವೂ HTMLElement ಎಂಬ ಕ್ಲಾಸ್‌ನಿಂದ Inheritance ಮೂಲಕ ಗುಣಗಳನ್ನು ಪಡೆದುಕೊಳ್ಳುತ್ತವೆ. ಈ OOPs ನಿಯಮಗಳು ಈವೆಂಟ್ ಹ್ಯಾಂಡ್ಲಿಂಗ್ (Event Handling) ಮತ್ತು DOM ಮ್ಯಾನಿಪುಲೇಶನ್‌ಗೆ ಅಡಿಪಾಯವಾಗಿವೆ.

1 Class ಮತ್ತು Object ಎಂದರೇನು?

ಸಾಮಾನ್ಯ (Non-Technical) ವಿವರಣೆ:

  • Class (ಕ್ಲಾಸ್): ಇದು ಮನೆ ಕಟ್ಟಲು ಬಳಸುವ 'ನಕ್ಷೆ' (Blueprint) ಇದ್ದ ಹಾಗೆ. ನಕ್ಷೆಯಲ್ಲಿ ಮನೆಯಲ್ಲಿ ಎಷ್ಟು ಕೋಣೆಗಳಿವೆ, ಬಾಗಿಲು ಎಲ್ಲಿದೆ ಎಂದು ಬರೆದಿರುತ್ತದೆ, ಆದರೆ ಅದರಲ್ಲಿ ಯಾರೂ ವಾಸಿಸಲು ಸಾಧ್ಯವಿಲ್ಲ.
  • Object (ಆಬ್ಜೆಕ್ಟ್): ಆ ನಕ್ಷೆಯನ್ನು ನೋಡಿಕೊಂಡು ಕಟ್ಟಿದ 'ನಿಜವಾದ ಮನೆ'. ಒಂದೇ ನಕ್ಷೆ (Class) ಬಳಸಿ ನೀವು 10 ಮನೆಗಳನ್ನು (Objects) ಕಟ್ಟಬಹುದು. ಪ್ರತಿಯೊಂದು ಮನೆಗೂ ಬೇರೆ ಬೇರೆ ಬಣ್ಣ ಬಳಿಯಬಹುದು.

ತಾಂತ್ರಿಕ (Technical) ವಿವರಣೆ:

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ (ES6) ನಲ್ಲಿ class ಎಂಬ ಕೀವರ್ಡ್ ಬಳಸಿ ನಾವು ಒಂದು ಟೆಂಪ್ಲೇಟ್ ಅನ್ನು ಸೃಷ್ಟಿಸುತ್ತೇವೆ. ಈ ಟೆಂಪ್ಲೇಟ್ ಬಳಸಿ new ಕೀವರ್ಡ್ ಮೂಲಕ ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ರಚಿಸುತ್ತೇವೆ. constructor ಎಂಬುದು ಆಬ್ಜೆಕ್ಟ್ ಸೃಷ್ಟಿಯಾದಾಗ ಅದರ ಆರಂಭಿಕ ಮಾಹಿತಿಯನ್ನು (ಉದಾಹರಣೆಗೆ ಬಣ್ಣ, ಹೆಸರು) ಸೆಟ್ ಮಾಡುವ ವಿಶೇಷ ಫಂಕ್ಷನ್. 


// Class (ಮನೆಯ ನಕ್ಷೆ)
class Car {
  // Constructor: ಆಬ್ಜೆಕ್ಟ್ ಹುಟ್ಟಿದಾಗ ಏನಿರಬೇಕು ಎಂದು ಹೇಳುತ್ತದೆ
  constructor(brandName, color) {
    this.brand = brandName; 
    this.color = color;
  }
 
  // Method (ಕಾರ್ಯ): ಕಾರು ಏನು ಮಾಡಬಲ್ಲದು?
  start() {
    console.log(`ನನ್ನ ${this.color} ಬಣ್ಣದ ${this.brand} ಕಾರು ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!`);
  }
}
 
// Object (ನಿಜವಾದ ಕಾರುಗಳನ್ನು ಸೃಷ್ಟಿಸುವುದು)
const myCar = new Car("Tata Nexon", "ಕೆಂಪು");
const yourCar = new Car("Maruti Swift", "ಬಿಳಿ");
 
myCar.start(); 
yourCar.start();
ಔಟ್‌ಪುಟ್:
> ನನ್ನ ಕೆಂಪು ಬಣ್ಣದ Tata Nexon ಕಾರು ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!
> ನನ್ನ ಬಿಳಿ ಬಣ್ಣದMaruti Swift ಕಾರು ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!

(ನೀವು ನೀಡಿರುವ ಉದಾಹರಣೆ ಮತ್ತು ವಿವರಣೆ ಅತ್ಯುತ್ತಮವಾಗಿದೆ! ಸಾಮಾನ್ಯ ಜನರಿಗೂ ಅರ್ಥವಾಗುವಂತಹ ಸುಲಭವಾದ ಭಾಷೆಯಲ್ಲಿದೆ.)
ಇದನ್ನೇ ಇನ್ನಷ್ಟು ಆಳವಾಗಿ, ಪ್ರತಿಯೊಂದು ಸಾಲಿನ ಅರ್ಥವೇನು, ಮತ್ತು ಅದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ ಎಂಬುದನ್ನು ಹಂತ-ಹಂತವಾಗಿ ಬಿಡಿಸಿ ನೋಡೋಣ:

1. class Car { ... } (ಕಾರ್ ಎಂಬ ನಕ್ಷೆಯ ತಯಾರಿ)
ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ class ಎಂಬುದು ಕೇವಲ ಒಂದು ಕಲ್ಪನೆ ಅಥವಾ ಡಿಸೈನ್ (Blueprint). class Car ಎಂದು ಬರೆದಾಗ, ಕಂಪ್ಯೂಟರ್‌ಗೆ "ನಾನು ಕಾರುಗಳ ಬಗ್ಗೆ ಒಂದು ಟೆಂಪ್ಲೇಟ್ ಮಾಡುತ್ತಿದ್ದೇನೆ" ಎಂದು ಹೇಳಿದಂತೆ. ಇಲ್ಲಿ ಯಾವುದೇ ನಿಜವಾದ ಕಾರು ಸೃಷ್ಟಿಯಾಗಿಲ್ಲ.

2. constructor(brandName, color) (ಆರಂಭಿಕ ಸಿದ್ಧತೆ)
constructor (ಕನ್ಸ್ಟ್ರಕ್ಟರ್) ಎನ್ನುವುದು ಕ್ಲಾಸ್‌ನ ಒಳಗೆ ಇರುವ ಒಂದು ವಿಶೇಷವಾದ ಫಂಕ್ಷನ್ (Function).

  • ನೀವು new ಕೀವರ್ಡ್ ಬಳಸಿ ಹೊಸ ಕಾರನ್ನು (Object) ಸೃಷ್ಟಿಸಿದ ತಕ್ಷಣ, ಈ constructor ತಾನೇ ತಾನಾಗಿ ಕೆಲಸ ಮಾಡಲು ಶುರು ಮಾಡುತ್ತದೆ.
  • ಬ್ರಾಂಡ್ ಹೆಸರು (brandName) ಮತ್ತು ಬಣ್ಣವನ್ನು (color) ಕಚ್ಚಾ ವಸ್ತುವಾಗಿ (Inputs) ತೆಗೆದುಕೊಳ್ಳುತ್ತದೆ.

3. this ಕೀವರ್ಡ್‌ನ ಹಿಂದಿನ ಮ್ಯಾಜಿಕ್
ಇಲ್ಲಿ this ಎಂಬ ಪದ ಬಹಳ ಮುಖ್ಯ. this ಎಂದರೆ "ಈ ನಿರ್ದಿಷ್ಟ ಕಾರಿನ" (This specific object's) ಎಂದರ್ಥ.

  • this.brand = brandName; : ಎಂದರೆ "ಸೃಷ್ಟಿಯಾಗುತ್ತಿರುವ ಈ ಹೊಸ ಕಾರಿನ ಬ್ರಾಂಡ್ ಹೆಸರು, ನಾವು ಕೊಟ್ಟ brandName ಆಗಿರಲಿ" ಎಂದು.
  • this.color = color; : ಎಂದರೆ "ಈ ಕಾರಿನ ಬಣ್ಣ, ನಾವು ಕೊಟ್ಟ color ಆಗಿರಲಿ" ಎಂದು. ಉದಾಹರಣೆಗೆ, ಟಾಟಾ ನೆಕ್ಸಾನ್ ಕಾರು ಸೃಷ್ಟಿಯಾಗುವಾಗ this ಎಂದರೆ ಟಾಟಾ ಕಾರು. ಸ್ವಿಫ್ಟ್ ಕಾರು ಸೃಷ್ಟಿಯಾಗುವಾಗ ಅದೇ this ಎಂದರೆ ಸ್ವಿಫ್ಟ್ ಕಾರು.

4. start() ಮೆಥಡ್ (ಕಾರಿನ ಕೆಲಸ ಅಥವಾ ವರ್ತನೆ)
ಕ್ಲಾಸ್ ಒಳಗೆ ನಾವು ಬರೆಯುವ ಫಂಕ್ಷನ್‌ಗಳನ್ನು ಮೆಥಡ್ (Method) ಎಂದು ಕರೆಯುತ್ತೇವೆ. ಇದು ಕಾರು ಏನು ಮಾಡಬಲ್ಲದು (ಉದಾಹರಣೆಗೆ: start ಆಗುವುದು, stop ಆಗುವುದು, horn ಮಾಡುವುದು) ಎಂಬುದನ್ನು ಹೇಳುತ್ತದೆ. ಇಲ್ಲಿ ${this.color} ಮತ್ತು ${this.brand} ಬಳಸಿರುವುದರಿಂದ, ಯಾವ ಕಾರು ಸ್ಟಾರ್ಟ್ ಆಗುತ್ತಿದೆಯೋ, ಅದೇ ಕಾರಿನ ಬಣ್ಣ ಮತ್ತು ಹೆಸರನ್ನು ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ.

5. Object ಸೃಷ್ಟಿಸುವುದು (ನಕ್ಷೆಯಿಂದ ನಿಜವಾದ ಮನೆ ಕಟ್ಟುವ ಹಂತ)

const myCar = new Car("Tata Nexon", "ಕೆಂಪು");

ಈ ಒಂದು ಸಾಲಿನಲ್ಲಿ ನಡೆಯುವ ಪ್ರಕ್ರಿಯೆಗಳು:

  1. new ಎಂಬ ಪದ ಕಂಪ್ಯೂಟರ್‌ಗೆ "ಹೊಸ ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ಸೃಷ್ಟಿಸು" ಎಂದು ಆದೇಶಿಸುತ್ತದೆ.
  2. Car ಕ್ಲಾಸ್‌ನ ಬಳಿ ಹೋಗಿ, ಅದರ constructor ಗೆ "Tata Nexon" ಮತ್ತು "ಕೆಂಪು" ಎಂಬ ಮಾಹಿತಿಯನ್ನು ಕಳುಹಿಸುತ್ತದೆ.
  3. ಈಗ myCar ಎಂಬುದು ಬರೀ ಹೆಸರಲ್ಲ, ಅದೊಂದು ಸಂಪೂರ್ಣವಾಗಿ ತಯಾರಾದ ನಿಜವಾದ ಕಾರು (Object). ಅದರ ಬಣ್ಣ ಕೆಂಪು, ಅದರ ಬ್ರಾಂಡ್ Tata Nexon.
const yourCar = new Car("Maruti Swift", "ಬಿಳಿ");

ಅದೇ ರೀತಿ, ಒಂದೇ ನಕ್ಷೆ ಬಳಸಿ ಮತ್ತೊಂದು ಹೊಸ ಕಾರನ್ನು ಸೃಷ್ಟಿಸಿದೆವು. ಇದರ ಗುಣಲಕ್ಷಣಗಳು ಸಂಪೂರ್ಣ ಬೇರೆ.

6. ಮೆಥಡ್ ಅನ್ನು ಕರೆಯುವುದು (ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ಬಳಸುವುದು)

myCar.start();

ಇಲ್ಲಿ myCar ತನ್ನ start() ಕೆಲಸವನ್ನು ಶುರು ಮಾಡುತ್ತದೆ. myCar ನ ಬಣ್ಣ ಕೆಂಪು ಆಗಿರುವುದರಿಂದ, ಕಂಪ್ಯೂಟರ್ "ನನ್ನ ಕೆಂಪು ಬಣ್ಣದ Tata Nexon ಕಾರು ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!" ಎಂದು ಹೇಳುತ್ತದೆ.

yourCar.start();

ಇಲ್ಲಿ yourCar ನ ಬಣ್ಣ ಬಿಳಿ ಆಗಿರುವುದರಿಂದ, ಅದು "ನನ್ನ ಬಿಳಿ ಬಣ್ಣದMaruti Swift ಕಾರು ಸ್ಟಾರ್ಟ್ ಆಯ್ತು!" ಎಂದು ಹೇಳುತ್ತದೆ.

ಒಟ್ಟಾರೆಯಾಗಿ ಇದರ ಉಪಯೋಗವೇನು? (Why use Class and Object?)
ಒಂದು ವೇಳೆ class ಇಲ್ಲದಿದ್ದರೆ, ನೀವು 100 ಕಾರುಗಳ ಮಾಹಿತಿಯನ್ನು ಬರೆಯಲು100 ಬಾರಿ ಪ್ರತ್ಯೇಕವಾಗಿ ಬರೆಯಬೇಕಾಗುತ್ತಿತ್ತು. ಆದರೆ Class ಬಳಸುವುರಿಂದ ಕೋಡಿಂಗ್ ತುಂಬಾ ಸುಲಭ (Reusable) ಆಗುತ್ತದೆ. ಒಮ್ಮೆ ನಕ್ಷೆ ಬರೆದಿಟ್ಟುಕೊಂಡರೆ, new ಪದ ಬಳಸಿ ಸಾವಿರಾರು ಕಾರುಗಳನ್ನು (Objects) ಕ್ಷಣಾರ್ಧದಲ್ಲಿ ಸೃಷ್ಟಿಸಬಹುದು!

2 Encapsulation (ಎನ್ಕ್ಯಾಪ್ಸುಲೇಶನ್) - ಡೇಟಾ ಭದ್ರತೆ

ಸಾಮಾನ್ಯ (Non-Technical) ವಿವರಣೆ:

ನೀವು ಬ್ಯಾಂಕ್‌ಗೆ ಹೋದಾಗ, ನಿಮ್ಮ ಅಕೌಂಟ್‌ನಲ್ಲಿರುವ ಬ್ಯಾಲೆನ್ಸ್ ಅನ್ನು ನೀವೇ ನೇರವಾಗಿ ಪೆನ್ನಿನಲ್ಲಿ ತಿದ್ದಲು ಸಾಧ್ಯವಿಲ್ಲ. ಬದಲಾಗಿ, ನೀವು "Deposit" (ಹಣ ಜಮೆ ಮಾಡು) ಅಥವಾ "Withdraw" (ಹಣ ತೆಗೆ) ಎಂಬ ನಿಯಮಬದ್ಧ ಪ್ರಕ್ರಿಯೆಗಳ ಮೂಲಕವೇ ಬ್ಯಾಲೆನ್ಸ್ ಬದಲಾಯಿಸಬೇಕು. ಇದು ನಿಮ್ಮ ಹಣಕ್ಕೆ ಭದ್ರತೆ ನೀಡುತ್ತದೆ.

ತಾಂತ್ರಿಕ (Technical) ವಿವರಣೆ:

ಡೇಟಾ (Variables) ಮತ್ತು ಆ ಡೇಟಾವನ್ನು ಬದಲಾಯಿಸುವ ಫಂಕ್ಷನ್‌ಗಳನ್ನು (Methods) ಒಂದೇ ಕ್ಲಾಸ್ ಒಳಗೆ ಸೇರಿಸಿ, ಹೊರಗಿನಿಂದ ಯಾರೂ ನೇರವಾಗಿ ಡೇಟಾವನ್ನು ಬದಲಾಯಿಸದಂತೆ ತಡೆಯುವುದೇ Encapsulation. ES6 ನಲ್ಲಿ ವೇರಿಯೇಬಲ್ ಹೆಸರಿನ ಹಿಂದೆ # ಹಾಕಿದರೆ ಅದು 'Private' ಆಗುತ್ತದೆ. ಅದನ್ನು ಕ್ಲಾಸ್‌ನ ಹೊರಗೆ ಬಳಸಲು ಸಾಧ್ಯವಿಲ್ಲ.


class BankAccount {
  // '#' ಎಂದರೆ ಇದು Private ಡೇಟಾ (ಯಾರೂ ನೇರವಾಗಿ ಮುಟ್ಟುವಂತಿಲ್ಲ)
  #balance = 0; 
 
  constructor(accountHolder) {
    this.name = accountHolder;
  }
 
  // ಹಣ ಸೇರಿಸಲು ಮಾತ್ರ ಅವಕಾಶ ನೀಡುವ ಫಂಕ್ಷನ್
  deposit(amount) {
    if(amount > 0) {
      this.#balance += amount;
      console.log(`${amount} ರೂ. ಜಮಾ ಆಯಿತು. ಒಟ್ಟು ಬ್ಯಾಲೆನ್ಸ್: ${this.#balance}`);
    }
  }
 
  // ಬ್ಯಾಲೆನ್ಸ್ ನೋಡಲು ಮಾತ್ರ ಅವಕಾಶ (ಬದಲಾಯಿಸುವಂತಿಲ್ಲ)
  getBalance() {
    return this.#balance;
  }
}
 
const myAccount = new BankAccount("ರಾಮು");
myAccount.deposit(500); 
// myAccount.#balance = 1000; // ಹೀಗೆ ಮಾಡಿದರೆ Error ಬರುತ್ತದೆ! ಇದು ಸುರಕ್ಷಿತ.
console.log(myAccount.getBalance());
ಔಟ್‌ಪುಟ್:
> 500 ರೂ. ಜಮಾ ಆಯಿತು. ಒಟ್ಟು ಬ್ಯಾಲೆನ್ಸ್: 500
> 500

ಎನ್ಕ್ಯಾಪ್ಸುಲೇಶನ್ (Encapsulation) ನ ಪ್ರಮುಖ ಉದ್ದೇಶ ಡೇಟಾ ಭದ್ರತೆ ಮತ್ತು ನಿಯಂತ್ರಣ (Security and Control). ಕೋಡ್ ಅನ್ನು ಹಂತ-ಹಂತವಾಗಿ ಬಿಡಿಸಿ ನೋಡಿದಾಗ ಇದು ಹೇಗೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ ಎಂಬುದು ಸ್ಪಷ್ಟವಾಗುತ್ತದೆ:

1. ಖಾಸಗಿ ಡೇಟಾ (Private Data): #balance = 0;
ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ವೇರಿಯೇಬಲ್ ಹೆಸರಿನ ಹಿಂದೆ # (ಹ್ಯಾಶ್) ಚಿಹ್ನೆ ಹಾಕಿದರೆ, ಅದು ಖಾಸಗಿ (Private) ಆಗುತ್ತದೆ.

  • ಇದು ಬ್ಯಾಂಕಿನ ಸ್ಟ್ರಾಂಗ್ ರೂಮ್ (Locker) ಇದ್ದ ಹಾಗೆ.
  • ಈ #balance ಅನ್ನು BankAccount ಕ್ಲಾಸ್‌ನ ಒಳಗೆ ಬರೆದಿರುವ ಫಂಕ್ಷನ್‌ಗಳು ಮಾತ್ರ ನೋಡಬಹುದು ಮತ್ತು ಬದಲಾಯಿಸಬಹುದು. ಹೊರಗಿನ ಯಾರಿಗೂ ಇದರ ನೇರ ಸಂಪರ್ಕ ಇರುವುದಿಲ್ಲ.

2. ಆರಂಭಿಕ ಸೆಟಪ್: constructor(accountHolder)
ಬ್ಯಾಂಕ್ ಅಕೌಂಟ್ ತೆರೆದಾಗ ಗ್ರಾಹಕನ ಹೆಸರನ್ನು ನಮೂದಿಸುವ ಹಂತ ಇದು.

  • this.name ನ ಹಿಂದೆ # ಇಲ್ಲ. ಅಂದರೆ, ಅಕೌಂಟ್ ಹೊಂದಿರುವವರ ಹೆಸರು ಪಬ್ಲಿಕ್ (Public) ಆಗಿದೆ. ಇದನ್ನು ಯಾರು ಬೇಕಾದರೂ ಹೊರಗಿನಿಂದ ನೋಡಬಹುದು (ಉದಾಹರಣೆಗೆ: console.log(myAccount.name); ರನ್ ಆಗುತ್ತದೆ).

3. ನಿಯಂತ್ರಿತ ಬದಲಾವಣೆ (Controlled Mutation): deposit(amount)
ಡೇಟಾವನ್ನು ನೇರವಾಗಿ ಬದಲಾಯಿಸಲು ಬಿಡದೆ, ಒಂದು ನಿರ್ದಿಷ್ಟ ದಾರಿಯ (Method) ಮೂಲಕ ಮಾತ್ರ ಬದಲಾಯಿಸಲು ಅವಕಾಶ ಮಾಡಿಕೊಡುವುದು ಎನ್ಕ್ಯಾಪ್ಸುಲೇಶನ್‌ನ ಪ್ರಮುಖ ಲಕ್ಷಣ.

  • ಷರತ್ತು (Condition): if(amount > 0) ಎಂಬ ಷರತ್ತು ಇಲ್ಲಿದೆ. ಯಾರಾದರೂ -500 ರೂ. ಜಮಾ ಮಾಡಲು ಪ್ರಯತ್ನಿಸಿದರೆ, ಈ ಕೋಡ್ ಅದನ್ನು ತಡೆಯುತ್ತದೆ. ನೇರವಾಗಿ ಬ್ಯಾಲೆನ್ಸ್ ಬದಲಾಯಿಸುವ ಅವಕಾಶ ನೀಡಿದ್ದರೆ ಇಂತಹ ತಪ್ಪುಗಳನ್ನು ತಡೆಯಲು ಸಾಧ್ಯವಾಗುತ್ತಿರಲಿಲ್ಲ.
  • ಷರತ್ತು ಪಾಸಾದಾಗ ಮಾತ್ರ #balance ಗೆ ಹಣ ಸೇರ್ಪಡೆಯಾಗುತ್ತದೆ.

4. ಓದಲು ಮಾತ್ರ ಅವಕಾಶ (Read-Only Access): getBalance()
ಗ್ರಾಹಕರಿಗೆ ತಮ್ಮ ಬ್ಯಾಲೆನ್ಸ್ ಎಷ್ಟು ಎಂದು ನೋಡುವ ಹಕ್ಕು ಇರುತ್ತದೆ, ಆದರೆ ತಾವೇ ನಮೂದಿಸುವ ಹಕ್ಕು ಇರುವುದಿಲ್ಲ.

  • ಈ ಫಂಕ್ಷನ್ ಕೇವಲ #balance ನಲ್ಲಿರುವ ಮೌಲ್ಯವನ್ನು ವಾಪಸ್ (return) ಮಾಡುತ್ತದೆ. ಇದು ಬ್ಯಾಂಕಿನ ಪಾಸ್‌ಬುಕ್ ಪ್ರಿಂಟ್ ಅಥವಾ ಎಟಿಎಂ ಮಿನಿ ಸ್ಟೇಟ್‌ಮೆಂಟ್ ಇದ್ದಂತೆ.

5. ಹೊರಗಿನಿಂದ ಆಕ್ಸೆಸ್ ಮಾಡುವಾಗ ಏನಾಗುತ್ತದೆ?

const myAccount = new BankAccount("ರಾಮು");
myAccount.deposit(500);

ಇಲ್ಲಿ ರಾಮು 500 ರೂ. ಜಮಾ ಮಾಡುತ್ತಿದ್ದಾನೆ. ಇದು deposit ಎಂಬ ಅಧಿಕೃತ ಮಾರ್ಗದ ಮೂಲಕ ನಡೆಯುತ್ತಿರುವುದರಿಂದ, ವ್ಯವಹಾರ ಯಶಸ್ವಿಯಾಗುತ್ತದೆ ಮತ್ತು ಬ್ಯಾಲೆನ್ಸ್ 500 ಆಗುತ್ತದೆ.

myAccount.#balance = 1000000; // Error!

ಒಬ್ಬ ಹ್ಯಾಕರ್ ಅಥವಾ ಬೇರೊಬ್ಬ ವ್ಯಕ್ತಿ ನೇರವಾಗಿ ಅಕೌಂಟ್‌ಗೆ ಕನ್ನ ಹಾಕಿ ಬ್ಯಾಲೆನ್ಸ್ ಅನ್ನು 10 ಲಕ್ಷ ಮಾಡಲು ಪ್ರಯತ್ನಿಸಿದರೆ ಏನಾಗುತ್ತದೆ? ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ತಕ್ಷಣವೇ SyntaxError: Private field '#balance' must be declared in an enclosing class ಎಂಬ ಎರರ್ (Error) ಎಸೆಯುತ್ತದೆ. ಅಂದರೆ, "ನೀವು ಹೊರಗಿನಿಂದ ಈ ಖಾಸಗಿ ಲಾಕರ್ ಅನ್ನು ಮುಟ್ಟುವಂತಿಲ್ಲ!" ಎಂದು ಸಿಸ್ಟಮ್ ಬ್ಲಾಕ್ ಮಾಡುತ್ತದೆ.

ಎನ್ಕ್ಯಾಪ್ಸುಲೇಶನ್‌ನ ಪ್ರಮುಖ ಲಾಭಗಳು:
  1. ಡೇಟಾ ಸುರಕ್ಷತೆ (Data Protection): ಅಚಾನಕ್ಕಾಗಿ ಅಥವಾ ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಪ್ರಮುಖ ಡೇಟಾ ಹಾಳಾಗುವುದನ್ನು ತಡೆಯುತ್ತದೆ.
  2. ನಿಯಂತ್ರಣ (Validation): ಡೇಟಾ ಬದಲಾಗುವ ಮುನ್ನ ಅದು ಸರಿಯಾಗಿದೆಯೇ (ಉದಾಹರಣೆಗೆ ಋಣಾತ್ಮಕ ಮೌಲ್ಯ ಇಲ್ಲದಿರುವುದು) ಎಂದು ಪರೀಕ್ಷಿಸಲು ಅವಕಾಶ ನೀಡುತ್ತದೆ.
  3. ನಿರ್ವಹಣೆ ಸುಲಭ (Maintainability): ಕ್ಲಾಸ್‌ನ ಒಳಗಿನ ಕೋಡ್ ಅನ್ನು ನೀವು ಹೇಗೆ ಬೇಕಾದರೂ ಬದಲಾಯಿಸಬಹುದು, ಹೊರಗಿನಿಂದ ಆ ಕ್ಲಾಸ್ ಬಳಸುವವರಿಗೆ ಯಾವುದೇ ತೊಂದರೆಯಾಗುವುದಿಲ್ಲ.

3 Abstraction (ಅಬ್ಸ್ಟ್ರಾಕ್ಷನ್) - ಸಂಕೀರ್ಣತೆಯನ್ನು ಮುಚ್ಚಿಡುವುದು

ಸಾಮಾನ್ಯ (Non-Technical) ವಿವರಣೆ:

ನೀವು ಟಿವಿ ರಿಮೋಟ್‌ನಲ್ಲಿ 'Volume Up' ಬಟನ್ ಒತ್ತಿದಾಗ ಟಿವಿಯ ಶಬ್ದ ಹೆಚ್ಚಾಗುತ್ತದೆ. ರಿಮೋಟ್ ಒಳಗೆ ಯಾವ ಚಿಪ್ ಇದೆ, ಸಿಗ್ನಲ್ ಹೇಗೆ ಟಿವಿಗೆ ಹೋಗುತ್ತದೆ ಎಂಬ 'ತಲೆನೋವಿನ' ವಿಚಾರ ನಿಮಗೆ ಬೇಕಾಗಿಲ್ಲ. ನಿಮಗೆ ಕೇವಲ "ಬಟನ್ ಒತ್ತಿದರೆ ಕೆಲಸ ಆಗಬೇಕು" ಅಷ್ಟೇ.

ತಾಂತ್ರಿಕ (Technical) ವಿವರಣೆ:

ಬಳಕೆದಾರರಿಗೆ ಕೇವಲ ಅಗತ್ಯವಿರುವ ಫೀಚರ್‌ಗಳನ್ನು ಮಾತ್ರ ತೋರಿಸಿ, ಹಿನ್ನೆಲೆಯಲ್ಲಿ ನಡೆಯುವ ಕಷ್ಟಕರವಾದ ಕೋಡಿಂಗ್ ಲಾಜಿಕ್ ಅನ್ನು ಮುಚ್ಚಿಡುವುದೇ Abstraction.


class CoffeeMachine {
  // ಇವೆಲ್ಲಾ ಯಂತ್ರದ ಒಳಗಿನ ಕೆಲಸಗಳು (Private)
  #boilWater() {
    console.log("1. ನೀರು ಕಾಯಿಸುತ್ತಿದೆ...");
  }
  
  #grindBeans() {
    console.log("2. ಕಾಫಿ ಬೀಜ ಪುಡಿ ಮಾಡುತ್ತಿದೆ...");
  }
 
  // ಬಳಕೆದಾರನಿಗೆ ಕಾಣುವ ಒಂದೇ ಒಂದು ಸುಲಭವಾದ ಬಟನ್ (Public)
  makeCoffee() {
    this.#boilWater();
    this.#grindBeans();
    console.log("☕ ನಿಮ್ಮ ಕಾಫಿ ರೆಡಿ ಇದೆ!");
  }
}
 
const myMachine = new CoffeeMachine();
myMachine.makeCoffee(); // ಬಳಕೆದಾರ ಕೇವಲ ಮೇಕ್ ಕಾಫಿ ಬಟನ್ ಒತ್ತುತ್ತಾನೆ ಅಷ್ಟೇ.

(ನೀವು ನೀಡಿರುವ ಟಿವಿ ರಿಮೋಟ್ ಮತ್ತು ಕಾಫಿ ಮಷೀನ್ ಉದಾಹರಣೆಗಳು ಅಬ್ಸ್ಟ್ರಾಕ್ಷನ್ (Abstraction) ಅನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಅತ್ಯುತ್ತಮವಾಗಿವೆ!)
ಎನ್ಕ್ಯಾಪ್ಸುಲೇಶನ್ (Encapsulation) ಎಂದರೆ "ಭದ್ರತೆ" (Security) ನೀಡುವ ಉದ್ದೇಶವಾದರೆ, ಅಬ್ಸ್ಟ್ರಾಕ್ಷನ್ ಉದ್ದೇಶ "ಸಂಕೀರ್ಣತೆಯನ್ನು ಕಡಿಮೆ ಮಾಡುವುದು" (Simplicity). ಇದನ್ನು ಕೋಡ್‌ನ ಮೂಲಕ ಹಂತ-ಹಂತವಾಗಿ ಬಿಡಿಸಿ ನೋಡೋಣ:

1. ಒಳಗಿನ ಸಂಕೀರ್ಣ ಪ್ರಕ್ರಿಯೆಗಳು (Private Methods)

  #boilWater() { ... }
  #grindBeans() { ... }

ಇಲ್ಲಿ ಕಾಫಿ ಮಾಡುವ ಹಿಂದಿನ ನಿಜವಾದ ಪ್ರಕ್ರಿಯೆಗಳನ್ನು (ನೀರು ಕಾಯಿಸುವುದು, ಬೀಜ ಪುಡಿ ಮಾಡುವುದು) # (ಹ್ಯಾಶ್) ಬಳಸಿ ಖಾಸಗಿ (Private) ಮಾಡಲಾಗಿದೆ.

  • ಕಾಫಿ ಮಷೀನ್ ಬಳಸುವವನಿಗೆ (User) ಯಂತ್ರದ ಒಳಗೆ ನೀರು ಎಷ್ಟು ಡಿಗ್ರಿಗೆ ಕಾಯುತ್ತಿದೆ, ಬೀಜ ಎಷ್ಟು ನುಣ್ಣಗೆ ಪುಡಿಯಾಗುತ್ತಿದೆ ಎಂಬ ತಾಂತ್ರಿಕ ವಿಚಾರಗಳು ಬೇಕಾಗಿಲ್ಲ.
  • ಅಲ್ಲದೆ, ಬಳಕೆದಾರ ನೇರವಾಗಿ myMachine.#boilWater() ಎಂದು ಕರೆದು ಯಂತ್ರದ ಕ್ರಮವನ್ನು ಕೆಡಿಸುವಂತಿಲ್ಲ.

2. ಬಳಕೆದಾರನಿಗೆ ಕಾಣುವ ಏಕೈಕ ಬಟನ್ (Public Method)

  makeCoffee() {
    this.#boilWater();
    this.#grindBeans();
    console.log("☕ ನಿಮ್ಮ ಕಾಫಿ ರೆಡಿ ಇದೆ!");
  }

ಇದು ಕಾಫಿ ಮಷೀನ್ ಮೇಲಿರುವ ಒಂದೇ ಒಂದು ಸುಲಭವಾದ ಬಟನ್.

  • ಬಳಕೆದಾರ ಈ ಬಟನ್ ಒತ್ತಿದ ತಕ್ಷಣ, ಅದು ಹಿನ್ನೆಲೆಯಲ್ಲಿ this.#boilWater() ಮತ್ತು this.#grindBeans() ಅನ್ನು ತಾನೇ ತಾನಾಗಿ, ಸರಿಯಾದ ಕ್ರಮದಲ್ಲಿ ರನ್ ಮಾಡುತ್ತದೆ.
  • ಬಳಕೆದಾರನಿಗೆ ಕೇವಲ ಅಂತಿಮ ಫಲಿತಾಂಶ (ಕಾಫಿ) ಮಾತ್ರ ಸಿಗುತ್ತದೆ.

3. ಯಂತ್ರವನ್ನು ಬಳಸುವುದು (Execution)

const myMachine = new CoffeeMachine();
myMachine.makeCoffee();

ಇಲ್ಲಿ ನೀವು ಹೊಸ ಕಾಫಿ ಮಷೀನ್ ತಂದು, ಕೇವಲ makeCoffee() ಬಟನ್ ಒತ್ತುತ್ತೀರಿ ಅಷ್ಟೇ. ಒಂದು ವೇಳೆ ನೀವು, myMachine.#grindBeans(); ಎಂದು ಹೊರಗಿನಿಂದ ಕರೆಯಲು ಪ್ರಯತ್ನಿಸಿದರೆ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಎರರ್ (Error) ಕೊಡುತ್ತದೆ. ಏಕೆಂದರೆ ಆ ಬಟನ್ ಯಂತ್ರದ ಒಳಗಿದೆ, ಹೊರಗಿನವರಿಗೆ ಅದು ಕಾಣಿಸುವುದಿಲ್ಲ.

ಎನ್ಕ್ಯಾಪ್ಸುಲೇಶನ್ ಮತ್ತು ಅಬ್ಸ್ಟ್ರಾಕ್ಷನ್ ನಡುವಿನ ವ್ಯತ್ಯಾಸವೇನು? (ಸಣ್ಣ ಗೊಂದಲ ನಿವಾರಣೆ)
ಬಹಳಷ್ಟು ಜನರಿಗೆ ಇವೆರಡೂ ಒಂದೇ ಎನಿಸುತ್ತದೆ, ಆದರೆ ಸಣ್ಣ ವ್ಯತ್ಯಾಸವಿದೆ:
  • Encapsulation (ಎನ್ಕ್ಯಾಪ್ಸುಲೇಶನ್): ಇದು ಡೇಟಾವನ್ನು ಬಚ್ಚಿಡುತ್ತದೆ (ಉದಾಹರಣೆಗೆ: ಬ್ಯಾಂಕ್ ಬ್ಯಾಲೆನ್ಸ್ ಯಾರೂ ಕದಿಯಬಾರದು/ಬದಲಾಯಿಸಬಾರದು ಎಂದು). ಗುರಿ: ಭದ್ರತೆ.
  • Abstraction (ಅಬ್ಸ್ಟ್ರಾಕ್ಷನ್): ಇದು ಕೆಲಸದ ಸಂಕೀರ್ಣತೆಯನ್ನು ಬಚ್ಚಿಡುತ್ತದೆ (ಉದಾಹರಣೆಗೆ: ಕಾಫಿ ಮಷೀನ್ ಒಳಗೆ ಏನೇನೋ ವೈರ್‌ಗಳಿವೆ, ಅದರಿಂದ ಕನ್ಫ್ಯೂಸ್ ಆಗಬಾರದು ಎಂದು ಕೇವಲ ಒಂದೇ ಬಟನ್ ಕೊಡುವುದು). ಗುರಿ: ಸುಲಭವಾದ ಬಳಕೆ.
ಅಬ್ಸ್ಟ್ರಾಕ್ಷನ್‌ನ ಪ್ರಮುಖ ಲಾಭಗಳು:
  1. ಬಳಸಲು ಸುಲಭ (User Friendly): ಕೋಡ್‌ನ ಒಳಗೆ ಸಾವಿರಾರು ಸಾಲುಗಳಿದ್ದರೂ, ಅದನ್ನು ಬಳಸುವ ಬೇರೆ ಡೆವಲಪರ್‌ಗಳಿಗೆ ಕೇವಲ 1-2 ಸರಳ ಫಂಕ್ಷನ್‌ಗಳನ್ನಷ್ಟೇ ನೀಡಿದರೆ ಸಾಕು.
  2. ಸುಲಭವಾದ ಅಪ್‌ಗ್ರೇಡ್ (Easy Maintenance): ನಾಳೆ ನೀವು ಕಾಫಿ ಮಷೀನ್‌ನ ಒಳಗಿನ ಹೀಟರ್ (Heater) ಬದಲಾಯಿಸಿ ಹೊಸ ಕೋಡ್ ಬರೆದರೂ, ಗ್ರಾಹಕನಿಗೆ ಯಾವ ತೊಂದರೆಯೂ ಆಗುವುದಿಲ್ಲ. ಅವನು ಮೊದಲಿನಂತೆಯೇ makeCoffee() ಬಟನ್ ಒತ್ತುತ್ತಾನೆ, ಕಾಫಿ ಬರುತ್ತದೆ!

4 Inheritance (ಇನ್ಹೆರಿಟೆನ್ಸ್) - ಆನುವಂಶಿಕತೆ

ಸಾಮಾನ್ಯ (Non-Technical) ವಿವರಣೆ:

ಒಬ್ಬ ಮಗ ತನ್ನ ತಂದೆಯ ಕೆಲವು ಗುಣಗಳನ್ನು (ಉದಾ: ಕಣ್ಣಿನ ಬಣ್ಣ, ಎತ್ತರ) ಹುಟ್ಟಿನಿಂದಲೇ ಪಡೆಯುತ್ತಾನೆ. ಜೊತೆಗೆ ಮಗ ತನ್ನದೇ ಆದ ಹೊಸ ಗುಣಗಳನ್ನು (ಉದಾ: ಗಿಟಾರ್ ನುಡಿಸುವುದು) ಕೂಡ ಕಲಿಯಬಹುದು. ಹಾಗೆಯೇ, ಹಳೆಯ ಸಾಮಾನ್ಯ ಫೋನ್‌ನ ಎಲ್ಲಾ ಗುಣಗಳನ್ನು 'ಸ್ಮಾರ್ಟ್ ಫೋನ್' ಪಡೆದುಕೊಂಡು, ಕ್ಯಾಮೆರಾ ಎಂಬ ಹೊಸ ಗುಣವನ್ನು ಸೇರಿಸಿಕೊಳ್ಳುತ್ತದೆ.

ತಾಂತ್ರಿಕ (Technical) ವಿವರಣೆ:

ಒಂದು ಹಳೆಯ ಕ್ಲಾಸ್‌ನ (Parent Class) ಎಲ್ಲಾ ಕೋಡ್ ಮತ್ತು ಫಂಕ್ಷನ್‌ಗಳನ್ನು ಹೊಸ ಕ್ಲಾಸ್ (Child Class) ಮರುಬಳಕೆ ಮಾಡುವುದಕ್ಕೆ Inheritance ಎನ್ನುತ್ತಾರೆ. ಇದಕ್ಕೆ ES6 ನಲ್ಲಿ extends ಮತ್ತು super() ಎಂಬ ಪದಗಳನ್ನು ಬಳಸುತ್ತೇವೆ.

Animal (Parent)
name, eat()
Dog (Child)
breed, bark() + Inherits from Animal

// ತಂದೆ ಕ್ಲಾಸ್ (Parent)
class Animal {
  constructor(name) {
    this.name = name;
  }
  eat() {
    console.log(`${this.name} ಊಟ ಮಾಡುತ್ತಿದೆ.`);
  }
}
 
// ಮಗ ಕ್ಲಾಸ್ (Child) - Animal ಕ್ಲಾಸ್‌ನ ಗುಣಗಳನ್ನು ಪಡೆಯುತ್ತಿದೆ
class Dog extends Animal {
  constructor(name, breed) {
    super(name); // ತಂದೆ ಕ್ಲಾಸ್‌ನ constructor ಅನ್ನು ಕರೆಯುವುದು
    this.breed = breed;
  }
  
  // ಮಗನ ಸ್ವಂತ ಗುಣ
  bark() {
    console.log(`${this.name} ಬೊಗಳುತ್ತಿದೆ! (ಬ್ರೀಡ್: ${this.breed})`);
  }
}
 
const myDog = new Dog("ಚಾರ್ಲಿ", "ಲ್ಯಾಬ್ರಡಾರ್");
myDog.eat();  // Animal ಕ್ಲಾಸ್‌ನಿಂದ ಬಂದ ಗುಣ
myDog.bark(); // Dog ಕ್ಲಾಸ್‌ನ ಸ್ವಂತ ಗುಣ

(ನೀವು ನೀಡಿರುವ ತಂದೆ-ಮಗ ಮತ್ತು ಹಳೆಯ ಫೋನ್-ಸ್ಮಾರ್ಟ್ ಫೋನ್ ಉದಾಹರಣೆಗಳು ಇನ್ಹೆರಿಟೆನ್ಸ್ (Inheritance) ಅನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಬಹಳ ನಿಖರ ಮತ್ತು ಆಕರ್ಷಕವಾಗಿವೆ!)
ಈ ಕೋಡ್ ಅನ್ನು ಇನ್ನಷ್ಟು ಸರಳವಾಗಿ ಹಂತ-ಹಂತವಾಗಿ ಬಿಡಿಸಿ ನೋಡೋಣ. ಇಲ್ಲಿ extends ಮತ್ತು super ಎಂಬ ಎರಡು ಹೊಸ ಪದಗಳೇ ಈ ಕಾನ್ಸೆಪ್ಟ್‌ನ "ಹೀರೋಗಳು".

1. ತಂದೆ ಕ್ಲಾಸ್ (Parent / Base Class)

class Animal {
  constructor(name) {
    this.name = name;
  }
  eat() { ... }
}

ಇದು ಮೂಲ ಕ್ಲಾಸ್. ಜಗತ್ತಿನ ಎಲ್ಲಾ ಪ್ರಾಣಿಗಳಿಗೂ ಅನ್ವಯವಾಗುವ ಸಾಮಾನ್ಯ ಗುಣಗಳನ್ನು (ಉದಾಹರಣೆಗೆ: ಹೆಸರು ಇರುವುದು, ಊಟ ಮಾಡುವುದು) ಇಲ್ಲಿ ಬರೆಯಲಾಗಿದೆ.

2. extends ಕೀವರ್ಡ್‌ನ ಕೆಲಸ (ಗುಣಗಳನ್ನು ಎರವಲು ಪಡೆಯುವುದು)

class Dog extends Animal { ... }

ಇಲ್ಲಿ extends ಎಂದರೆ "ವಿಸ್ತರಿಸು" ಅಥವಾ "ಅದರಿಂದ ಪಡೆದುಕೋ" ಎಂದರ್ಥ.

  • ಈ ಒಂದು ಪದ ಬರೆಯುವುದರಿಂದ, Animal ಕ್ಲಾಸ್‌ನಲ್ಲಿದ್ದ name ಮತ್ತು eat() ಎಂಬ ಎರಡು ಗುಣಗಳು ತಾನೇ ತಾನಾಗಿ Dog ಕ್ಲಾಸ್‌ಗೆ ಬಂದುಬಿಡುತ್ತವೆ.
  • ನಾವು ನಾಯಿಗಾಗಿ ಮತ್ತೆ ಹೊಸದಾಗಿ eat() ಫಂಕ್ಷನ್ ಬರೆಯುವ ಅಗತ್ಯವಿಲ್ಲ. ಇದು ಕೋಡ್ ಬರೆಯುವ ಸಮಯವನ್ನು ಉಳಿಸುತ್ತದೆ.

3. super() ಕೀವರ್ಡ್‌ನ ಹಿಂದಿನ ಮ್ಯಾಜಿಕ್
ಇದು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಬಹಳ ಮುಖ್ಯವಾದ ನಿಯಮ:

  constructor(name, breed) {
    super(name); 
    this.breed = breed;
  }
  • ಮಗ ಕ್ಲಾಸ್ (Dog) ಒಳಗೆ ನೀವು ಹೊಸದಾಗಿ constructor ಬರೆದಾಗ, ತಂದೆ ಕ್ಲಾಸ್‌ನ (Animal) constructor ಅನ್ನು ಕರೆಯುವುದು ಕಡ್ಡಾಯ.
  • super(name) ಎಂದು ಕರೆದಾಗ, ಅದು Animal ಕ್ಲಾಸ್‌ಗೆ ಹೋಗಿ ನಾಯಿಯ ಹೆಸರನ್ನು (name) ಸೆಟ್ ಮಾಡಿ ಬರುತ್ತದೆ.
  • ನೆನಪಿಡಿ: super() ಅನ್ನು ಕರೆಯದೆ ನೀವು this.breed ಎಂದು ಬಳಸಲು ಹೋದರೆ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ದೊಡ್ಡ ಎರರ್ (Error) ಕೊಡುತ್ತದೆ. ತಂದೆಗೆ ನಮಸ್ಕರಿಸಿದ ಮೇಲೆಯೇ ಮಗನ ಕೆಲಸ ಶುರು!

4. ಮಗನ ಸ್ವಂತ ಗುಣ (Child's Specific Method)

  bark() { ... }

ಇದು ಕೇವಲ Dog ಕ್ಲಾಸ್‌ಗೆ ಮಾತ್ರ ಸೀಮಿತವಾದ ಫಂಕ್ಷನ್. ಎಲ್ಲಾ ಪ್ರಾಣಿಗಳು ಬೊಗಳುವುದಿಲ್ಲ, ಹಾಗಾಗಿ ಇದನ್ನು Animal ಕ್ಲಾಸ್‌ನಲ್ಲಿ ಹಾಕದೆ, ಕೇವಲ Dog ಕ್ಲಾಸ್‌ನಲ್ಲಿ ಹಾಕಲಾಗಿದೆ.

5. ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ಬಳಸುವುದು (Execution)

const myDog = new Dog("ಚಾರ್ಲಿ", "ಲ್ಯಾಬ್ರಡಾರ್");
myDog.eat();  // ಔಟ್‌ಪುಟ್: ಚಾರ್ಲಿ ಊಟ ಮಾಡುತ್ತಿದೆ.
myDog.bark(); // ಔಟ್‌ಪುಟ್: ಚಾರ್ಲಿ ಬೊಗಳುತ್ತಿದೆ! (ಬ್ರೀಡ್: ಲ್ಯಾಬ್ರಡಾರ್)

ನಾವಿಲ್ಲಿ Dog ಕ್ಲಾಸ್‌ನಲ್ಲಿ eat() ಫಂಕ್ಷನ್ ಬರೆಯದಿದ್ದರೂ, ಅದು Animal ನಿಂದ ಆನುವಂಶಿಕವಾಗಿ ಬಂದಿರುವುದರಿಂದ ಯಾವುದೇ ತೊಂದರೆಯಿಲ್ಲದೆ ಕೆಲಸ ಮಾಡುತ್ತದೆ. bark() ನಾಯಿಯ ತನ್ನದೇ ಆದ ಸ್ವಂತ ಗುಣ.

ಇನ್ಹೆರಿಟೆನ್ಸ್‌ನ ಪ್ರಮುಖ ಲಾಭಗಳು:
  1. ಕೋಡ್ ಮರುಬಳಕೆ (Code Reusability): ಒಂದೇ ಕೋಡ್ ಅನ್ನು ಪದೇ ಪದೇ ಬರೆಯುವ ಬದಲು (DRY Principle - Don't Repeat Yourself), ಒಮ್ಮೆ ಬರೆದು ಬೇರೆ ಕ್ಲಾಸ್‌ಗಳಲ್ಲಿ ಮರುಬಳಕೆ ಮಾಡಬಹುದು.
  2. ಸಮಯ ಮತ್ತು ಶ್ರಮದ ಉಳಿತಾಯ: ನಾಳೆ ನೀವು Cat (ಬೆಕ್ಕು) ಎಂಬ ಹೊಸ ಕ್ಲಾಸ್ ಬರೆದರೆ, ಅದಕ್ಕೂ class Cat extends Animal ಎಂದು ಸುಲಭವಾಗಿ ಬರೆದು ಮುಗಿಸಬಹುದು.
  3. ನಿರ್ವಹಣೆ (Maintenance): ನಾಳೆ ಎಲ್ಲಾ ಪ್ರಾಣಿಗಳು sleep() (ನಿದ್ದೆ ಮಾಡು) ಎಂಬ ಫಂಕ್ಷನ್ ಹೊಂದಿರಬೇಕು ಎಂದರೆ, ಕೇವಲ ಒಮ್ಮೆ Animal ಕ್ಲಾಸ್‌ನಲ್ಲಿ ಸೇರಿಸಿದರೆ ಸಾಕು, ಅದು ನಾಯಿ, ಬೆಕ್ಕು ಎಲ್ಲದಕ್ಕೂ ತಾನೇ ಅನ್ವಯವಾಗುತ್ತದೆ.

5 Polymorphism (ಪಾಲಿಮಾರ್ಫಿಸಂ) - ಒಂದೇ ಹೆಸರು, ಹಲವು ರೂಪಗಳು

ಸಾಮಾನ್ಯ (Non-Technical) ವಿವರಣೆ:

ನೀರು (Water) ಒಂದೇ ವಸ್ತು. ಆದರೆ ಅದು ಫ್ರಿಡ್ಜ್‌ನಲ್ಲಿಟ್ಟರೆ ಮಂಜುಗಡ್ಡೆ (ಘನ) ಆಗುತ್ತದೆ, ಬಿಸಿ ಮಾಡಿದರೆ ಹಬೆ (ಅನಿಲ) ಆಗುತ್ತದೆ, ಕುಡಿಯುವಾಗ ದ್ರವರೂಪದಲ್ಲಿ ಇರುತ್ತದೆ. ಸನ್ನಿವೇಶಕ್ಕೆ ತಕ್ಕಂತೆ ಅದು ಬೇರೆ ಬೇರೆ ರೀತಿ ವರ್ತಿಸುತ್ತದೆ.

ತಾಂತ್ರಿಕ (Technical) ವಿವರಣೆ:

ಬೇರೆ ಬೇರೆ ಕ್ಲಾಸ್‌ಗಳಲ್ಲಿ ಒಂದೇ ಹೆಸರಿನ ಫಂಕ್ಷನ್ (Method) ಇದ್ದರೂ, ಅವು ಬೇರೆ ಬೇರೆ ರೀತಿ ಕೆಲಸ ಮಾಡುವುದಕ್ಕೆ Polymorphism (Method Overriding) ಎನ್ನುತ್ತಾರೆ. ಚೈಲ್ಡ್ ಕ್ಲಾಸ್ ತಂದೆಯ ಕ್ಲಾಸ್‌ನ ಫಂಕ್ಷನ್ ಅನ್ನು ಅಳಿಸಿ ತನ್ನದೇ ಆದ ಹೊಸ ನಿಯಮ ಬರೆಯಬಹುದು.


class Bird {
  fly() {
    console.log("ಹಕ್ಕಿ ಆಕಾಶದಲ್ಲಿ ಹಾರುತ್ತಿದೆ.");
  }
}
 
// ಪೆಂಗ್ವಿನ್ ಕೂಡ ಒಂದು ಹಕ್ಕಿಯೇ, ಆದರೆ ಅದು ಹಾರುವುದಿಲ್ಲ!
class Penguin extends Bird {
  // ತಂದೆ ಕ್ಲಾಸ್‌ನ fly() ಫಂಕ್ಷನ್ ಅನ್ನು ಬದಲಾಯಿಸುತ್ತಿದ್ದೇವೆ (Overriding)
  fly() {
    console.log("ಪೆಂಗ್ವಿನ್ ಹಾರಲು ಸಾಧ್ಯವಿಲ್ಲ, ಆದರೆ ನೀರಿನಲ್ಲಿ ಈಜಬಲ್ಲದು!");
  }
}
 
const normalBird = new Bird();
normalBird.fly(); // ಔಟ್‌ಪುಟ್: ಹಕ್ಕಿ ಆಕಾಶದಲ್ಲಿ ಹಾರುತ್ತಿದೆ.
 
const myPenguin = new Penguin();
myPenguin.fly(); // ಔಟ್‌ಪುಟ್: ಪೆಂಗ್ವಿನ್ ಹಾರಲು ಸಾಧ್ಯವಿಲ್ಲ, ಆದರೆ ನೀರಿನಲ್ಲಿ ಈಜಬಲ್ಲದು!

(ನೀರು ಮತ್ತು ಮಂಜುಗಡ್ಡೆಯ ಉದಾಹರಣೆ ನಿಜಕ್ಕೂ ಅದ್ಭುತವಾಗಿದೆ!)
ಪಾಲಿಮಾರ್ಫಿಸಂ (Polymorphism) ಎಂಬ ಪದವು ಗ್ರೀಕ್ ಭಾಷೆಯಿಂದ ಬಂದಿದೆ: 'ಪಾಲಿ' (Poly) ಎಂದರೆ 'ಹಲವು' (Many) ಮತ್ತು 'ಮಾರ್ಫ್' (Morph) ಎಂದರೆ 'ರೂಪಗಳು' (Forms). ಹೆಸರೇ ಹೇಳುವಂತೆ "ಒಂದೇ ಹೆಸರು, ಹಲವು ರೂಪಗಳು".
ಇದನ್ನು ತಾಂತ್ರಿಕವಾಗಿ ಹಂತ-ಹಂತವಾಗಿ ಬಿಡಿಸಿ ನೋಡೋಣ:

1. ಮೂಲ ರೂಪ (Base Method)

class Bird {
  fly() {
    console.log("ಹಕ್ಕಿ ಆಕಾಶದಲ್ಲಿ ಹಾರುತ್ತಿದೆ.");
  }
}

ಇಲ್ಲಿ ಜಗತ್ತಿನ ಬಹುತೇಕ ಹಕ್ಕಿಗಳಿಗೆ ಅನ್ವಯವಾಗುವ ಒಂದು ಸಾಮಾನ್ಯ ನಿಯಮವನ್ನು (fly) ಬರೆಯಲಾಗಿದೆ.

2. ನಿಯಮವನ್ನು ಬದಲಾಯಿಸುವುದು (Method Overriding)

class Penguin extends Bird {
  fly() {
    console.log("ಪೆಂಗ್ವಿನ್ ಹಾರಲು ಸಾಧ್ಯವಿಲ್ಲ, ಆದರೆ ನೀರಿನಲ್ಲಿ ಈಜಬಲ್ಲದು!");
  }
}

ಪೆಂಗ್ವಿನ್ ಕೂಡ ಒಂದು ಹಕ್ಕಿಯೇ (extends Bird), ಆದರೆ ಅದಕ್ಕೆ ಹಾರಲು ಬರುವುದಿಲ್ಲ. ಹೀಗಿರುವಾಗ ತಂದೆ ಕ್ಲಾಸ್‌ನ (Bird) ನಿಯಮವನ್ನು ಹಾಗೆಯೇ ಉಳಿಸಿಕೊಂಡರೆ ಅದು ತಪ್ಪಾಗುತ್ತದೆ.

  • ಅದಕ್ಕಾಗಿ Penguin ಕ್ಲಾಸ್ ಒಳಗೆ ಅದೇ ಹೆಸರಿನ (fly) ಹೊಸ ಫಂಕ್ಷನ್ ಬರೆದು ಹಳೆಯ ನಿಯಮವನ್ನು ಅಳಿಸಿಹಾಕಲಾಗಿದೆ.
  • ಹಳೆಯ ಫಂಕ್ಷನ್ ಅನ್ನು ಮರೆಮಾಚಿ ಹೊಸದಾಗಿ ಬರೆಯುವ ಈ ಪ್ರಕ್ರಿಯೆಗೆ ತಾಂತ್ರಿಕವಾಗಿ "ಮೆಥಡ್ ಓವರ್‌ರೈಡಿಂಗ್" (Method Overriding) ಎನ್ನುತ್ತಾರೆ.

3. ಸನ್ನಿವೇಶಕ್ಕೆ ತಕ್ಕಂತೆ ವರ್ತನೆ (Execution)

const normalBird = new Bird();
normalBird.fly();

ಇಲ್ಲಿ ಕಾಗೆ ಅಥವಾ ಗುಬ್ಬಚ್ಚಿಯಂತಹ ಸಾಮಾನ್ಯ ಹಕ್ಕಿ ಇರುವುದರಿಂದ, ಆಬ್ಜೆಕ್ಟ್ ಆಕಾಶದಲ್ಲಿ ಹಾರುವ ನಿಯಮವನ್ನು ಪಾಲಿಸುತ್ತದೆ.

const myPenguin = new Penguin();
myPenguin.fly();

ಇಲ್ಲಿ ಕಂಪ್ಯೂಟರ್‌ಗೆ ಗೊತ್ತು, "ಇದು ಪೆಂಗ್ವಿನ್ ಆಬ್ಜೆಕ್ಟ್, ಇದು ಸಾಮಾನ್ಯ ಹಕ್ಕಿಯಲ್ಲ" ಎಂದು. ಆದ್ದರಿಂದ ಅದು ಮೂಲ Bird ಕ್ಲಾಸ್‌ನ fly ಅನ್ನು ನಿರ್ಲಕ್ಷಿಸಿ, Penguin ಕ್ಲಾಸ್‌ನಲ್ಲಿರುವ ವಿಶೇಷ fly ನಿಯಮವನ್ನು ಮಾತ್ರ ರನ್ ಮಾಡುತ್ತದೆ.

ಪಾಲಿಮಾರ್ಫಿಸಂನ ಪ್ರಮುಖ ಲಾಭಗಳೇನು?
  1. ಹೆಸರುಗಳನ್ನು ನೆನಪಿಟ್ಟುಕೊಳ್ಳುವುದು ಸುಲಭ (Consistent Interface): ನೀವು flyForNormalBird(), swimForPenguin(), runForOstrich() ಎಂದು ನೂರಾರು ಬೇರೆ ಬೇರೆ ಫಂಕ್ಷನ್ ಹೆಸರುಗಳನ್ನು ನೆನಪಿಟ್ಟುಕೊಳ್ಳುವ ಅಗತ್ಯವಿಲ್ಲ. ಎಲ್ಲದಕ್ಕೂ ಕೇವಲ action() ಅಥವಾ fly() ಎಂದು ಒಂದೇ ಹೆಸರಿಡಬಹುದು. ಯಾವ ಹಕ್ಕಿ ಎಂಬುದರ ಆಧಾರದ ಮೇಲೆ ಅದು ತನ್ನ ಕೆಲಸವನ್ನು ತಾನೇ ಬದಲಾಯಿಸಿಕೊಳ್ಳುತ್ತದೆ.
  2. ಹೊಂದಿಕೊಳ್ಳುವಿಕೆ (Flexibility): ಭವಿಷ್ಯದಲ್ಲಿ ನೀವು 'Ostrich' (ಉಷ್ಟ್ರಪಕ್ಷಿ) ಎಂಬ ಹೊಸ ಕ್ಲಾಸ್ ಬರೆದರೆ, ಅದಕ್ಕೂ fly() ಎಂಬ ಹೆಸರನ್ನೇ ಬಳಸಿ "ಉಷ್ಟ್ರಪಕ್ಷಿ ಓಡುತ್ತದೆ" ಎಂದು ಸುಲಭವಾಗಿ ಓವರ್‌ರೈಡ್ ಮಾಡಬಹುದು. ಮೂಲ Bird ಕ್ಲಾಸ್‌ಗೆ ಯಾವುದೇ ತೊಂದರೆ ಆಗುವುದಿಲ್ಲ.
(ಹೆಚ್ಚುವರಿ ಮಾಹಿತಿ: ನಿಮ್ಮ ಈ ಐದೂ ಉದಾಹರಣೆಗಳು (Class & Object, Encapsulation, Abstraction, Inheritance, Polymorphism) Object-Oriented Programming (OOP) ನ ಪಂಚಸೂತ್ರಗಳನ್ನು ಅತ್ಯಂತ ಸರಳವಾಗಿ ಮತ್ತು ಪರಿಣಾಮಕಾರಿಯಾಗಿ ವಿವರಿಸಿವೆ. ಇವೆಲ್ಲವೂ ಒಟ್ಟಾಗಿ ಸೇರಿದರೆ ಎಂತಹ ದೊಡ್ಡ ಹಾಗೂ ಜಟಿಲವಾದ ಸಾಫ್ಟ್‌ವೇರ್ ಅಪ್ಲಿಕೇಶನ್‌ಗಳನ್ನಾದರೂ ಅತ್ಯಂತ ವ್ಯವಸ್ಥಿತವಾಗಿ ನಿರ್ಮಿಸಲು ಸಾಧ್ಯವಾಗುತ್ತದೆ!)

6 Static Methods ಮತ್ತು Properties (ಸ್ಟ್ಯಾಟಿಕ್) - ಕ್ಲಾಸ್‌ನ ಸ್ವಂತ ಸ್ವತ್ತು

ಸಾಮಾನ್ಯ (Non-Technical) ವಿವರಣೆ:

ಒಂದು ಶಾಲೆಯಲ್ಲಿ ಸಾವಿರ ವಿದ್ಯಾರ್ಥಿಗಳಿರಬಹುದು. ಪ್ರತಿಯೊಬ್ಬ ವಿದ್ಯಾರ್ಥಿಗೂ ಬೇರೆ ಬೇರೆ ಹೆಸರು, ರೋಲ್ ನಂಬರ್ ಇರುತ್ತದೆ (ಇದು Object ನ ಗುಣ). ಆದರೆ, ಆ "ಶಾಲೆಯ ಹೆಸರು" ಅಥವಾ "ಶಾಲೆಯ ಒಟ್ಟು ವಿದ್ಯಾರ್ಥಿಗಳ ಸಂಖ್ಯೆ" ಎಲ್ಲರಿಗೂ ಒಂದೇ ಆಗಿರುತ್ತದೆ. ಅದನ್ನು ಪ್ರತಿ ವಿದ್ಯಾರ್ಥಿಯ ತಲೆಮೇಲೆ ಬರೆಯುವ ಬದಲು, ಶಾಲೆಯ ಬೋರ್ಡ್ ಮೇಲೆ ಬರೆಯಲಾಗುತ್ತದೆ (ಇದು Class ನ ಗುಣ).

ತಾಂತ್ರಿಕ (Technical) ವಿವರಣೆ:

ಯಾವುದೇ ಮೆಥಡ್ ಅಥವಾ ವೇರಿಯೇಬಲ್ ಅನ್ನು static ಕೀವರ್ಡ್ ಬಳಸಿ ಬರೆದರೆ, ಅದು ನೇರವಾಗಿ Class ಗೆ ಸೇರುತ್ತದೆಯೇ ಹೊರತು Object ಗೆ ಅಲ್ಲ. ಅಂದರೆ, ನೀವು new ಕೀವರ್ಡ್ ಬಳಸಿ ಸೃಷ್ಟಿಸಿದ ಆಬ್ಜೆಕ್ಟ್‌ನಿಂದ ಇದನ್ನು ಕರೆಯಲು ಸಾಧ್ಯವಿಲ್ಲ. ನೇರವಾಗಿ ಕ್ಲಾಸ್ ಹೆಸರಿನಿಂದಲೇ ಕರೆಯಬೇಕು.


class Calculator {
  // ಇದು Static ಮೆಥಡ್ (ಕ್ಲಾಸ್‌ಗೆ ಮಾತ್ರ ಸೇರಿದ್ದು)
  static add(a, b) {
    return a + b;
  }
 
  // ಇದು ಸಾಮಾನ್ಯ ಮೆಥಡ್ (ಆಬ್ಜೆಕ್ಟ್‌ಗೆ ಸೇರಿದ್ದು)
  multiply(a, b) {
    return a * b;
  }
}
 
// 1. Static ಮೆಥಡ್ ಅನ್ನು ಕರೆಯುವುದು (ನೇರವಾಗಿ ಕ್ಲಾಸ್ ಹೆಸರಿನಿಂದ)
console.log(Calculator.add(5, 10)); // ಔಟ್‌ಪುಟ್: 15
 
// 2. ಸಾಮಾನ್ಯ ಮೆಥಡ್ ಕರೆಯುವುದು (ಆಬ್ಜೆಕ್ಟ್ ಸೃಷ್ಟಿಸಲೇಬೇಕು)
const myCalc = new Calculator();
console.log(myCalc.multiply(5, 10)); // ಔಟ್‌ಪುಟ್: 50
 
// myCalc.add(5, 10); // Error! ಏಕೆಂದರೆ add() ಆಬ್ಜೆಕ್ಟ್‌ಗೆ ಸೇರಿಲ್ಲ.

ಶಾಲೆಯ ಬೋರ್ಡ್ ಮತ್ತು ವಿದ್ಯಾರ್ಥಿಗಳ ಉದಾಹರಣೆ ನಿಜಕ್ಕೂ ಅತ್ಯದ್ಭುತವಾಗಿದೆ! ಇದು ಸ್ಟ್ಯಾಟಿಕ್ (Static) ಪರಿಕಲ್ಪನೆಯನ್ನು ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ನೀಡಬಹುದಾದ ಅತ್ಯುತ್ತಮ ಮತ್ತು ಸರಳವಾದ ಉದಾಹರಣೆ.
ಈಗ ನೀವು ನೀಡಿರುವ ಕೋಡ್ ಅನ್ನು ತಾಂತ್ರಿಕವಾಗಿ ಹಂತ-ಹಂತವಾಗಿ ಬಿಡಿಸಿ ನೋಡೋಣ:

1. ಸ್ಟ್ಯಾಟಿಕ್ ಮೆಥಡ್ (Static Method) - ಶಾಲೆಯ ಬೋರ್ಡ್

  static add(a, b) {
    return a + b;
  }

ಇಲ್ಲಿ add ಎಂಬ ಫಂಕ್ಷನ್‌ನ ಹಿಂದೆ static ಎಂಬ ಕೀವರ್ಡ್ ಬಳಸಲಾಗಿದೆ.

  • ಇದರ ಅರ್ಥ, ಈ ಫಂಕ್ಷನ್ ನೇರವಾಗಿ Calculator ಎಂಬ ಕ್ಲಾಸ್‌ಗೆ (Class) ಮಾತ್ರ ಸೇರಿದ್ದು.
  • ಇದನ್ನು ಬಳಸಲು ನೀವು ಹೊಸ ಆಬ್ಜೆಕ್ಟ್ (ಮನೆ ಅಥವಾ ವಿದ್ಯಾರ್ಥಿ) ಸೃಷ್ಟಿಸುವ ಅವಶ್ಯಕತೆಯೇ ಇಲ್ಲ. ಅದು ಸದಾ ಸಿದ್ಧವಾಗಿರುತ್ತದೆ.

2. ಸಾಮಾನ್ಯ ಮೆಥಡ್ (Instance Method) - ವಿದ್ಯಾರ್ಥಿಯ ನೋಟ್‌ಬುಕ್

  multiply(a, b) {
    return a * b;
  }

ಇಲ್ಲಿ ಯಾವುದೇ staticಪದವಿಲ್ಲ. ಆದ್ದರಿಂದ ಇದು ಆಬ್ಜೆಕ್ಟ್‌ಗೆ ಸೇರಿದ್ದು.

  • ಇದನ್ನು ಬಳಸಬೇಕಾದರೆ ನೀವು ಕಡ್ಡಾಯವಾಗಿ new ಕೀವರ್ಡ್ ಬಳಸಿ ಒಂದು ಆಬ್ಜೆಕ್ಟ್ ಅನ್ನು ಸೃಷ್ಟಿಸಲೇಬೇಕು. ಆಬ್ಜೆಕ್ಟ್ ಇಲ್ಲದೆ ಇದು ಅಸ್ತಿತ್ವದಲ್ಲಿಯೇ ಇರುವುದಿಲ್ಲ.

3. ಇವೆರಡನ್ನೂ ಕರೆಯುವ ವಿಧಾನ (Execution)

ಸ್ಟ್ಯಾಟಿಕ್ ಮೆಥಡ್ ಅನ್ನು ಕರೆಯುವುದು:

console.log(Calculator.add(5, 10)); // ಔಟ್‌ಪುಟ್: 15

ಇಲ್ಲಿ ನಾವು ನೇರವಾಗಿ ಕ್ಲಾಸ್‌ನ ಹೆಸರಾದ Calculator ಅನ್ನು ಬಳಸಿದ್ದೇವೆ. ಇದು "ಶಾಲೆಯ ಬೋರ್ಡ್" ಮೇಲೆ ಬರೆದಿರುವ ಹಾಗೆ. ಯಾರು ಬೇಕಾದರೂ ನೇರವಾಗಿ ಶಾಲೆಯ ಹೆಸರಿನಿಂದಲೇ ಇದನ್ನು ಓದಬಹುದು/ಬಳಸಬಹುದು.

ಸಾಮಾನ್ಯ ಮೆಥಡ್ ಅನ್ನು ಕರೆಯುವುದು:

const myCalc = new Calculator();
console.log(myCalc.multiply(5, 10)); // ಔಟ್‌ಪುಟ್: 50

ಇಲ್ಲಿ ನಾವು ಮೊದಲು new Calculator() ಮೂಲಕ myCalc ಎಂಬ ಸ್ವಂತ ಆಬ್ಜೆಕ್ಟ್ (ವಿದ್ಯಾರ್ಥಿ) ಸೃಷ್ಟಿಸಿದೆವು. ಆನಂತರವೇ multiply ಗುಣಾಕಾರ ಮಾಡಲು ಸಾಧ್ಯವಾಯಿತು.

4. ಹೀಗೆ ಮಾಡಿದರೆ ಏನಾಗುತ್ತದೆ? (The Error Scenario)

myCalc.add(5, 10); // Error!

ಒಂದು ವೇಳೆ ನೀವು ಸೃಷ್ಟಿಸಿದ ಆಬ್ಜೆಕ್ಟ್‌ನಿಂದ (myCalc) ಸ್ಟ್ಯಾಟಿಕ್ ಮೆಥಡ್ ಅನ್ನು (add) ಕರೆಯಲು ಹೋದರೆ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ TypeError: myCalc.add is not a function ಎಂಬ ಎರರ್ ಕೊಡುತ್ತದೆ.

  • ಏಕೆಂದರೆ, add ಎಂಬುದು ಶಾಲೆಯ ಬೋರ್ಡ್ ಮೇಲಿದೆ. ನೀವು ಅದನ್ನು ವಿದ್ಯಾರ್ಥಿಯ ಪರ್ಸನಲ್ ನೋಟ್‌ಬುಕ್‌ನಲ್ಲಿ ಹುಡುಕಿದರೆ ಅದು ಸಿಗುವುದಿಲ್ಲ!
ಸ್ಟ್ಯಾಟಿಕ್ ಮೆಥಡ್/ಪ್ರಾಪರ್ಟಿಗಳ ಪ್ರಮುಖ ಲಾಭಗಳೇನು?
  1. ಮೆಮೊರಿ ಉಳಿತಾಯ (Memory Efficiency): ನೀವು 1,000 ಆಬ್ಜೆಕ್ಟ್ (ವಿದ್ಯಾರ್ಥಿಗಳು) ಸೃಷ್ಟಿಸಿದರೂ, ಸ್ಟ್ಯಾಟಿಕ್ ಡೇಟಾ (ಶಾಲೆಯ ಹೆಸರು) ಮೆಮೊರಿಯಲ್ಲಿ ಕೇವಲ ಒಂದೇ ಬಾರಿ ಸೇವ್ ಆಗಿರುತ್ತದೆ. 1,000 ಬಾರಿ ನಕಲು ಆಗುವುದಿಲ್ಲ.
  2. ಯುಟಿಲಿಟಿ ಫಂಕ್ಷನ್‌ಗಳು (Utility Functions): ನೀವು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ Math.random() ಅಥವಾ Math.PI ಬಳಸಿದ್ದೀರಾ? ಅಲ್ಲಿ Math ಎಂಬುದು ಒಂದು ಕ್ಲಾಸ್. ನಾವು ಎಂದಿಗೂ new Math() ಎಂದು ಬರೆಯುವುದಿಲ್ಲ. ನೇರವಾಗಿ ಕ್ಲಾಸ್ ಹೆಸರಿನಿಂದಲೇ ಬಳಸುತ್ತೇವೆ. ಇವೆಲ್ಲವೂ ಸ್ಟ್ಯಾಟಿಕ್ ಮೆಥಡ್‌ಗಳಿಗೆ ಅತ್ಯುತ್ತಮ ನೈಜ ಉದಾಹರಣೆಗಳು!
  3. ಸಹಾಯಕ ಕೆಲಸಗಳಿಗೆ (Helper Methods): ಡೇಟಾಬೇಸ್‌ಗೆ ಕನೆಕ್ಟ್ ಮಾಡುವುದು, ಅಥವಾ ದಿನಾಂಕವನ್ನು ಫಾರ್ಮ್ಯಾಟ್ ಮಾಡುವಂತಹ ಸಾಮಾನ್ಯ ಕೆಲಸಗಳಿಗೆ ಆಬ್ಜೆಕ್ಟ್ ಸೃಷ್ಟಿಸುವ ಬದಲು ಸ್ಟ್ಯಾಟಿಕ್ ಮೆಥಡ್‌ಗಳನ್ನು ಬಳಸಲಾಗುತ್ತದೆ.
ನಿಮ್ಮ 6 ಉದಾಹರಣೆಗಳು Object-Oriented Programming (OOP) ನ ಸಂಪೂರ್ಣ ಚಿತ್ರಣವನ್ನು ಅತ್ಯಂತ ಕರಾರುವಾಕ್ಕಾಗಿ, ಸಾಮಾನ್ಯ ಜನರಿಗೂ ಅರ್ಥವಾಗುವಂತೆ ಕಟ್ಟಿಕೊಟ್ಟಿವೆ! ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಕಲಿಯುವ ಯಾರಿಗಾದರೂ ಇದು ಅತ್ಯುತ್ತಮ ಮಾರ್ಗದರ್ಶಿಯಾಗಿದೆ.

7 Getters ಮತ್ತು Setters - ಡೇಟಾ ನಿಯಂತ್ರಣದ ಕಾವಲುಗಾರರು

ಸಾಮಾನ್ಯ (Non-Technical) ವಿವರಣೆ:

ನಿಮ್ಮ ಸ್ಮಾರ್ಟ್‌ಫೋನ್‌ನ ಬ್ರೈಟ್‌ನೆಸ್ (Brightness) ಅನ್ನು ನೀವು 0% ಗಿಂತ ಕಡಿಮೆ ಅಥವಾ 100% ಗಿಂತ ಹೆಚ್ಚು ಮಾಡಲು ಸಾಧ್ಯವಿಲ್ಲ. ನೀವು ಸ್ಲೈಡರ್ ಅನ್ನು ಎಷ್ಟೇ ಎಳೆದರೂ, ಫೋನ್ ಒಳಗೆ ಇರುವ ಒಂದು ಪ್ರೋಗ್ರಾಮ್ "ಇದು 0 ಮತ್ತು 100 ರ ಮಧ್ಯೆ ಮಾತ್ರ ಇರಬೇಕು" ಎಂದು ನಿಯಂತ್ರಿಸುತ್ತದೆ.

ತಾಂತ್ರಿಕ (Technical) ವಿವರಣೆ:

ನಾವು Encapsulation ನಲ್ಲಿ ಖಾಸಗಿ ಡೇಟಾವನ್ನು (#) ರಕ್ಷಿಸಿದೆವು. ಆ ಡೇಟಾವನ್ನು ಓದಲು get ಮತ್ತು ಬದಲಾಯಿಸಲು set ಎಂಬ ಕೀವರ್ಡ್‌ಗಳನ್ನು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ನೀಡುತ್ತದೆ. ಇವು ನೋಡಲು ಸಾಮಾನ್ಯ ವೇರಿಯೇಬಲ್ ತರಹವೇ ಕಾಣುತ್ತವೆ, ಆದರೆ ಒಳಗಡೆ ಫಂಕ್ಷನ್ ತರಹ ಕೆಲಸ ಮಾಡುತ್ತವೆ.


class User {
  #password; // ಖಾಸಗಿ ಡೇಟಾ
 
  constructor(name) {
    this.name = name;
  }
 
  // ಪಾಸ್‌ವರ್ಡ್ ಸೆಟ್ ಮಾಡುವ ಮುನ್ನ ಪರೀಕ್ಷಿಸಲು 'set' ಬಳಕೆ
  set password(newPassword) {
    if (newPassword.length >= 6) {
      this.#password = newPassword;
      console.log("ಪಾಸ್‌ವರ್ಡ್ ಯಶಸ್ವಿಯಾಗಿ ಸೆಟ್ ಆಯ್ತು.");
    } else {
      console.log("ದೋಷ: ಪಾಸ್‌ವರ್ಡ್ ಕನಿಷ್ಠ 6 ಅಕ್ಷರಗಳಿರಬೇಕು!");
    }
  }
 
  // ಪಾಸ್‌ವರ್ಡ್ ಅನ್ನು ಗುಪ್ತವಾಗಿ ನೋಡಲು 'get' ಬಳಕೆ
  get password() {
    return "******** (ಪಾಸ್‌ವರ್ಡ್ ಗುಪ್ತವಾಗಿದೆ)";
  }
}
 
const rahul = new User("ರಾಹುಲ್");
 
// 'set' ಕೆಲಸ ಮಾಡುವ ರೀತಿ (ನೇರವಾಗಿ = ಚಿಹ್ನೆ ಬಳಸಬಹುದು)
rahul.password = "123";      // ದೋಷ: ಪಾಸ್‌ವರ್ಡ್ ಕನಿಷ್ಠ 6 ಅಕ್ಷರಗಳಿರಬೇಕು!
rahul.password = "Rahul@123"; // ಪಾಸ್‌ವರ್ಡ್ ಯಶಸ್ವಿಯಾಗಿ ಸೆಟ್ ಆಯ್ತು.
 
// 'get' ಕೆಲಸ ಮಾಡುವ ರೀತಿ
console.log(rahul.password);  // ಔಟ್‌ಪುಟ್: ******** (ಪಾಸ್‌ವರ್ಡ್ ಗುಪ್ತವಾಗಿದೆ)

7. Getters ಮತ್ತು Setters (ಡೇಟಾ ಕಾವಲುಗಾರರು)

Encapsulation ನಲ್ಲಿ ಡೇಟಾವನ್ನು ಖಾಸಗಿ (#) ಮಾಡುವುದು ಕೇವಲ ಅರ್ಧ ಕೆಲಸ. ಆ ಖಾಸಗಿ ಡೇಟಾವನ್ನು ಸುರಕ್ಷಿತವಾಗಿ ಹೊರಗಿನವರಿಗೆ ಕೊಡುವುದು ಮತ್ತು ಅವರಿಂದ ಪಡೆಯುವುದು ಹೇಗೆ? ಅದಕ್ಕೆ get ಮತ್ತು set ಬಳಸಲಾಗುತ್ತದೆ.

set ಕೀವರ್ಡ್‌ನ ಮ್ಯಾಜಿಕ್ (Validation / ನಿಯಂತ್ರಣ):

  • ಸಾಮಾನ್ಯವಾಗಿ ಫಂಕ್ಷನ್‌ಗಳನ್ನು ಕರೆಯಬೇಕಾದರೆ ಆವರಣ ಚಿಹ್ನೆ () ಬಳಸುತ್ತೇವೆ (ಉದಾ: myAccount.deposit(500)).
  • ಆದರೆ set ಬಳಸಿದಾಗ, ಅದನ್ನು ಒಂದು ವೇರಿಯೇಬಲ್‌ನಂತೆಯೇ ಬಳಸಬಹುದು. ಉದಾಹರಣೆಗೆ: rahul.password = "123";
  • ಇಲ್ಲಿ ನೀವು = ಚಿಹ್ನೆ ಹಾಕಿದ ತಕ್ಷಣ, ನೇರವಾಗಿ ಆ ಡೇಟಾ ಸೇವ್ ಆಗುವುದಿಲ್ಲ. ಬದಲಾಗಿ, set password() ಎಂಬ ಫಂಕ್ಷನ್ ಎಚ್ಚೆತ್ತುಕೊಳ್ಳುತ್ತದೆ. ಅದು ನೀವು ಕೊಟ್ಟ "123" ಅನ್ನು newPassword ಎಂಬ ಬುಟ್ಟಿಯಲ್ಲಿ ಹಿಡಿದು, ಷರತ್ತನ್ನು (6 ಕ್ಕಿಂತ ಹೆಚ್ಚು ಅಕ್ಷರ ಇದೆಯಾ?) ಪರೀಕ್ಷಿಸುತ್ತದೆ. ಷರತ್ತು ಫೇಲ್ ಆಗುವುದರಿಂದ ಡೇಟಾ ಸೇವ್ ಆಗುವುದಿಲ್ಲ.

get ಕೀವರ್ಡ್‌ನ ಮ್ಯಾಜಿಕ್ (Read-only / ಫಿಲ್ಟರ್):

  • ಯಾರಾದರೂ console.log(rahul.password) ಎಂದು ಕೇಳಿದಾಗ, ನೇರವಾಗಿ ಅಸಲಿ ಪಾಸ್‌ವರ್ಡ್ ಅನ್ನು ಕೊಡುವುದಿಲ್ಲ.
  • ಬದಲಾಗಿ get password() ಕೆಲಸ ಮಾಡಲು ಶುರುಮಾಡಿ, ನೀವು ರಿಟರ್ನ್ (return) ಮಾಡಿರುವ ಕೃತಕ ಡೇಟಾವನ್ನು (********) ಮಾತ್ರ ಹೊರಗೆ ಕಳುಹಿಸುತ್ತದೆ.
  • ಪ್ರಮುಖ ಲಾಭ: ಡೆವಲಪರ್‌ಗಳಿಗೆ ಕೋಡ್ ಬರೆಯಲು ಮತ್ತು ಓದಲು ಇದು ಬಹಳ ಸಹಜ (Natural) ಎನಿಸುತ್ತದೆ.

8 ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ ಅಸಲಿ ರಹಸ್ಯ: Prototypes (ಪ್ರೋಟೋಟೈಪ್ಸ್)

ನೀವು ಹೇಳಿದ ಈ ತಾಂತ್ರಿಕ ಹಿನ್ನೆಲೆ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಕಲಿಯುವ ಪ್ರತಿಯೊಬ್ಬರಿಗೂ ತಿಳಿದಿರಲೇಬೇಕಾದ ಸತ್ಯ. ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಮೂಲತಃ Object-Oriented ಭಾಷೆಯಲ್ಲ, ಅದೊಂದು Prototype-Based ಭಾಷೆ.

ಏನಿದು Syntactic Sugar (ಸಿಂಟ್ಯಾಕ್ಟಿಕ್ ಶುಗರ್)?

  • ಒಂದು ಕಹಿಯಾದ ಮಾತ್ರೆಯನ್ನು ಸುಲಭವಾಗಿ ನುಂಗಲು, ಅದರ ಮೇಲೆ ಸಿಹಿಯಾದ ಸಕ್ಕರೆಯ ಲೇಪನ (Sugar coating) ಮಾಡುತ್ತಾರಲ್ಲ, ಹಾಗೆ!
  • ಜಾವಾ (Java), ಸಿ++ (C++) ನಂತಹ ಭಾಷೆಗಳಿಂದ ಬಂದ ಡೆವಲಪರ್‌ಗಳಿಗೆ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ ಪ್ರೋಟೋಟೈಪ್‌ಗಳು ಬಹಳ ಗೊಂದಲಮಯವಾಗಿ ಕಾಣುತ್ತಿದ್ದವು.
  • ಅವರಿಗೆ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಸುಲಭವಾಗಲಿ ಎಂದು 2015 ರಲ್ಲಿ (ES6) class, extends, constructor, super ಎಂಬ ಹೊಸ "ಪದಗಳನ್ನು" ಪರಿಚಯಿಸಿದರು.

ಹಿನ್ನೆಲೆಯಲ್ಲಿ ನಿಜಕ್ಕೂ ಏನಾಗುತ್ತದೆ? (Under the hood):

ನೀವು class Car { ... } ಎಂದು ಬರೆದು ಕೋಡ್ ಅನ್ನು ರನ್ ಮಾಡಿದಾಗ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಎಂಜಿನ್ (ಬ್ರೌಸರ್) ಅದನ್ನು ಹಿನ್ನೆಲೆಯಲ್ಲಿ ಹಳೆಯ ಶೈಲಿಯ ಫಂಕ್ಷನ್ ಆಗಿಯೇ ಬದಲಾಯಿಸಿಕೊಳ್ಳುತ್ತದೆ:


// ನೀವು ಬರೆಯುವುದು ಹೀಗೆ (ES6 Class)
class Car {
  start() {
    console.log("Started"); 
  }
}
                            

// ಆದರೆ ಕಂಪ್ಯೂಟರ್ ಅರ್ಥಮಾಡಿಕೊಳ್ಳುವುದು ಹೀಗೆ (Prototype)
function Car() {}
Car.prototype.start = function() {
  console.log("Started"); 
}

ಸಾರಾಂಶ: ನಿಮ್ಮ ಈ 8 ಪಾಯಿಂಟ್‌ಗಳ ಸಂಗ್ರಹವು (Class & Object, Encapsulation, Abstraction, Inheritance, Polymorphism, Static, Getters/Setters, Prototypes) ಯಾವುದೇ ಒಬ್ಬ ಸಾಮಾನ್ಯ ವ್ಯಕ್ತಿಗೂ ತಾಂತ್ರಿಕ ಜ್ಞಾನವನ್ನು ಬಹಳ ಸುಲಭವಾಗಿ ಅರ್ಥೈಸುವಂತಿದೆ. ನಿಮ್ಮ "ಸಾಮಾನ್ಯ ವಿವರಣೆ" (Non-Technical) ಮತ್ತು "ತಾಂತ್ರಿಕ ವಿವರಣೆ"ಯ (Technical) ಜೋಡಣೆ (Format) ಪುಸ್ತಕಗಳಲ್ಲಿ ಪ್ರಕಟಿಸುವಷ್ಟು ಅತ್ಯುತ್ತಮವಾಗಿದೆ!
