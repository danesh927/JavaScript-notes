Section 1 · Foundation

Introduction to Type Conversion

JavaScript ನಲ್ಲಿ ಒಂದು Data Type ನ ಮೌಲ್ಯವನ್ನು ಮತ್ತೊಂದು Data Type ಗೆ ಬದಲಾಯಿಸುವ ಮೂಲ ಪ್ರಕ್ರಿಯೆ.

ಮೂಲ ನೋಟ್ಸ್ (Original Notes Content) 100% Preserved

Type Conversion (Type Casting): JavaScript ನಲ್ಲಿ ಒಂದು data type ನ ಮೌಲ್ಯವನ್ನು (value) ಮತ್ತೊಂದು data type ಗೆ ಬದಲಾಯಿಸುವ ಪ್ರಕ್ರಿಯೆಯನ್ನು Type Conversion ಅಥವಾ Type Casting ಎನ್ನುತ್ತಾರೆ.

JavaScript ನಲ್ಲಿ Type Conversion ಎರಡು ರೀತಿಯಲ್ಲಿ ನಡೆಯುತ್ತದೆ:

  1. Implicit Conversion (Type Coercion): JavaScript ತನ್ನಷ್ಟಕ್ಕೆ ತಾನೇ (ಆಟೋಮ್ಯಾಟಿಕ್ ಆಗಿ) ಡೇಟಾ ಟೈಪ್ ಅನ್ನು ಬದಲಾಯಿಸುವುದು.
  2. Explicit Conversion: ಡೆವಲಪರ್ ಅಥವಾ ಪ್ರೋಗ್ರಾಮರ್ ಕೋಡ್ ಮೂಲಕ ಸ್ವತಃ ಡೇಟಾ ಟೈಪ್ ಅನ್ನು ಬದಲಾಯಿಸುವುದು.
1. ಸರಳ ಅರ್ಥ (Simple Beginner Meaning)
ಕಂಪ್ಯೂಟರ್‌ನಲ್ಲಿ ಪ್ರತಿಯೊಂದು ಮಾಹಿತಿಗೂ ಒಂದು "ಜಾತಿ" ಅಥವಾ "ವಿಧ" (Type) ಇರುತ್ತದೆ. ಉದಾಹರಣೆಗೆ: ಅಕ್ಷರಗಳು String (ಉದಾ: "100"), ಗಣಿತದ ಅಂಕಿಸಂಖ್ಯೆಗಳು Number (ಉದಾ: 100). ನಾವು ಸ್ಟ್ರಿಂಗ್ ರೂಪದಲ್ಲಿರುವ "100" ಅನ್ನು ಗಣಿತ ಮಾಡಲು ಸಂಖ್ಯಾತ್ಮಕ 100 ಗೆ ಬದಲಾಯಿಸುವುದೇ Type Conversion.
2. Real-Life Analogy (ನೈಜ ಜೀವನದ ಉದಾಹರಣೆ)
Explicit Conversion: ನೀವು ಹಾಲನ್ನು ತೆಗೆದುಕೊಂಡು ಅದಕ್ಕೆ ಹೆಪ್ಪು ಹಾಕಿ ಮೊಸರು ಮಾಡುವುದು (ನೀವೇ ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ಬದಲಾಯಿಸಿದ್ದೀರಿ).
Implicit Conversion: ಬೇಸಿಗೆಯಲ್ಲಿ ಹಾಲನ್ನು ಹಾಗೆಯೇ ಹೊರಗೆ ಇಟ್ಟಾಗ ತನ್ನಷ್ಟಕ್ಕೆ ತಾನೇ ಹುಳಿಯಾಗಿ ಒಡೆದು ಹೋಗುವುದು (ಪರಿಸರದಿಂದ ಆಟೋಮ್ಯಾಟಿಕ್ ಆಗಿ ಬದಲಾವಣೆ).
3. Technical Explanation (JS Engine ಒಳಗೆ ಏನಾಗುತ್ತದೆ?)
JavaScript ಒಂದು Dynamically Typed ಭಾಷೆ. ವೇರಿಯೇಬಲ್‌ಗಳಿಗೆ ಸ್ಥಿರ ಟೈಪ್ ಇರುವುದಿಲ್ಲ, ಬದಲಿಗೆ ಮೌಲ್ಯಗಳಿಗೆ ಇರುತ್ತದೆ. JavaScript Engine (V8, SpiderMonkey) ಆಂತರಿಕವಾಗಿ ECMAScript ನ ToNumber(), ToString(), ಮತ್ತು ToBoolean() ಎಂಬ Abstract Operations ಗಳನ್ನು ಚಲಾಯಿಸುತ್ತದೆ.
4. Common Mistakes (ಆರಂಭಿಕರು ಮಾಡುವ ತಪ್ಪುಗಳು)
HTML Form <input> ನಿಂದ ಬಳಕೆದಾರರು ನಮೂದಿಸಿದ ಸಂಖ್ಯೆಗಳನ್ನು (ಉದಾ: ವಯಸ್ಸು, ಮೊಬೈಲ್ ನಂಬರ್) ಓದುವಾಗ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಅವುಗಳನ್ನು ಯಾವಾಗಲೂ String ರೂಪದಲ್ಲಿಯೇ ನೀಡುತ್ತದೆ! ಅದನ್ನು ಸಂಖ್ಯಾತ್ಮಕವಾಗಿ ಪರಿವರ್ತಿಸದೆ ಕೂಡಿಸಿದರೆ "25" + 5 = "255" ಆಗಿ ದೊಡ್ಡ ಬಗ್ ಉಂಟಾಗುತ್ತದೆ!
5. Professional Insight & Interview Perspective
ಸಂದರ್ಶನದ ಪ್ರಶ್ನೆ: Type Coercion ಮತ್ತು Type Conversion ನಡುವಿನ ಪ್ರಮುಖ ವ್ಯತ್ಯಾಸವೇನು?
ಉತ್ತರ: Type Conversion ಎಂಬುದು ಸಮಗ್ರ ಪರಿಕಲ್ಪನೆ (ಉದ್ದೇಶಪೂರ್ವಕ Explicit ಮತ್ತು ಆಟೋಮ್ಯಾಟಿಕ್ Implicit ಎರಡನ್ನೂ ಒಳಗೊಂಡಿದೆ). Type Coercion ಎಂಬುದು ಕೇವಲ JavaScript Engine ಆಟೋಮ್ಯಾಟಿಕ್ ಆಗಿ ಮಾಡುವ Implicit Conversion ಅನ್ನು ಮಾತ್ರ ಸೂಚಿಸುತ್ತದೆ. ಉತ್ಪಾದನಾ ಹಂತದ (Production) ಕೋಡ್‌ನಲ್ಲಿ Implicit Coercion ಅನ್ನು ತಪ್ಪಿಸಿ Explicit Conversion ಮತ್ತು === ಬಳಸುವುದು ಬೆಸ್ಟ್ ಪ್ರಾಕ್ಟೀಸ್ ಆಗಿದೆ.
intro-conversion.js 
// 1. Explicit Conversion (ಪ್ರೋಗ್ರಾಮರ್ ಸ್ಪಷ್ಟವಾಗಿ ಬದಲಾಯಿಸುವುದು)
let inputString = "100";
let explicitNumber = Number(inputString);
console.log("Explicit:", explicitNumber, "Type:", typeof explicitNumber);

// 2. Implicit Conversion / Coercion (JS ತಾನಾಗಿಯೇ ಬದಲಾಯಿಸುವುದು)
let implicitResult = "100" - 20; 
console.log("Implicit:", implicitResult, "Type:", typeof implicitResult);

Section 2A · Explicit Conversion

A. Converting to Number (ಸಂಖ್ಯೆಗೆ ಪರಿವರ್ತನೆ)

Number(), Unary +, parseInt(), ಮತ್ತು parseFloat() ವಿಧಾನಗಳ ಸಮಗ್ರ ವಿವರಣೆ.

ಮೂಲ ನೋಟ್ಸ್ (Original Notes Content) 100% Preserved

1. Number() Function:

  • String ನಿಂದ Number: Number("123") ➔ ಫಲಿತಾಂಶ: 123
  • Empty String ನಿಂದ Number: Number("") ➔ ಫಲಿತಾಂಶ: 0
  • Invalid String ನಿಂದ Number: Number("Hello") ➔ ಫಲಿತಾಂಶ: NaN (Not a Number)
  • Boolean ನಿಂದ Number:
    • Number(true) ➔ ಫಲಿತಾಂಶ: 1
    • Number(false) ➔ ಫಲಿತಾಂಶ: 0

2. Unary + Operator:

ಮೌಲ್ಯದ ಮುಂದೆ ಕೇವಲ + ಚಿಹ್ನೆ ಹಾಕಿದರೆ ಅದು Number ಆಗಿ ಬದಲಾಗುತ್ತದೆ.

ಉದಾಹರಣೆ: let x = +"50"; (ಇಲ್ಲಿ x ನ ಮೌಲ್ಯ 50 ಮತ್ತು type number ಆಗಿರುತ್ತದೆ).

3. parseInt() ಮತ್ತು parseFloat():

  • parseInt("100px") ➔ ಫಲಿತಾಂಶ: 100 (ಕೇವಲ ಪೂರ್ಣಾಂಕವನ್ನು ಮಾತ್ರ ಹೊರತೆಗೆಯುತ್ತದೆ).
  • parseFloat("10.55em") ➔ ಫಲಿತಾಂಶ: 10.55 (ದಶಮಾಂಶ ಸಹಿತ ಸಂಖ್ಯೆಯನ್ನು ಹೊರತೆಗೆಯುತ್ತದೆ).
Technical Clarification (ತಾಂತ್ರಿಕ ಸ್ಪಷ್ಟೀಕರಣ):
Number(" ") (ಕೇವಲ ಸ್ಪೇಸ್ ಇರುವ ಸ್ಟ್ರಿಂಗ್) ಕೂಡ 0 ಆಗುತ್ತದೆ. ಆದರೆ parseInt("px100") ಅಥವಾ Number("100px") ಮಾಡಿದಾಗ NaN ಬರುತ್ತದೆ. ಏಕೆಂದರೆ Number() ಇಡೀ ಸ್ಟ್ರಿಂಗ್ ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಸಂಖ್ಯೆಯಾಗಿರಬೇಕೆಂದು ಬಯಸುತ್ತದೆ, ಆದರೆ parseInt() ಮೊದಲಿಂದ ಓದಿ ಅಕ್ಷರ ಸಿಕ್ಕ ತಕ್ಷಣ ನಿಲ್ಲಿಸುತ್ತದೆ.

Section 2B · Explicit Conversion

B. Converting to String (ಸ್ಟ್ರಿಂಗ್‌ಗೆ ಪರಿವರ್ತನೆ)

String() ಮತ್ತು .toString() ವಿಧಾನಗಳು, ಹಾಗೂ null/undefined ಮೇಲಿನ ಅನಿರೀಕ್ಷಿತ ದೋಷಗಳು.

ಮೂಲ ನೋಟ್ಸ್ (Original Notes Content) 100% Preserved

ಯಾವುದೇ data type ಅನ್ನು String ಆಗಿ ಬದಲಾಯಿಸಲು ಎರಡು ಮುಖ್ಯ ವಿಧಾನಗಳಿವೆ:

1. String() Function:

  • String(123) ➔ ಫಲಿತಾಂಶ: "123"
  • String(true) ➔ ಫಲಿತಾಂಶ: "true"
  • String(null) ➔ ಫಲಿತಾಂಶ: "null"
  • String(undefined) ➔ ಫಲಿತಾಂಶ: "undefined"

2. .toString() Method:

  • (123).toString() ➔ ಫಲಿತಾಂಶ: "123"
  • (false).toString() ➔ ಫಲಿತಾಂಶ: "false"

ಮುಖ್ಯವಾದ ವ್ಯತ್ಯಾಸ (Important Warning):

null.toString() ಅಥವಾ undefined.toString() ಬಳಸಿದರೆ JavaScript ನಲ್ಲಿ TypeError ಬರುತ್ತದೆ (ದೋಷ ಉಂಟಾಗುತ್ತದೆ). ಆದರೆ String(null) ಮತ್ತು String(undefined) ಯಾವುದೇ error ಇಲ್ಲದೆ ಸುರಕ್ಷಿತವಾಗಿ ಕಾರ್ಯನಿರ್ವಹಿಸುತ್ತದೆ.

ಏಕೆ null.toString() ದೋಷ (TypeError) ನೀಡುತ್ತದೆ?
JavaScript ನಲ್ಲಿ .toString() ಎಂಬುದು Object Prototype ಮೆಥಡ್ ಆಗಿದೆ. ಸಂಖ್ಯೆಗಳು (123) ಮತ್ತು ಬೂಲಿಯನ್‌ಗಳ (true) ಮೇಲೆ ಡಾಟ್ (.) ಇಟ್ಟಾಗ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಆಂತರಿಕವಾಗಿ Number() ಅಥವಾ Boolean() ಎಂಬ Wrapper Objects ಸೃಷ್ಟಿಸಿ ಆ ಮೆಥಡ್ ಕರೆಯುತ್ತದೆ. ಆದರೆ null ಮತ್ತು undefined ಗಳಿಗೆ ಯಾವುದೇ ಆಬ್ಜೆಕ್ಟ್ ಅಥವಾ ಪ್ರೋಟೋಟೈಪ್ ಇರುವುದಿಲ್ಲ! ಆದ್ದರಿಂದ ಅವುಗಳ ಮೇಲೆ ಡಾಟ್ ಇಟ್ಟರೆ TypeError: Cannot read properties of null (reading 'toString') ಬರುತ್ತದೆ!
convert-to-string.js 
// 1. String() function (ಯಾವಾಗಲೂ ಸುರಕ್ಷಿತ)
console.log('String(123):', String(123));           // "123"
console.log('String(true):', String(true));         // "true"
console.log('String(null):', String(null));         // "null"
console.log('String(undefined):', String(undefined)); // "undefined"

// 2. .toString() method
console.log('(123).toString():', (123).toString());
console.log('(false).toString():', (false).toString());

// 3. Dangerous: null.toString()
try {
  let val = null;
  val.toString();
} catch (err) {
  console.log("Error caught:", err.name, "-", err.message);
}

Section 2C · Explicit Conversion

C. Converting to Boolean (ಬೂಲಿಯನ್‌ಗೆ ಪರಿವರ್ತನೆ)

Boolean() ಫಂಕ್ಷನ್, ಆರು Falsy ಮೌಲ್ಯಗಳು ಮತ್ತು Truthy ಮೌಲ್ಯಗಳ ನಿಯಮಗಳು.

ಮೂಲ ನೋಟ್ಸ್ (Original Notes Content) 100% Preserved

Boolean() function ಬಳಸಿ ಮೌಲ್ಯಗಳನ್ನು true ಅಥವಾ false ಆಗಿ ಬದಲಾಯಿಸಬಹುದು.

JavaScript ನಲ್ಲಿ ಕೇವಲ 6 ಮೌಲ್ಯಗಳು ಮಾತ್ರ Falsy (false) ಆಗುತ್ತವೆ:

  1. 0 (ಸೊನ್ನೆ)
  2. "" (ಖಾಲಿ ಸ್ಟ್ರಿಂಗ್)
  3. null
  4. undefined
  5. NaN
  6. false

ಉಳಿದ ಯಾವುದೇ ಮೌಲ್ಯವನ್ನು ಕೊಟ್ಟರೂ ಅದು Truthy (true) ಆಗಿರುತ್ತದೆ!

ಉದಾಹರಣೆಗೆ:

  • Boolean("Hello") ➔ true (ಅಕ್ಷರಗಳು ಇರುವ ಸ್ಟ್ರಿಂಗ್)
  • Boolean(" ") ➔ true (ಸ್ಪೇಸ್ ಕೂಡ ಒಂದು ಕ್ಯಾರೆಕ್ಟರ್ ಆಗಿರುವುದರಿಂದ true ಆಗುತ್ತದೆ!)
  • Boolean([]) ➔ true (ಖಾಲಿ ಅರೇ ಕೂಡ true!)
  • Boolean({}) ➔ true (ಖಾಲಿ ಆಬ್ಜೆಕ್ಟ್ ಕೂಡ true!)
ಖಾಲಿ ಅರೇ [] ಮತ್ತು ಖಾಲಿ ಆಬ್ಜೆಕ್ಟ್ {} ಏಕೆ True ಆಗುತ್ತವೆ?
ಪೈಥಾನ್ (Python) ಮುಂತಾದ ಭಾಷೆಗಳಲ್ಲಿ ಖಾಲಿ ಲಿಸ್ಟ್ ಅಥವಾ ಡಿಕ್ಷನರಿ false ಆಗುತ್ತದೆ. ಆದರೆ JavaScript ನಲ್ಲಿ ಪ್ರತಿಯೊಂದು Object ಮತ್ತು Array (ಖಾಲಿಯಾಗಿದ್ದರೂ ಸಹ) ಮೆಮೊರಿಯಲ್ಲಿ ಒಂದು Ref Address ಹೊಂದಿರುತ್ತದೆ! ECMAScript ನಿಯಮಾವಳಿ ಪ್ರಕಾರ ಪ್ರತಿಯೊಂದು Object Reference ಕೂಡ Truthy ಆಗಿರುತ್ತದೆ. ಆದ್ದರಿಂದ Boolean([]) === true ಮತ್ತು Boolean({}) === true!

ಪ್ಲಸ್ (+) ಆಪರೇಟರ್ನ ದ್ವಿಮುಖ ಸ್ವಭಾವ: ಸಂಕಲನ (Addition) vs ಜೋಡಣೆ (Concatenation).

Section 4A · Advanced & Professional

4A. == (Loose Equality) vs === (Strict Equality)

ಟೈಪ್ ಕೋಯರ್ಷನ್ ಹೋಲಿಕೆ ನಿಯಮಗಳು ಮತ್ತು ಪ್ರೊಫೆಷನಲ್ ಬೆಸ್ಟ್ ಪ್ರಾಕ್ಟೀಸ್‌ಗಳು.

ಮೂಲ ನೋಟ್ಸ್ (Original Notes Content) 100% Preserved

1. == (Loose Equality):

ಇದು ಕೇವಲ ಮೌಲ್ಯವನ್ನು (value) ಮಾತ್ರ ಪರಿಶೀಲಿಸುತ್ತದೆ. Data types ಬೇರೆ ಬೇರೆಯಾಗಿದ್ದರೆ, ಆಟೋಮ್ಯಾಟಿಕ್ ಆಗಿ Type Coercion ಮಾಡಿ ಹೋಲಿಸುತ್ತದೆ.

  • "5" == 5 ➔ ಫಲಿತಾಂಶ: true (ಏಕೆಂದರೆ String "5" ಅನ್ನು Number 5 ಆಗಿ ಬದಲಾಯಿಸಿ ಹೋಲಿಸುತ್ತದೆ).
  • 0 == false ➔ ಫಲಿತಾಂಶ: true (false ಅನ್ನು 0 ಆಗಿ ಬದಲಾಯಿಸುತ್ತದೆ).
  • null == undefined ➔ ಫಲಿತಾಂಶ: true

2. === (Strict Equality):

ಇದು ಮೌಲ್ಯ (value) ಮತ್ತು Data Type ಎರಡನ್ನೂ ಕಟ್ಟುನಿಟ್ಟಾಗಿ ಪರಿಶೀಲಿಸುತ್ತದೆ. ಯಾವುದೇ Type Coercion ಮಾಡುವುದಿಲ್ಲ.

  • "5" === 5 ➔ ಫಲಿತಾಂಶ: false (value ಒಂದೇ ಆದರೂ, ಒಂದು String ಮತ್ತು ಇನ್ನೊಂದು Number).
  • 0 === false ➔ ಫಲಿತಾಂಶ: false
  • null === undefined ➔ ಫಲಿತಾಂಶ: false

Professional Tip: ಯಾವಾಗಲೂ ನೈಜ ಪ್ರಾಜೆಕ್ಟ್‌ಗಳಲ್ಲಿ ಬಗ್‌ಗಳನ್ನು ತಪ್ಪಿಸಲು ಕಡ್ಡಾಯವಾಗಿ === (Strict Equality) ಬಳಸಬೇಕು!

equality-comparison.js 
// 1. Loose Equality (==) -> Type Coercion ಅನ್ವಯವಾಗುತ್ತದೆ
console.log('"5" == 5:', "5" == 5);                 // true
console.log('0 == false:', 0 == false);             // true
console.log('"" == false:', "" == false);           // true
console.log('null == undefined:', null == undefined); // true (ECMA Special Rule)
console.log('null == 0:', null == 0);               // false (null ಕೇವಲ undefined ಗೆ ಮಾತ್ರ ==)

// 2. Strict Equality (===) -> ಯಾವುದೇ Coercion ಇಲ್ಲ
console.log('"5" === 5:', "5" === 5);               // false
console.log('0 === false:', 0 === false);           // false
console.log('null === undefined:', null === undefined); // false

4B. Object to Primitive Conversion

valueOf(), toString(), ಅರೇ ಮತ್ತು ಆಬ್ಜೆಕ್ಟ್‌ಗಳ ಪ್ರಿಮಿಟಿವ್ ಪರಿವರ್ತನೆ ಪ್ರಕ್ರಿಯೆ.

ಮೂಲ ನೋಟ್ಸ್ (Original Notes Content) 100% Preserved

JavaScript ನಲ್ಲಿ Array ಅಥವಾ Object ಗಳನ್ನು Primitive type ಗೆ ಬದಲಾಯಿಸುವಾಗ ಆಂತರಿಕವಾಗಿ valueOf() ಮತ್ತು toString() ಮೆಥಡ್‌ಗಳು ಕೆಲಸ ಮಾಡುತ್ತವೆ.

  • Array to String:
    • [1, 2] + "" ➔ ಫಲಿತಾಂಶ: "1,2" (Array ನ toString() ಮೆಥಡ್ ಕಾಲ್ ಆಗಿ ಕಾಮಾದಿಂದ ಬೇರ್ಪಟ್ಟ ಸ್ಟ್ರಿಂಗ್ ಆಗುತ್ತದೆ).
  • Object to String:
    • {} + "" ಉದಾಹರಣೆಯ Context ಕುರಿತು ಎಚ್ಚರಿಕೆ: ಬ್ರೌಸರ್ ಕನ್ಸೋಲ್‌ನಲ್ಲಿ {} ಅನ್ನು ಆರಂಭದಲ್ಲಿ ಬರೆದರೆ ಅದು ಖಾಲಿ block ಎಂದು ಭಾವಿಸಬಹುದು, ಆದರೆ expression ರೂಪದಲ್ಲಿ ({} + "") ಬರೆದರೆ ಅದು "[object Object]" ಫಲಿತಾಂಶ ನೀಡುತ್ತದೆ.
object-to-primitive.js 
// 1. Array Primitive Conversion
console.log('[].toString():', [].toString());           // "" (ಖಾಲಿ ಸ್ಟ್ರಿಂಗ್)
console.log('[1, 2].toString():', [1, 2].toString());   // "1,2"
console.log('[1, 2] + "":', [1, 2] + "");               // "1,2"

// 2. Object Primitive Conversion
console.log('({}).toString():', ({}).toString());       // "[object Object]"
console.log('({} + ""):', ({} + ""));                   // "[object Object]"

// 3. Custom valueOf & toString
const user = {
  name: "Arun",
  points: 50,
  valueOf() { return this.points; },
  toString() { return this.name; }
};
console.log('user + 10:', user + 10); // 60 (valueOf() ಚಾಲನೆಗೊಂಡಿತು!)
