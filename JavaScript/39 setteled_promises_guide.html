Settled Promises

ಪರಿವಿಡಿ (Contents)

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ 'ಪ್ರಾಮಿಸ್' (Promise) ಎಂದರೆ ಭವಿಷ್ಯದಲ್ಲಿ ನಡೆಯುವ ಒಂದು ಕೆಲಸ ಅಥವಾ ಡೇಟಾ. 'ಸೆಟಲ್ಡ್ ಪ್ರಾಮಿಸ್' (Settled Promise) ಎಂದರೆ ಆ ಕೆಲಸಕ್ಕಾಗಿ ಕಾಯುವ ಅಗತ್ಯವಿಲ್ಲ; ಅದು ಈಗಾಗಲೇ ಯಶಸ್ವಿಯಾಗಿದೆ (Resolved) ಅಥವಾ ವಿಫಲವಾಗಿದೆ (Rejected) ಎಂದರ್ಥ.

1. ತಳಮಟ್ಟದ ವಿವರಣೆ (ಚಿಕ್ಕ ಮಕ್ಕಳಿಗೆ ಅರ್ಥವಾಗುವಂತೆ)

ಒಂದು ಸರಳ ಉದಾಹರಣೆ ತೆಗೆದುಕೊಳ್ಳಿ: ನೀವು ನಿಮ್ಮ ತಾಯಿಯ ಬಳಿ "ನನಗೆ ಐಸ್ ಕ್ರೀಮ್ ಬೇಕು" ಎಂದು ಕೇಳುತ್ತೀರಿ.

  • ಸಾಮಾನ್ಯ ಪ್ರಾಮಿಸ್ (Pending): ತಾಯಿ "ಸಂಜೆ ತಂದು ಕೊಡುತ್ತೇನೆ" ಎನ್ನುತ್ತಾರೆ. ನೀವು ಸಂಜೆಯವರೆಗೆ ಕಾಯಬೇಕು.
  • ಸೆಟಲ್ಡ್ ಪ್ರಾಮಿಸ್ (Settled):
    • ಯಶಸ್ವಿ (Promise.resolve): ತಾಯಿಯ ಫ್ರಿಡ್ಜ್‌ನಲ್ಲಿ ಈಗಾಗಲೇ ಐಸ್ ಕ್ರೀಮ್ ಇದೆ ಮತ್ತು ಅವರು ತಕ್ಷಣವೇ ನಿಮಗೆ ಕೊಡುತ್ತಾರೆ. ಇಲ್ಲಿ ಕಾಯುವ ಅಗತ್ಯವಿಲ್ಲ!
    • ವಿಫಲ (Promise.reject): ತಾಯಿ ತಕ್ಷಣವೇ "ಇಲ್ಲ, ನಿನಗೆ ನೆಗಡಿಯಾಗಿದೆ, ಐಸ್ ಕ್ರೀಮ್ ಕೊಡುವುದಿಲ್ಲ" ಎಂದು ಹೇಳಿಬಿಡುತ್ತಾರೆ. ಇದಕ್ಕೂ ಕಾಯುವ ಅಗತ್ಯವಿಲ್ಲ, ನಿರ್ಧಾರ ತಕ್ಷಣ ಗೊತ್ತಾಗುತ್ತದೆ.

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ, ಯಾವುದೇ ಕಾಯುವಿಕೆ ಇಲ್ಲದೆ ತಕ್ಷಣವೇ ಫಲಿತಾಂಶ ಅಥವಾ ದೋಷವನ್ನು ನೀಡುವ ಪ್ರಾಮಿಸ್‌ಗಳನ್ನು "ಸೆಟಲ್ಡ್ ಪ್ರಾಮಿಸ್‌ಗಳು" ಎಂದು ಕರೆಯುತ್ತಾರೆ.

2. ತಾಂತ್ರಿಕ ವಿವರಣೆ ಮತ್ತು ಕೆಲಸ

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಸೆಟಲ್ಡ್ ಪ್ರಾಮಿಸ್‌ಗಳನ್ನು ರಚಿಸಲು ಎರಡು ಮುಖ್ಯ ವಿಧಾನಗಳಿವೆ:

1. Promise.resolve(value)

ಮೌಲ್ಯವನ್ನು (value) ತಕ್ಷಣವೇ ಹಿಂತಿರುಗಿಸುವ ಯಶಸ್ವಿ ಪ್ರಾಮಿಸ್.

2. Promise.reject(reason)

ದೋಷವನ್ನು (error) ತಕ್ಷಣವೇ ಹಿಂತಿರುಗಿಸುವ ವಿಫಲ ಪ್ರಾಮಿಸ್.

Promise Lifecycle Diagram

ಇವುಗಳ ಉಪಯೋಗವೇನು?

  • ಸ್ಥಿರತೆ (Consistency): ಒಂದು ಫಂಕ್ಷನ್ ಕೆಲವೊಮ್ಮೆ ತಕ್ಷಣ ಡೇಟಾ ನೀಡಬಹುದು, ಕೆಲವೊಮ್ಮೆ ಸರ್ವರ್‌ನಿಂದ ತರಲು ಸಮಯ ತೆಗೆದುಕೊಳ್ಳಬಹುದು. ಆದರೆ ಆ ಫಂಕ್ಷನ್ ಯಾವಾಗಲೂ 'Promise' ಅನ್ನೇ ಹಿಂದಿರುಗಿಸುವಂತೆ ಮಾಡಲು ಇದನ್ನು ಬಳಸುತ್ತಾರೆ.
  • ಕ್ಯಾಶಿಂಗ್ (Caching): ಈಗಾಗಲೇ ಡೌನ್‌ಲೋಡ್ ಮಾಡಿದ ಡೇಟಾವನ್ನು ಮತ್ತೆ ಸರ್ವರ್‌ನಿಂದ ತರುವ ಬದಲು ತಕ್ಷಣವೇ ಹಿಂದಿರುಗಿಸಲು.
  • ಟೆಸ್ಟಿಂಗ್ (Testing): ಕೋಡ್ ಅನ್ನು ಟೆಸ್ಟ್ ಮಾಡುವಾಗ ಕೃತಕ (mock) ಡೇಟಾವನ್ನು ತಕ್ಷಣವೇ ಸೃಷ್ಟಿಸಲು.

3. ಎಲ್ಲಾ ರೀತಿಯ ಉದಾಹರಣೆಗಳು ಮತ್ತು ಹಂತ-ಹಂತದ ವಿವರಣೆ

ಉದಾಹರಣೆ 1: ಯಶಸ್ವಿಯಾದ ಪ್ರಾಮಿಸ್ (Promise.resolve)

// ಹಂತ 1: ತಕ್ಷಣವೇ ಯಶಸ್ವಿಯಾಗುವ ಪ್ರಾಮಿಸ್ ರಚನೆ
const instantSuccess = Promise.resolve("ಡೇಟಾ ತಕ್ಷಣ ಸಿಕ್ಕಿತು!");

// ಹಂತ 2: ಫಲಿತಾಂಶವನ್ನು .then() ಮೂಲಕ ಪಡೆಯುವುದು
instantSuccess.then((message) => {
    console.log(message); 
});
// ಔಟ್‌ಪುಟ್: ಡೇಟಾ ತಕ್ಷಣ ಸಿಕ್ಕಿತು!

ವಿವರಣೆ: ಇಲ್ಲಿ ನಾವು ಯಾವುದೇ ಸರ್ವರ್‌ಗೆ ಮನವಿ ಕಳುಹಿಸುತ್ತಿಲ್ಲ. ಬದಲಿಗೆ, ನಮ್ಮ ಬಳಿ ಇರುವ ಸ್ಟ್ರಿಂಗ್ ಅನ್ನು Promise.resolve() ಬಳಸಿ ಪ್ರಾಮಿಸ್ ರೂಪಕ್ಕೆ ಬದಲಾಯಿಸಿದ್ದೇವೆ. .then() ಬಳಸಿ ಆ ಮೌಲ್ಯವನ್ನು ನಾವು ತಕ್ಷಣವೇ ಪಡೆಯಬಹುದು.

ಉದಾಹರಣೆ 2: ವಿಫಲವಾದ ಪ್ರಾಮಿಸ್ (Promise.reject)

// ಹಂತ 1: ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ವಿಫಲವಾಗುವ ಪ್ರಾಮಿಸ್ ರಚನೆ
const instantFailure = Promise.reject(new Error("ಇಂಟರ್ನೆಟ್ ಸಂಪರ್ಕವಿಲ್ಲ!"));

// ಹಂತ 2: ದೋಷವನ್ನು .catch() ಮೂಲಕ ಹಿಡಿಯುವುದು
instantFailure.catch((error) => {
    console.log(error.message); 
});
// ಔಟ್‌ಪುಟ್: ಇಂಟರ್ನೆಟ್ ಸಂಪರ್ಕವಿಲ್ಲ!

ವಿವರಣೆ: Promise.reject ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ದೋಷವನ್ನು ಸೃಷ್ಟಿಸುತ್ತದೆ. ಅಪ್ಲಿಕೇಶನ್‌ನಲ್ಲಿ ಯೂಸರ್ ತಪ್ಪು ಡೇಟಾ ನೀಡಿದಾಗ ತಕ್ಷಣವೇ ದೋಷವನ್ನು ಹಿಂದಿರುಗಿಸಲು ಇದನ್ನು ಬಳಸಲಾಗುತ್ತದೆ. ವಿಫಲವಾದ ಪ್ರಾಮಿಸ್ ಅನ್ನು ನಿರ್ವಹಿಸಲು .catch() ಬಳಸಬೇಕು.

ಉದಾಹರಣೆ 3: ವೃತ್ತಿಪರ ಮಟ್ಟದ ಉಪಯೋಗ (ಕ್ಯಾಶಿಂಗ್)

ವೃತ್ತಿಪರ ಡೆವಲಪರ್‌ಗಳು ಡೇಟಾವನ್ನು ಉಳಿಸಿ (cache) ಮತ್ತೆ ವೇಗವಾಗಿ ಬಳಸಲು ಇದನ್ನು ಹೇಗೆ ಬಳಸುತ್ತಾರೆಂದು ನೋಡೋಣ.

// ಇದು ನಮ್ಮ ಡೇಟಾಬೇಸ್ ಅಥವಾ ಕ್ಯಾಶ್ ಎಂದು ಕಲ್ಪಿಸಿಕೊಳ್ಳಿ
const cache = {
    user123: { name: "ರಾಮ್", age: 25 }
};

// ಬಳಕೆದಾರನ ಡೇಟಾ ತರುವ ಫಂಕ್ಷನ್
function getUserData(userId) {
    // ಹಂತ 1: ಡೇಟಾ ಈಗಾಗಲೇ ಕ್ಯಾಶ್‌ನಲ್ಲಿದ್ದರೆ, ತಕ್ಷಣವೇ ಸೆಟಲ್ಡ್ ಪ್ರಾಮಿಸ್ ಮೂಲಕ ಹಿಂದಿರುಗಿಸಿ
    if (cache[userId]) {
        console.log("ಕ್ಯಾಶ್‌ನಿಂದ ಡೇಟಾ ತರಲಾಗುತ್ತಿದೆ...");
        return Promise.resolve(cache[userId]);
    }
    
    // ಹಂತ 2: ಡೇಟಾ ಇಲ್ಲದಿದ್ದರೆ, ಸರ್ವರ್‌ನಿಂದ ತರಲು ಹೊಸ ಪ್ರಾಮಿಸ್ (ಕಾಯುವಿಕೆ) ಮಾಡಿ
    console.log("ಸರ್ವರ್‌ನಿಂದ ಡೇಟಾ ತರಲಾಗುತ್ತಿದೆ...");
    return fetch(`https://api.example.com/users/${userId}`)
        .then(response => response.json());
}

// ಬಳಕೆ (Usage)
getUserData("user123").then(data => {
    console.log("ಬಳಕೆದಾರನ ಹೆಸರು:", data.name);
});
// ಔಟ್‌ಪುಟ್:
// ಕ್ಯಾಶ್‌ನಿಂದ ಡೇಟಾ ತರಲಾಗುತ್ತಿದೆ...
// ಬಳಕೆದಾರನ ಹೆಸರು: ರಾಮ್

ವಿವರಣೆ: ಈ ಕೋಡ್‌ನಲ್ಲಿ getUserData ಎಂಬುದು ಯಾವಾಗಲೂ .then() ಅನ್ನು ಬೆಂಬಲಿಸುವ ಪ್ರಾಮಿಸ್ ಅನ್ನು ಹಿಂದಿರುಗಿಸಬೇಕು ಎಂಬ ನಿಯಮವಿರುತ್ತದೆ. ಡೇಟಾ ಈಗಾಗಲೇ cache ನಲ್ಲಿದ್ದರೆ, ನಾವು ಅದನ್ನು ನೇರವಾಗಿ return cache[userId] ಎಂದು ಕಳುಹಿಸುವಂತಿಲ್ಲ, ಏಕೆಂದರೆ ಆಗ ಅದು ಪ್ರಾಮಿಸ್ ಆಗಿರುವುದಿಲ್ಲ. ಆದ್ದರಿಂದ Promise.resolve(cache[userId]) ಅನ್ನು ಬಳಸುವ ಮೂಲಕ ಡೇಟಾವನ್ನು ಪ್ರಾಮಿಸ್ ರೂಪದಲ್ಲೇ ತಕ್ಷಣ ಹಿಂದಿರುಗಿಸುತ್ತೇವೆ.

4. Promise.allSettled() ನ ಬಗ್ಗೆ

Promise.allSettled() ಎಂಬುದು ಬಹುಪಾಲು ಪ್ರಾಮಿಸ್‌ಗಳನ್ನು ಒಟ್ಟಿಗೆ ನಿರ್ವಹಿಸಲು ಬಳಸುವ ಅತ್ಯಂತ ಉಪಯುಕ್ತ ವಿಧಾನವಾಗಿದೆ. Promise.all() ಗಿಂತ ಇದು ಭಿನ್ನವಾಗಿದೆ; ಏಕೆಂದರೆ ಇದರಲ್ಲಿ ಯಾವುದೇ ಒಂದು ಪ್ರಾಮಿಸ್ ವಿಫಲವಾದರೂ (Rejected), ಇಡೀ ಪ್ರಕ್ರಿಯೆ ನಿಲ್ಲುವುದಿಲ್ಲ. ಬದಲಿಗೆ, ಎಲ್ಲಾ ಪ್ರಾಮಿಸ್‌ಗಳು ಮುಗಿಯುವವರೆಗೆ ಕಾಯುತ್ತದೆ ಮತ್ತು ಪ್ರತಿಯೊಂದರ ಅಂತಿಮ ಸ್ಥಿತಿಯನ್ನು (status - fulfilled or rejected) ನಮಗೆ ಹಿಂದಿರುಗಿಸುತ್ತದೆ. 

// ಮೂರು ಬೇರೆ ಬೇರೆ ಪ್ರಾಮಿಸ್‌ಗಳ ರಚನೆ
const promise1 = Promise.resolve("ಮೊದಲನೇ ಕೆಲಸ ಯಶಸ್ವಿ!");
const promise2 = Promise.reject(new Error("ಎರಡನೇ ಕೆಲಸ ವಿಫಲ!"));
const promise3 = new Promise((resolve) => setTimeout(resolve, 100, "ಮೂರನೇ ಕೆಲಸ ಸ್ವಲ್ಪ ತಡವಾಗಿ ಯಶಸ್ವಿ!"));

// ಎಲ್ಲಾ ಪ್ರಾಮಿಸ್‌ಗಳು ಸೆಟಲ್ ಆಗುವವರೆಗೆ ಕಾಯುವುದು
Promise.allSettled([promise1, promise2, promise3])
    .then((results) => {
        results.forEach((result, index) => {
            if (result.status === 'fulfilled') {
                console.log(`ಪ್ರಾಮಿಸ್ ${index + 1}: ಯಶಸ್ವಿ ->`, result.value);
            } else if (result.status === 'rejected') {
                console.log(`ಪ್ರಾಮಿಸ್ ${index + 1}: ವಿಫಲ ->`, result.reason.message);
            }
        });
    });

/* ಔಟ್‌ಪುಟ್:
ಪ್ರಾಮಿಸ್ 1: ಯಶಸ್ವಿ -> ಮೊದಲನೇ ಕೆಲಸ ಯಶಸ್ವಿ!
ಪ್ರಾಮಿಸ್ 2: ವಿಫಲ -> ಎರಡನೇ ಕೆಲಸ ವಿಫಲ!
ಪ್ರಾಮಿಸ್ 3: ಯಶಸ್ವಿ -> ಮೂರನೇ ಕೆಲಸ ಸ್ವಲ್ಪ ತಡವಾಗಿ ಯಶಸ್ವಿ!
*/

ವಿವರಣೆ: ಇಲ್ಲಿ ನಾವು ಮೂರು ಪ್ರಾಮಿಸ್‌ಗಳನ್ನು ಒಟ್ಟಿಗೆ ಕಳುಹಿಸುತ್ತಿದ್ದೇವೆ. ಒಂದು ಉದ್ದೇಶಪೂರ್ವಕವಾಗಿ ವಿಫಲವಾದರೂ (promise2), Promise.allSettled() ಪ್ರಕ್ರಿಯೆಯನ್ನು ಅಡ್ಡಿಪಡಿಸುವುದಿಲ್ಲ. ಬದಲಿಗೆ, ಎಲ್ಲಾ ಮೂರು ಪ್ರಾಮಿಸ್‌ಗಳ ಅಂತಿಮ ಸ್ಥಿತಿಯನ್ನು ಮತ್ತು ಅವುಗಳ ಮೌಲ್ಯ ಅಥವಾ ದೋಷವನ್ನು ಒಂದು ಅರೇ (Array) ರೂಪದಲ್ಲಿ ನಮಗೆ ಒದಗಿಸುತ್ತದೆ. ಒಂದಕ್ಕೊಂದು ಸಂಬಂಧವಿಲ್ಲದ ಬಹು API ಕಾಲ್‌ಗಳನ್ನು ಒಟ್ಟಿಗೆ ಮಾಡುವಾಗ ಇದು ಬಹಳ ಉಪಯುಕ್ತ.
