JavaScript Notes

ಪರಿವಿಡಿ (TOC)

ಪೀಠಿಕೆ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ ಹೃದಯ 1. ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ 2. ವೆಬ್ ಎಪಿಐಗಳು 3. ಕ್ಯೂ (Queue) 4. ಇವೆಂಟ್ ಲೂಪ್ ದಿ ಅಲ್ಟಿಮೇಟ್ ಕೋಡ್ ಸವಾಲು ಡೆವಲಪರ್‌ಗಳಿಗೆ ಏಕೆ ಅತಿ ಮುಖ್ಯ?

ಖಂಡಿತ, ನೀವು ಕೇಳಿದಂತೆ ಈ ಹಿಂದೆ ಚರ್ಚಿಸಿದ ಎಲ್ಲಾ ಮಾಹಿತಿಯನ್ನು (ಯಾವುದನ್ನೂ ಕೈಬಿಡದೆ) ಒಳಗೊಂಡು, ಪ್ರತಿಯೊಂದು ಹಂತಕ್ಕೂ ಕೋಡಿಂಗ್ ಉದಾಹರಣೆ ಮತ್ತು ಅದರ ವಿವರಣೆಯೊಂದಿಗೆ ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ "ಇವೆಂಟ್ ಲೂಪ್" (Event Loop) ಪ್ರಕ್ರಿಯೆಯನ್ನು ಇಲ್ಲಿ ಮರು-ತಯಾರಿಸಲಾಗಿದೆ. ನಾನ್-ಐಟಿ (Non-IT) ಹಿನ್ನೆಲೆಯವರಿಗೂ ತಾಂತ್ರಿಕವಾಗಿ ಅರ್ಥವಾಗುವಂತೆ ಹೋಟೆಲ್ ಉದಾಹರಣೆಯೊಂದಿಗೆ ಇದನ್ನು ವಿವರಿಸಲಾಗಿದೆ.

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ ಹೃದಯ (Heartbeat of JavaScript)

ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಒಮ್ಮೆಗೆ ಒಂದೇ ಕೆಲಸ ಮಾಡುವ (Single-threaded) ಭಾಷೆಯಾಗಿದ್ದರೂ, ಮಲ್ಟಿ-ಟಾಸ್ಕಿಂಗ್ ಅನ್ನು ಯಾವುದೇ ಅಡೆತಡೆಯಿಲ್ಲದೆ ನಿಭಾಯಿಸುತ್ತದೆ. ಒಂದು ದೊಡ್ಡ ವಿಡಿಯೋ ಡೌನ್‌ಲೋಡ್ ಆಗುವವರೆಗೂ ಇಡೀ ವೆಬ್‌ಸೈಟ್ ಹ್ಯಾಂಗ್ ಆಗದೆ, ನಾವು ಬೇರೆ ಬಟನ್‌ಗಳನ್ನು ಕ್ಲಿಕ್ ಮಾಡಲು ಸಾಧ್ಯವಾಗುವುದರ ಹಿಂದಿನ ಸಂಪೂರ್ಣ ರಹಸ್ಯ ಅಡಗಿರುವುದೇ Web APIs ಮತ್ತು Event Loop ನಲ್ಲಿ.

ಇದನ್ನು ಸರಿಯಾಗಿ ಅರ್ಥಮಾಡಿಕೊಳ್ಳಲು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ 4 ಮುಖ್ಯ ಆಧಾರಸ್ತಂಭಗಳನ್ನು ಕೋಡ್ ಉದಾಹರಣೆಗಳೊಂದಿಗೆ ನೋಡೋಣ:

1. ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ (Call Stack) - ಕೆಲಸದ ಮೇಜು = ಹೋಟೆಲ್ ವೇಟರ್

ಇದು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ ಮುಖ್ಯ ಕೆಲಸಗಾರ. ನೀವು ಬರೆಯುವ ಸಾಮಾನ್ಯ (ಸಿಂಕ್ರೋನಸ್) ಕೋಡ್‌ಗಳು ಇಲ್ಲಿಯೇ ರನ್ ಆಗುತ್ತವೆ.

  • ತಾಂತ್ರಿಕ ನಿಯಮ: "ಏಕಕಾಲದಲ್ಲಿ ಒಂದೇ ಕೆಲಸ." ಒಂದು ಸಾಲಿನ ಕೋಡ್ ರನ್ ಆಗಿ ಮುಗಿಯುವವರೆಗೂ ಇದು ಮುಂದಿನ ಸಾಲಿಗೆ ಹೋಗುವುದಿಲ್ಲ.
  • ಹೋಟೆಲ್ ಉದಾಹರಣೆ: ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ ಎಂದರೆ ಹೋಟೆಲ್‌ನಲ್ಲಿರುವ ಏಕೈಕ ವೇಟರ್. ಇವನು ಒಮ್ಮೆಗೆ ಒಬ್ಬ ಗ್ರಾಹಕನಿಗೆ ಮಾತ್ರ ಸೇವೆ ಸಲ್ಲಿಸುತ್ತಾನೆ. ನೀರು ಕೊಡುವುದು, ಮೆನು ಕಾರ್ಡ್ ಕೊಡುವಂತಹ ದಿಢೀರ್ ಕೆಲಸಗಳನ್ನು ಇವನೇ ಮುಗಿಸುತ್ತಾನೆ.

ಕೋಡಿಂಗ್ ಉದಾಹರಣೆ:

console.log("1. ಗ್ರಾಹಕ ಬಂದರು");
console.log("2. ನೀರು ಕೊಟ್ಟೆ");
console.log("3. ಆರ್ಡರ್ ತೆಗೆದುಕೊಂಡೆ");
ವಿವರಣೆ: ಇಲ್ಲಿ ಯಾವುದೇ ತಡವಾಗುವ ಕೆಲಸವಿಲ್ಲ. ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ (ವೇಟರ್) ಮೊದಲ ಸಾಲನ್ನು ಓದುತ್ತದೆ, ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ. ನಂತರ ಎರಡನೇ ಸಾಲು, ಆಮೇಲೆ ಮೂರನೇ ಸಾಲು. ಇದು ಒಂದರ ಹಿಂದೊಂದು ತಕ್ಷಣವೇ ಮುಗಿದುಹೋಗುತ್ತದೆ.

2. ವೆಬ್ ಎಪಿಐಗಳು (Web APIs) - ಹಿನ್ನೆಲೆಯ ಸಹಾಯಕರು = ಅಡುಗೆಮನೆ

ಇವು ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನ ಸ್ವಂತ ಭಾಗವಲ್ಲ, ಬದಲಾಗಿ ಬ್ರೌಸರ್ (Chrome, Edge ಇತ್ಯಾದಿ) ಒದಗಿಸುವ ಸೂಪರ್ ಪವರ್‌ಗಳು.

  • ತಾಂತ್ರಿಕ ನಿಯಮ: ಸಮಯ ತೆಗೆದುಕೊಳ್ಳುವ ಕೆಲಸಗಳಾದ setTimeout (ಟೈಮರ್‌ಗಳು) ಬಂದರೆ ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ ನಿಲ್ಲುವುದಿಲ್ಲ, ಅದನ್ನು ಬ್ರೌಸರ್‌ಗೆ ವಹಿಸುತ್ತದೆ.
  • ಹೋಟೆಲ್ ಉದಾಹರಣೆ: ವೇಟರ್‌ಗೆ ದೋಸೆ ಮಾಡಲು ಬರುವುದಿಲ್ಲ (ಅದಕ್ಕೆ ಸಮಯ ಹಿಡಿಯುತ್ತದೆ). ಆದ್ದರಿಂದ ಆ ಆರ್ಡರ್ ಅನ್ನು ಅಡುಗೆಮನೆಗೆ (Web APIs) ಕೊಟ್ಟು, ವೇಟರ್ ತಾನು ಬೇರೆ ಕೆಲಸ ನೋಡಿಕೊಳ್ಳಲು ಹೋಗುತ್ತಾನೆ.

ಕೋಡಿಂಗ್ ಉದಾಹರಣೆ:

console.log("1. ದೋಸೆ ಆರ್ಡರ್ ತಗೊಂಡೆ");

setTimeout(() => {
    console.log("2. ದೋಸೆ ರೆಡಿಯಾಯಿತು (3 ಸೆಕೆಂಡ್ ನಂತರ)");
}, 3000); 

console.log("3. ಬೇರೆ ಟೇಬಲ್‌ಗೆ ಹೋದೆ");
ವಿವರಣೆ: ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಮೊದಲು "1" ಅನ್ನು ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ. ನಂತರ setTimeout ಬಂದಾಗ ಅದು 3 ಸೆಕೆಂಡ್ ಸುಮ್ಮನೆ ನಿಂತು ಕಾಯುವುದಿಲ್ಲ. ಆ ಟೈಮರ್ ಓಡಿಸುವ ಕೆಲಸವನ್ನು Web API (ಅಡುಗೆಮನೆ) ಗೆ ಒಪ್ಪಿಸಿ, ತಕ್ಷಣ "3. ಬೇರೆ ಟೇಬಲ್‌ಗೆ ಹೋದೆ" ಅನ್ನು ಪ್ರಿಂಟ್ ಮಾಡುತ್ತದೆ. 3 ಸೆಕೆಂಡ್ ಆದಮೇಲೆ "2" ಪ್ರಿಂಟ್ ಆಗುತ್ತದೆ.

3. ಕ್ಯೂ (Queue) - ಕಾಯುವ ಸಾಲು = ಪಾರ್ಸೆಲ್ ಕೌಂಟರ್

Web API ತನ್ನ ಹಿನ್ನೆಲೆ ಕೆಲಸವನ್ನು ಮುಗಿಸಿದ ನಂತರ, ಆ ಫಲಿತಾಂಶವನ್ನು ನೇರವಾಗಿ ಮತ್ತೆ ಕಾಲ್ ಸ್ಟ್ಯಾಕ್‌ಗೆ ಎಸೆಯುವುದಿಲ್ಲ. ಬದಲಾಗಿ, ಅದನ್ನು ಒಂದು ಸಾಲಿನಲ್ಲಿ (Queue) ನಿಲ್ಲಿಸುತ್ತದೆ. ಇಲ್ಲಿ ಎರಡು ಸಾಲುಗಳಿವೆ:

  • ಮೈಕ್ರೋಟಾಸ್ಕ್ ಕ್ಯೂ (VIP ಕೌಂಟರ್): ಇಲ್ಲಿರುವ ಕೆಲಸಗಳಿಗೆ ಯಾವಾಗಲೂ ಮೊದಲ ಆದ್ಯತೆ! Promises, async/await ಮತ್ತು fetch (ಬೇರೆ ಸರ್ವರ್‌ನಿಂದ ತಂದ ಡೇಟಾ) ನಂತಹ ಫಲಿತಾಂಶಗಳು ಈ VIP ಸಾಲಿನಲ್ಲಿ ಬರುತ್ತವೆ.
  • ಟಾಸ್ಕ್ ಕ್ಯೂ (ಸಾಮಾನ್ಯ ಕೌಂಟರ್): ಇದು ಸಾಮಾನ್ಯ ಸಾಲು. setTimeout ಮತ್ತು DOM (ಬಟನ್ ಕ್ಲಿಕ್) ನಂತಹ ಕೆಲಸಗಳು ಇಲ್ಲಿ ಕಾಯುತ್ತವೆ.

ಹೆಚ್ಚುವರಿ ತಾಂತ್ರಿಕ ಮಾಹಿತಿ: ನೀವು ಕಲಿಯುತ್ತಿರುವ async/await ಕೂಡ ಹಿನ್ನೆಲೆಯಲ್ಲಿ Promises ರೀತಿಯಲ್ಲೇ ಕೆಲಸ ಮಾಡುತ್ತದೆ. await ಕೀವರ್ಡ್ ಎದುರಾದಾಗ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್ ಆ ಫಂಕ್ಷನ್‌ನ ಮುಂದಿನ ಭಾಗವನ್ನು ನೇರವಾಗಿ ಇದೇ 'ಮೈಕ್ರೋಟಾಸ್ಕ್ ಕ್ಯೂ' (VIP ಸಾಲು) ಗೆ ಸೇರಿಸುತ್ತದೆ.

ಕೋಡಿಂಗ್ ಉದಾಹರಣೆ (fetch ಮತ್ತು DOM ಕ್ಲಿಕ್):

// 1. ಸಾಮಾನ್ಯ ಕೆಲಸ (DOM - Task Queue)
document.getElementById("myButton").addEventListener("click", () => {
    console.log("ಬಟನ್ ಕ್ಲಿಕ್ ಮಾಡಲಾಗಿದೆ (ಸಾಮಾನ್ಯ ಸಾಲು)");
});

// 2. VIP ಕೆಲಸ (fetch / Promise - Microtask Queue)
fetch('https://api.example.com/data')
    .then(response => {
        console.log("ಇಂಟರ್ನೆಟ್‌ನಿಂದ ಡೇಟಾ ಬಂತು (VIP ಸಾಲು)");
    });
ವಿವರಣೆ:
  • ನೀವು ಹೋಟೆಲ್‌ನಲ್ಲಿ ಕೂತು ಆನ್‌ಲೈನ್ ಆಪ್ (fetch) ಮೂಲಕ ಊಟ ಬುಕ್ ಮಾಡಿದರೆ, ಆ ಊಟ ಬಂದ ತಕ್ಷಣ ಅದು VIP ಸಾಲಿಗೆ ಹೋಗುತ್ತದೆ.
  • ಅದೇ ರೀತಿ ನೀವು ವೆಬ್‌ಸೈಟ್‌ನಲ್ಲಿ ಬಟನ್ (DOM) ಕ್ಲಿಕ್ ಮಾಡಿದರೆ, ಆ ಕ್ಲಿಕ್ ಆದೇಶವು ನೇರವಾಗಿ ರನ್ ಆಗದೆ ಸಾಮಾನ್ಯ ಸಾಲಿನಲ್ಲಿ ಹೋಗಿ ನಿಲ್ಲುತ್ತದೆ.

4. ಇವೆಂಟ್ ಲೂಪ್ (Event Loop) - ಟ್ರಾಫಿಕ್ ಮ್ಯಾನೇಜರ್ = ಹೋಟೆಲ್ ಮ್ಯಾನೇಜರ್

ಇವೆಂಟ್ ಲೂಪ್‌ನ ಕೆಲಸ ತುಂಬಾ ಸರಳ. ಇದು ಸತತವಾಗಿ ಕೇವಲ ಎರಡು ಪ್ರಶ್ನೆಗಳನ್ನು ಕೇಳಿಕೊಳ್ಳುತ್ತಿರುತ್ತದೆ:

  1. "ವೇಟರ್ ಫ್ರೀ ಇದ್ದಾನಾ?" (ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ ಖಾಲಿ ಇದೆಯಾ?)
  2. "ಪಾರ್ಸೆಲ್ ಕೌಂಟರ್‌ನಲ್ಲಿ ಗ್ರಾಹಕರಿಗೆ ಕೊಡಲು ಏನಾದರೂ ರೆಡಿ ಇದೆಯಾ?" (ಕ್ಯೂ ನಲ್ಲಿ ಕೆಲಸ ಇದೆಯಾ?)

ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ ಸಂಪೂರ್ಣವಾಗಿ ಖಾಲಿಯಾದಾಗ ಮಾತ್ರ, ಇವೆಂಟ್ ಲೂಪ್ ಮೊದಲು VIP ಸಾಲಿನಲ್ಲಿ ಕಾಯುತ್ತಿರುವ ಫಲಿತಾಂಶವನ್ನು ಎತ್ತಿ ಕಾಲ್ ಸ್ಟ್ಯಾಕ್‌ಗೆ ಹಾಕುತ್ತದೆ. ಅದು ಖಾಲಿಯಾದ ಮೇಲೆ ಸಾಮಾನ್ಯ ಸಾಲಿನ ಕಡೆ ಮುಖ ಮಾಡುತ್ತದೆ.

ದಿ ಅಲ್ಟಿಮೇಟ್ ಕೋಡ್ ಸವಾಲು (ಇದೆಲ್ಲವೂ ಒಟ್ಟಿಗೆ ಕೆಲಸ ಮಾಡುವ ರೀತಿ)

ಮೇಲಿನ ಎಲ್ಲವನ್ನೂ ಸೇರಿಸಿ ಡೆವಲಪರ್‌ಗಳ ಇಂಟರ್ವ್ಯೂಗಳಲ್ಲಿ ಕೇಳಲಾಗುವ ಒಂದು ಸವಾಲಿನ ಕೋಡ್ ಇಲ್ಲಿದೆ. ಇದು ಯಾವ ಕ್ರಮದಲ್ಲಿ ಪ್ರಿಂಟ್ ಆಗುತ್ತದೆ ಎಂದು ನೋಡಿ:

console.log("1. ಪ್ರಾರಂಭ");

// ಸಾಮಾನ್ಯ ಸಾಲಿಗೆ ಹೋಗುವ ಕೆಲಸ (Task Queue)
setTimeout(() => {
    console.log("2. ಟೈಮರ್ ಮುಗಿಯಿತು");
}, 0);

// VIP ಸಾಲಿಗೆ ಹೋಗುವ ಕೆಲಸ (Microtask Queue)
Promise.resolve().then(() => {
    console.log("3. ಪ್ರಾಮಿಸ್ ಮುಗಿಯಿತು");
});

console.log("4. ಅಂತ್ಯ");

ಇದು ಹೇಗೆ ರನ್ ಆಗುತ್ತದೆ (ಹಿನ್ನೆಲೆಯ ರಹಸ್ಯದ ವಿವರಣೆ):

  1. 1. ಮೊದಲು ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ console.log("1. ಪ್ರಾರಂಭ") ರನ್ ಮಾಡುತ್ತದೆ.
    👉 ಔಟ್‌ಪುಟ್: 1
  2. 2. setTimeout ಬರುತ್ತದೆ. ಇದು Web API, ಹಾಗಾಗಿ ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ ಇದನ್ನು ಅಡುಗೆಮನೆಗೆ ಕಳುಹಿಸುತ್ತದೆ. ಇದರ ಟೈಮ್ 0 ಸೆಕೆಂಡ್ (ತಕ್ಷಣವೇ) ಆದರೂ ಸಹ, ನಿಯಮದ ಪ್ರಕಾರ ಇದು ಸಾಮಾನ್ಯ ಸಾಲಿಗೆ (Task Queue) ಹೋಗಿ ಕಾಯಲೇಬೇಕು.
  3. 3. Promise ಬರುತ್ತದೆ. ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ ಇದನ್ನು ಕೂಡ Web API ಗೆ ಕಳುಹಿಸುತ್ತದೆ. ಇದು VIP ಕೆಲಸವಾದ್ದರಿಂದ, ರೆಡಿಯಾದ ತಕ್ಷಣ VIP ಸಾಲಿಗೆ (Microtask Queue) ಬಂದು ನಿಲ್ಲುತ್ತದೆ.
  4. 4. ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ console.log("4. ಅಂತ್ಯ") ರನ್ ಮಾಡುತ್ತದೆ.
    👉 ಔಟ್‌ಪುಟ್: 4
  5. 5. ಇವೆಂಟ್ ಲೂಪ್ (ಮ್ಯಾನೇಜರ್) ಎಂಟ್ರಿ: ಈಗ ಕಾಲ್ ಸ್ಟ್ಯಾಕ್ (ವೇಟರ್) ಸಂಪೂರ್ಣ ಖಾಲಿ! ಇವೆಂಟ್ ಲೂಪ್ ಕೌಂಟರ್ ಕಡೆ ನೋಡುತ್ತದೆ. ಸಾಲಿನಲ್ಲಿ ಇಬ್ಬರು ಕಾಯುತ್ತಿದ್ದಾರೆ (Promise ಮತ್ತು setTimeout).
  6. 6. VIP ಸಾಲಿಗೆ (Microtask Queue) ಮೊದಲ ಆದ್ಯತೆ! ಹಾಗಾಗಿ ಇವೆಂಟ್ ಲೂಪ್ ಮೊದಲು Promise ಅನ್ನು ಕಾಲ್ ಸ್ಟ್ಯಾಕ್‌ಗೆ ಕಳುಹಿಸುತ್ತದೆ.
    👉 ಔಟ್‌ಪುಟ್: 3
  7. 7. VIP ಕೌಂಟರ್ ಖಾಲಿಯಾದ ಮೇಲೆ ಸಾಮಾನ್ಯ ಸಾಲಿನಲ್ಲಿ (Task Queue) ಕಾಯುತ್ತಿದ್ದ setTimeout ಅನ್ನು ಕಾಲ್ ಸ್ಟ್ಯಾಕ್‌ಗೆ ಕಳುಹಿಸುತ್ತದೆ.
    👉 ಔಟ್‌ಪುಟ್: 2
ಅಂತಿಮ ಔಟ್‌ಪುಟ್:
1. ಪ್ರಾರಂಭ 4. ಅಂತ್ಯ 3. ಪ್ರಾಮಿಸ್ ಮುಗಿಯಿತು 2. ಟೈಮರ್ ಮುಗಿಯಿತು

ಇದು ಡೆವಲಪರ್‌ಗಳಿಗೆ ಏಕೆ ಅತಿ ಮುಖ್ಯ? (Bugs ಪತ್ತೆ ಹಚ್ಚುವಿಕೆ)

ಹೊಸದಾಗಿ ಕೋಡ್ ಕಲಿಯುವವರು "ನಾನು ಮೊದಲು setTimeout (ಟೈಮರ್) ಬರೆದಿದ್ದೇನೆ, ಹಾಗಾಗಿ ಅದು ಪ್ರಾಮಿಸ್‌ಗಿಂತ ಮೊದಲು ಪ್ರಿಂಟ್ ಆಗಬೇಕು" ಎಂದುಕೊಳ್ಳುತ್ತಾರೆ. ಆದರೆ ಈ 'Event Loop' ಮತ್ತು ಕ್ಯೂಗಳ (VIP vs ಸಾಮಾನ್ಯ) ನಿಯಮ ಗೊತ್ತಿಲ್ಲದಿದ್ದರೆ, ಡೆವಲಪರ್‌ಗಳು "ನನ್ನ ಕೋಡ್ ಯಾಕೆ ತಪ್ಪು ತಪ್ಪಾಗಿ ರನ್ ಆಗುತ್ತಿದೆ? ನನ್ನ ಡೇಟಾ ಬರುವ ಮುನ್ನವೇ ಬೇರೆ ಬಟನ್ ಯಾಕೆ ಕ್ಲಿಕ್ ಆಗುತ್ತಿದೆ?" ಎಂದು ತಲೆಕೆಡಿಸಿಕೊಳ್ಳುತ್ತಾರೆ.

ಈ Call Stack, Web APIs, Microtask / Task Queue ಮತ್ತು Event Loop ಪ್ರಕ್ರಿಯೆಯನ್ನು ಒಮ್ಮೆ ಅರ್ಥಮಾಡಿಕೊಂಡರೆ, ಜಾವಾಸ್ಕ್ರಿಪ್ಟ್‌ನಲ್ಲಿ ಎಂತಹ ಜಟಿಲವಾದ ತಪ್ಪುಗಳನ್ನು (Bugs) ಸಹ ನೀವು ಅತ್ಯಂತ ಸುಲಭವಾಗಿ ಪತ್ತೆಹಚ್ಚಿ ಸರಿಪಡಿಸಬಹುದು!
